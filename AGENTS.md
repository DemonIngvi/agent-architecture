# AGENTS.md — как работать с этим репозиторием

Инструкции для любого ИИ-агента (Claude Code, Codex, Cursor, Gemini, Copilot) и человека. Репозиторий — документация агентной платформы для ICPlan (форк It's a Plan): архитектура, спеки OpenSpec, R&D, задачи; сайт собирается из исходников (`html-view/build.py`).

## Перед началом

```bash
./tools/setup.sh          # Windows: tools\setup.ps1 — включает git-хуки (.githooks) и проверяет Python
```

## Правило в момент правки — инструмент, а не чтение всех правил

Правил много (`docs/rules`). Не читай их целиком — получай выжимку для файла:

| Когда | Команда |
|---|---|
| перед правкой файла | `./tools/doc route <файл>` — тип документа, что обязательно, чего нельзя, где источник, методология, что синхронизировать |
| файл генерируется? | `./tools/doc pre <файл>` — код 2 и источник, если файл генерируемый: правь источник |
| после правки | `./tools/doc post <файл>` — выжимка и замечания проверок; `./tools/doc check` — все проверки за доли секунды |
| посмотреть схемы | `./tools/doc diagram <файл>` — mermaid-схемы файла (C1, C2, C3, sequence) отрисованной HTML-страницей |
| что править дальше | `./tools/doc next <файл>` — следующие документы по графу связности и методология каждого; правь их **по одному** |
| перед коммитом | git-хук `pre-commit` запускает `./tools/doc staged` сам |
| новое R&D | `./tools/doc rnd <slug> <тема>` — заготовка, проходящая проверку структуры |
| полная проверка | `python html-view/build.py`, `openspec validate <change> --strict` |

Windows: `tools\doc.cmd …`. Без обёрток: `python html-view/doctool.py …`.

## Договорённости проекта

- **Один документ за раз.** Изменение идёт по цепочке ([путь изменения](docs/rules/agent-workflow.md)): методология документа (устарела — сначала она и инструменты) → правка → проверка → `next` → следующий документ. Не правь все места пачкой.
- **Один факт — один источник.** Значения параметров — в `interfaces.md` спек; интеграции, модели, таблицы, структура API — в `html-view/datamodel.py`; в остальных местах ссылка. Генерируемое руками не правим.
- **Расхождение нашёл — запиши:** строка в [журнале отклонений](docs/rules/deviations.md): что → почему появилось → правило и проверка.
- **Не выдумывать.** Ссылки на решения (D-номер) и требования (R-…) — только существующие (проверь поиском); поля ICPlan — по коду форка и его OpenAPI (`html-view/icplan_openapi.json`); не определено — открытый вопрос в `open-questions.md` спеки.
- **Архитектура:** уровни C4 — C1 = платформа и ICPlan, C2 = внутренняя структура. Ответ по архитектуре: нарисованная схема нужного вида — C1, C2, C3, sequence (mermaid по [FORMAT.md](FORMAT.md); посмотреть — `./tools/doc diagram <файл>`) + таблица блоков + расширения + плюсы и минусы по каждому модулю; правка — с указанием файла и раздела.
- **Замечания ревью и вопросы всегда относятся к спеке.** «Ни к чему не относится» — признак ошибки границ: найди существующее требование.
- **Спеки:** не генерировать одним шаблоном — сначала вид спеки ([spec-kinds.md](docs/rules/spec-kinds.md)); подтверждения в `approvals.md` честно: 🤖 — проверено агентом по роли, 👤 — человеком.
- **R&D** — по [методологии v3.1](docs/rules/rnd-methodology.md): первая страница — презентация на 3 минуты, последствия Э10 вносятся по всей цепочке.
- **Языки:** документы на русском; заголовки OpenSpec и SHALL / MUST — на английском.

## Публикация и безопасность

- Репозиторий **публичный**. Не коммитить секреты, `.env`, учётные данные, рантайм-данные (БД, вложения, токены); файлы `*.local*`, `SECRETS*`, `ACCOUNTS*` не читать и не выводить.
- Коммиты — от `DemonIngvi <DemonIngvi@users.noreply.github.com>`; push в `main` публикует сайт (GitHub Pages).
- Сервисы платформы (Runner, Harness, Memory API, образы среды) — закрытый код в отдельных приватных репозиториях; открыт только форк ICPlan (AGPL).
