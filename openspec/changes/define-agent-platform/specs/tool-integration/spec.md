# Spec Delta

## Purpose

Подключение тулов и MCP-серверов к агентам через Registry, чтобы расширять возможности агентов без изменения кода платформы. Обоснование: [R&D](../../../../../docs/rnd/mcp-vs-direct.md).

## ADDED Requirements

### Requirement: Регистрация MCP-сервера
Система SHALL позволять зарегистрировать MCP-сервер в Registry и подключить его к агенту ссылкой в определении.

#### Scenario: Новый MCP-сервер
- **WHEN** администратор регистрирует MCP-сервер и добавляет его агенту
- **THEN** при следующем запуске тулы сервера доступны агенту

#### Scenario: Недоступный сервер
- **WHEN** регистрируемый сервер не отвечает
- **THEN** регистрация сохраняется с пометкой «недоступен», агенту тулы не выдаются

#### Scenario: Повторная регистрация
- **WHEN** сервер с тем же адресом уже есть
- **THEN** регистрация отклоняется как дубликат

### Requirement: Ограничение набора тулов
Агенту SHALL быть доступны только тулы, явно перечисленные в его определении (допускается подмножество тулов MCP-сервера).

#### Scenario: Тул вне списка
- **WHEN** LLM запрашивает тул, не входящий в определение агента
- **THEN** вызов отклоняется

#### Scenario: Тул из списка
- **WHEN** LLM запрашивает тул из определения
- **THEN** вызов выполняется

#### Scenario: Новый тул на сервере
- **WHEN** на MCP-сервере появился тул, которого нет в allowlist
- **THEN** агенту он не виден

### Requirement: Таймауты и ошибки тулов
Каждый вызов тула MUST иметь таймаут; ошибка или таймаут SHALL возвращаться агенту как результат тула, а не прерывать запуск.

#### Scenario: Недоступный MCP
- **WHEN** MCP-сервер не ответил за таймаут
- **THEN** агент получает ошибку тула и продолжает цикл

#### Scenario: Успешный вызов
- **WHEN** тул ответил вовремя
- **THEN** результат возвращается агенту

#### Scenario: Большой ответ
- **WHEN** ответ тула больше лимита
- **THEN** ответ обрезается с пометкой, контекст не переполняется

### Requirement: Выбор между MCP и прямым вызовом
Тип интеграции SHALL выбираться по правилам: детерминированные последовательности, пакетные операции и внутренние вызовы платформы (Runner↔ICPlan, Harness↔LLM Gateway, проверки G1–G4, автозапись M1/M2) — прямой вызов; действия, которые выбирает модель, — тул агента; тул, нужный нескольким агентам или хранящий секрет вне агента, — MCP-сервер; стабильный тул только для Harness — нативный тул.

#### Scenario: Внутренний вызов
- **WHEN** Agent Runner получает запуск из очереди ICPlan
- **THEN** используется прямой API, а не MCP

#### Scenario: Тул для нескольких агентов
- **WHEN** доступ к git-провайдеру нужен нескольким агентам
- **THEN** он подключается как MCP-сервер, секрет хранится на стороне сервера

#### Scenario: Пакетная операция
- **WHEN** нужно обработать 500 записей
- **THEN** используется прямой вызов, не тул модели

### Requirement: Административные тулы отделены
Административные функции (бюджеты, политики, профили) SHALL отдаваться отдельными MCP-серверами и MUST NOT подключаться рабочим агентам по умолчанию.

#### Scenario: Рабочий агент
- **WHEN** у рабочего агента запрашивается список тулов
- **THEN** административных тулов в нём нет

#### Scenario: Агент-администратор
- **WHEN** агенту явно подключён админ-сервер
- **THEN** админ-тулы ему видны, вызовы идут в аудит

#### Scenario: Попытка вызова
- **WHEN** рабочий агент пытается вызвать админ-тул по имени
- **THEN** вызов отклоняется

### Requirement: Скиллы
Скилл SHALL быть пакетом из инструкций и ссылок на тулы, подключаемым к агенту как единое целое.

#### Scenario: Подключение скилла
- **WHEN** агенту добавлен скилл
- **THEN** агент получает инструкции скилла и его тулы

#### Scenario: Скилл без тулов
- **WHEN** скилл содержит только инструкции
- **THEN** агент получает инструкции, набор тулов не меняется

#### Scenario: Скилл с недоступным тулом
- **WHEN** тул скилла не входит в allowlist агента
- **THEN** скилл подключается без этого тула, событие-предупреждение
