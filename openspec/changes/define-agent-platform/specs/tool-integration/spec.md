# Spec Delta

## Purpose

Подключение тулов и MCP-серверов к агентам через Registry, чтобы расширять возможности агентов без изменения кода платформы. Обоснование: [R&D](../../../../../docs/rnd/mcp-vs-direct.md).

## ADDED Requirements

### Requirement: Регистрация MCP-сервера
Система SHALL позволять зарегистрировать MCP-сервер в Registry и подключить его к агенту ссылкой в определении.

#### Scenario: Новый MCP-сервер
- **WHEN** администратор регистрирует MCP-сервер и добавляет его агенту
- **THEN** при следующем запуске тулы сервера доступны агенту

#### Scenario: Недоступный сервер
- **WHEN** регистрируемый сервер не отвечает
- **THEN** регистрация сохраняется с пометкой «недоступен», агенту тулы не выдаются

#### Scenario: Повторная регистрация
- **WHEN** сервер с тем же адресом уже есть
- **THEN** регистрация отклоняется как дубликат

<a id="r-mcp-01"></a>**ID:** `R-MCP-01` · **Реализует задача:** [1.4](../../../../../docs/tasks/1.4-harness-mcp-tools.md)

### Requirement: Ограничение набора тулов
Агенту SHALL быть доступны только тулы, явно перечисленные в его определении (допускается подмножество тулов MCP-сервера).

#### Scenario: Тул вне списка
- **WHEN** LLM запрашивает тул, не входящий в определение агента
- **THEN** вызов отклоняется

#### Scenario: Тул из списка
- **WHEN** LLM запрашивает тул из определения
- **THEN** вызов выполняется

#### Scenario: Новый тул на сервере
- **WHEN** на MCP-сервере появился тул, которого нет в allowlist
- **THEN** агенту он не виден

<a id="r-mcp-02"></a>**ID:** `R-MCP-02` · **Реализует задача:** [1.4](../../../../../docs/tasks/1.4-harness-mcp-tools.md)

### Requirement: Таймауты и ошибки тулов
Каждый вызов тула MUST иметь таймаут; ошибка или таймаут SHALL возвращаться агенту как результат тула, а не прерывать запуск.

#### Scenario: Недоступный MCP
- **WHEN** MCP-сервер не ответил за таймаут
- **THEN** агент получает ошибку тула и продолжает цикл

#### Scenario: Успешный вызов
- **WHEN** тул ответил вовремя
- **THEN** результат возвращается агенту

#### Scenario: Большой ответ
- **WHEN** ответ тула больше лимита
- **THEN** ответ обрезается с пометкой, контекст не переполняется

<a id="r-mcp-03"></a>**ID:** `R-MCP-03` · **Реализует задача:** [1.4](../../../../../docs/tasks/1.4-harness-mcp-tools.md)

### Requirement: Выбор между MCP и прямым вызовом
Тип интеграции SHALL выбираться по правилам: детерминированные последовательности, пакетные операции и внутренние вызовы платформы (Runner↔ICPlan, Harness↔LLM Gateway, проверки G1–G4, автозапись M1/M2) — прямой вызов; действия, которые выбирает модель, — тул агента; тул, нужный нескольким агентам или хранящий секрет вне агента, — MCP-сервер; стабильный тул только для Harness — нативный тул.

#### Scenario: Внутренний вызов
- **WHEN** Agent Runner получает запуск из очереди ICPlan
- **THEN** используется прямой API, а не MCP

#### Scenario: Тул для нескольких агентов
- **WHEN** доступ к git-провайдеру нужен нескольким агентам
- **THEN** он подключается как MCP-сервер, секрет хранится на стороне сервера

#### Scenario: Пакетная операция
- **WHEN** нужно обработать 500 записей
- **THEN** используется прямой вызов, не тул модели

<a id="r-mcp-04"></a>**ID:** `R-MCP-04` · **Реализует задача:** [2.4](../../../../../docs/tasks/2.4-mcp-itsaplan-core.md)

### Requirement: Административные тулы отделены
Административные функции (бюджеты, политики, профили) SHALL отдаваться отдельными MCP-серверами и MUST NOT подключаться рабочим агентам по умолчанию.

#### Scenario: Рабочий агент
- **WHEN** у рабочего агента запрашивается список тулов
- **THEN** административных тулов в нём нет

#### Scenario: Агент-администратор
- **WHEN** агенту явно подключён админ-сервер
- **THEN** админ-тулы ему видны, вызовы идут в аудит

#### Scenario: Попытка вызова
- **WHEN** рабочий агент пытается вызвать админ-тул по имени
- **THEN** вызов отклоняется

<a id="r-mcp-05"></a>**ID:** `R-MCP-05` · **Реализует задача:** [бэклог](../../../../../docs/BACKLOG.md)

### Requirement: Скиллы
Скилл SHALL быть пакетом из инструкций и ссылок на тулы, подключаемым к агенту как единое целое.

#### Scenario: Подключение скилла
- **WHEN** агенту добавлен скилл
- **THEN** агент получает инструкции скилла и его тулы

#### Scenario: Скилл без тулов
- **WHEN** скилл содержит только инструкции
- **THEN** агент получает инструкции, набор тулов не меняется

#### Scenario: Скилл с недоступным тулом
- **WHEN** тул скилла не входит в allowlist агента
- **THEN** скилл подключается без этого тула, событие-предупреждение

<a id="r-mcp-06"></a>**ID:** `R-MCP-06` · **Реализует задача:** [1.3](../../../../../docs/tasks/1.3-harness-core.md)

### Requirement: MCP-сервер ICPlan
Агент SHALL работать с ICPlan через MCP-сервер `itsaplan-core` (REST API ICPlan как тулы: чтение задачи, комментарий, `update_issue`, создание задач), включённый для проекта, по ключу агента. Для задачи в процессе смена колонки через `update_issue` MUST отклоняться (переход делает ICPlan).

#### Scenario: Работа с задачей
- **WHEN** агент читает задачу и пишет комментарий через `itsaplan-core`
- **THEN** данные и комментарий в задаче, от имени агента

#### Scenario: MCP выключен в проекте
- **WHEN** MCP проекта выключен
- **THEN** тулы ICPlan недоступны, запуск завершается с причиной

#### Scenario: Смена колонки в процессе
- **WHEN** агент вызывает `update_issue` со сменой колонки задачи в процессе
- **THEN** смена колонки отклонена, остальные поля обновлены

<a id="r-mcp-13"></a>**ID:** `R-MCP-13` · **Реализует задача:** [2.4](../../../../../docs/tasks/2.4-mcp-itsaplan-core.md), ✅ есть в ICPlan (базовое поведение)

### Requirement: Конфигурация модуля
Модуль SHALL брать свои параметры (5, таблица «Параметры модуля» в `interfaces.md`) с уровней L2 (S1), L0 (S9): значение — с самого конкретного уровня; значение вне границ «Мин»–«Макс» таблицы MUST отклоняться с ошибкой, называющей параметр и границы.

#### Scenario: Значение по умолчанию
- **WHEN** `servers` (подключённые MCP-серверы) не задан в конфигурации
- **THEN** применяется значение по умолчанию: itsaplan-core

#### Scenario: Выше максимума
- **WHEN** `timeout_s` задан больше 300
- **THEN** значение отклонено, ошибка называет `timeout_s` и границы 5–300

#### Scenario: Нет обязательного поля
- **WHEN** настройку сохраняют без `auth.secret_ref`
- **THEN** сохранение отклонено, ошибка называет `auth.secret_ref`

<a id="r-mcp-07"></a>**ID:** `R-MCP-07` · **Реализует задача:** [1.4](../../../../../docs/tasks/1.4-harness-mcp-tools.md), [2.8](../../../../../docs/tasks/2.8-config-storage-interfaces-fmea.md)

### Requirement: Хранилища данных
Модуль SHALL хранить и читать свои данные только в S1 (PostgreSQL 17 (CloudNativePG), БД `itsaplan`) (`interfaces.md`); к данным других модулей — только через их API. Секреты MUST NOT храниться в БД и git.

#### Scenario: Запись в своё хранилище
- **WHEN** модуль сохраняет mCP-серверы проекта, тулы и навыки, ссылки на секреты
- **THEN** запись попадает в S1 (PostgreSQL 17 (CloudNativePG), БД `itsaplan`)

#### Scenario: S1 недоступно
- **WHEN** S1 (PostgreSQL 17 (CloudNativePG), БД `itsaplan`) не отвечает
- **THEN** операция завершается ошибкой без частичной записи, событие эксплуатации

#### Scenario: Доступ вне своих хранилищ
- **WHEN** код tool-integration обращается к таблицам вне S1
- **THEN** доступа нет: роль БД tool-integration ограничена S1

<a id="r-mcp-08"></a>**ID:** `R-MCP-08` · **Реализует задача:** [1.4](../../../../../docs/tasks/1.4-harness-mcp-tools.md)

### Requirement: Интерфейсы обмена
Интерфейсы модуля (I9, I17) SHALL соблюдать протокол, формат, аутентификацию, таймаут и политику повтора из `interfaces.md`; неидемпотентные вызовы MUST NOT повторяться автоматически.

#### Scenario: Таймаут I9
- **WHEN** Harness → MCP-серверы (I9) не ответил за 30 с
- **THEN** вызов прерывается; повтор: чтение — 2 раза; запись — нет

#### Scenario: Аутентификация I17
- **WHEN** собеседник по I17 отклонил учётные данные (allowlist хостов, подстановка секретов)
- **THEN** вызов не повторяется, событие с причиной

#### Scenario: Неидемпотентный вызов I9
- **WHEN** вызов I9 (Harness → MCP-серверы) прервался сбоем сети
- **THEN** автоматического повтора нет, решение принимает вызывающий

<a id="r-mcp-09"></a>**ID:** `R-MCP-09` · **Реализует задача:** [1.4](../../../../../docs/tasks/1.4-harness-mcp-tools.md), [2.4](../../../../../docs/tasks/2.4-mcp-itsaplan-core.md)

### Requirement: Поведение при отказах зависимостей
Модуль SHALL вести себя при отказах зависимостей по таблице FMEA (`interfaces.md`): отказ обнаруживается, поведение предсказуемо и безопасно (fail-closed для проверок безопасности), восстановление не теряет данные.

#### Scenario: MCP-сервер недоступен
- **WHEN** mcp-сервер недоступен
- **THEN** ошибка тула агенту

#### Scenario: Секрет MCP не задан
- **WHEN** секрет mcp не задан
- **THEN** тулы сервера недоступны агенту, предупреждение

#### Scenario: Сервер изменил набор тулов
- **WHEN** сервер изменил набор тулов
- **THEN** новые тулы не видны без allowlist

<a id="r-mcp-10"></a>**ID:** `R-MCP-10` · **Реализует задача:** [1.4](../../../../../docs/tasks/1.4-harness-mcp-tools.md)

### Requirement: Нагрузка и производительность
Модуль SHALL выдерживать профиль нагрузки (`interfaces.md`, «Нагрузка и развёртывание»): вызовы MCP ~1 RPS; таймаут 30 с. Превышение профиля MUST приводить к очереди или отказу с причиной, а не к деградации всей платформы.

#### Scenario: Пик профиля
- **WHEN** нагрузка достигает профиля: вызовы MCP ~1 RPS
- **THEN** выполняется: профиль выдерживается без ошибок

#### Scenario: Превышение профиля
- **WHEN** нагрузка вдвое выше профиля (вызовы MCP ~1 RPS)
- **THEN** лишние вызовы ждут в очереди или получают отказ с причиной, активные запуски не страдают

#### Scenario: Замер
- **WHEN** нагрузочный тест 4.8 на профиле «вызовы MCP ~1 RPS»
- **THEN** фактические значения (профиль выдерживается без ошибок) записаны и сравнены с профилем

<a id="r-mcp-11"></a>**ID:** `R-MCP-11` · **Реализует задача:** [4.8](../../../../../docs/tasks/4.8-load-test.md)

### Requirement: Развёртывание
Модуль SHALL разворачиваться так: MCP `itsaplan-core` — часть api ICPlan; внешние MCP — через egress-прокси. Ресурсы MUST задаваться requests / limits, версии образов — закреплены; публичный доступ — только через ingress, если он указан.

#### Scenario: Установка
- **WHEN** выполняется `helm install`: MCP `itsaplan-core` — часть api ICPlan; внешние MCP — через egress-прокси
- **THEN** объекты созданы в своём namespace с заданными requests / limits, проверки готовности зелёные

#### Scenario: Обновление
- **WHEN** выходит новая версия образа `itsaplan-core` (1 реплика)
- **THEN** `itsaplan-core` заменяется по одной реплике; работа, начатая на старой версии, доделывается

#### Scenario: Нехватка ресурсов
- **WHEN** узлу не хватает ресурсов для пода `itsaplan-core`
- **THEN** под `itsaplan-core` ждёт размещения, событие эксплуатации
