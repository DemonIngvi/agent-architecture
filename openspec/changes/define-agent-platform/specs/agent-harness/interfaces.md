## Уровни конфигурации

| Уровень | Что | Где хранится | Область |
|---|---|---|---|
| L0 | Конфиг деплоя | S9 | платформа целиком: адреса, переключатели G1–G4, режим планирования, потолки лимитов |
| L1 | Platform module | S2 | агент: бюджеты, профили, данные guardrails, флаги планирования |
| L2 | Определение агента | S1 (+ YAML импорт) | агент: модель, инструкция, тулы, навыки, MCP, лимиты запуска |
| L3 | Запуск | задача ICPlan / `Run` | версия агента, критерии приёмки, задание |

Правило: значение берётся с самого конкретного уровня (L3 → L0), но не выше потолка L0.

## Параметры модуля

| Параметр | Что задаёт | Уровень | Хранилище | По умолчанию |
|---|---|---|---|---|
| `limits.max_steps` | Шагов цикла | L2 | S1 | 30 |
| `limits.max_tokens` | Токенов на запуск | L2 | S1 | 200 000 |
| `compaction.threshold` | Когда сжимать историю | L2 | S1 | 80% окна |
| `approval.tools` | Тулы с паузой на подтверждение | L2 | S1 | из guardrails |
| `hooks` | Подключённые hooks | L0 | S9 | G2 |
| `checkpoint.ttl` | Сколько хранить состояние | L0 | S9 | 7 дней |

## Интерфейсы обмена

| ID | От → к | Протокол | Формат | Аутентификация | Режим | Таймаут | Повтор | Идемпотентность |
|---|---|---|---|---|---|---|---|---|
| I7 | Agent Runner ↔ Harness | HTTP внутри сети sandbox; события — NDJSON-поток | `RunBundle`, `RunEvent`, `RunResult`, `ApprovalDecision` | одноразовый токен запуска | поток | = `timeout_s` | переподключение с последнего `seq` | да, по `seq` |
| I8 | Harness → LiteLLM | HTTP, OpenAI Chat Completions, SSE-стрим | JSON + `metadata.run_id` | Bearer virtual key (подставляет egress-прокси) | синхронно / стрим | 120 с | 2 раза с backoff | нет — повтор = новые затраты |
| I9 | Harness → MCP-серверы | MCP Streamable HTTP, JSON-RPC 2.0 | `tools/list`, `tools/call` | токен подставляет egress-прокси | синхронно | 30 с | чтение — 2 раза; запись — нет | запись — нет |
| I10 | Harness → OPA (G2) | HTTP REST `POST /v1/data/agent/g2` | JSON `PolicyInput` / `PolicyDecision` | внутренняя сеть | синхронно | 200 мс | нет → `on_engine_error` | чтение |
| I11 | Harness → Memory API | HTTP REST | JSON `M3Record`, контекст | токен запуска | синхронно | 2 с | 2 раза | запись M3 — upsert по (задача, область) |
| I12 | Harness → checkpointer | протокол PostgreSQL к схеме `harness_ckpt` | LangGraph checkpoint | роль только на свою схему | синхронно | 5 с | 2 раза | да, по (thread, step) |

## Нагрузка и развёртывание

| | |
|---|---|
| **Нагрузка** (гипотеза, [R&D](../../../../../docs/rnd/load-profile.md)) | шаг цикла 5–20 с; ~0.1 RPS к LiteLLM на запуск; до 200 тыс. токенов на запуск |
| **Развёртывание** ([R&D](../../../../../docs/rnd/kubernetes-runtime.md)) | процесс внутри контейнера sandbox, образ `harness:<версия>`; ресурсы — профиль sandbox |

Детали форматов — [потоки](../../../../../docs/flows/harness.md).

## Отказы (FMEA)

| Отказ | Обнаружение | Поведение | Восстановление |
|---|---|---|---|
| LiteLLM недоступен | ошибки I8 | повтор с backoff; после `circuit.max_errors` — `failed` | запуск заново |
| MCP-сервер недоступен | таймаут I9 | ошибка тула возвращается агенту, цикл продолжается | circuit breaker |
| Checkpointer недоступен | ошибка I12 | пауза на approve невозможна — опасные действия отклоняются | восстановление БД |
| Memory API недоступен | ошибка I11 | запуск идёт без M3/M2, событие-предупреждение | повтор записи M3 в конце |
| Битое определение агента | валидация Bootstrap | запуск не стартует, `invalid_definition` | исправление определения |
