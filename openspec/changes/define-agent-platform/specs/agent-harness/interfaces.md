# agent-harness — конфигурация, данные, интерфейсы, отказы

← [spec.md](spec.md) · [схема](architecture.md) · [трассировка](traceability.md) · [правила](../../../../../docs/rules/spec-criteria.md)

## Уровни конфигурации

| Уровень | Что | Где хранится | Область |
|---|---|---|---|
| L0 | Конфиг деплоя | S9 | платформа целиком: адреса, переключатели G1–G4, режим планирования, потолки лимитов |
| L1 | Platform module | S2 | агент: бюджеты, профили, данные guardrails, флаги планирования |
| L2 | Определение агента | S1 (+ YAML импорт) | агент: модель, инструкция, тулы, навыки, MCP, лимиты запуска |
| L3 | Запуск | задача ICPlan / `Run` | версия агента, критерии приёмки, задание |

Правило: значение берётся с самого конкретного уровня (L3 → L0), но не выше потолка L0.

## Параметры модуля

Значения и границы пересматриваются по статистике запусков (3.9) и нагрузочному тесту (4.8); правило — [виды спек, таблица параметров](../../../../../docs/rules/spec-kinds.md#params).

| Параметр | Что задаёт | Уровень | Хранилище | По умолчанию | Почему так по умолчанию | Мин | Макс | На что опираться при выборе |
|---|---|---|---|---|---|---|---|---|
| `model.temperature` | Температура выборки | L2 | S1 | 0.2 | работа по задаче требует повторяемости, а не разнообразия | 0 | 1.0 | выше 1 ответы непредсказуемы; творческим агентам (тексты) — 0.5–0.8 |
| `model.top_p` | Отсечение по вероятности | L2 | S1 | 1.0 | регулируется температурой; не менять оба сразу | 0.1 | 1.0 | менять только если не помогает температура |
| `model.max_output_tokens` | Лимит токенов одного ответа модели | L2 | S1 | 8192 | хватает на план и код одного шага | 256 | лимит выхода модели | длина типичного ответа шага; больше — дольше и дороже шаг |
| `model.reasoning_effort` | Глубина размышлений модели | L2 | S1 | medium | баланс качества и стоимости | low | high | high — для анализа и архитектуры; low — для рутинных шагов; только у моделей с размышлениями |
| `model.reasoning_budget_tokens` | Бюджет токенов размышлений на ответ | L2 | S1 | 8000 | ≈ размер ответа; минимум провайдеров — 1024 | 1024 | `model.max_output_tokens` × 4 | доля размышлений в затратах (3.9) |
| `model.tool_choice` | Обязан ли агент вызвать тул | L2 | S1 | auto | модель сама решает, нужен ли тул | none | required | required — для шагов, где без тула нет результата |
| `model.parallel_tool_calls` | Несколько вызовов тулов в одном ответе | L2 | S1 | false | каждый вызов проходит G2 по очереди, проще аудит | false | true | true — только для тулов чтения без подтверждений |
| `model.response_format` | Формат итогового ответа | L2 | S1 | text | итог — комментарий в задаче | text | json_schema | json_schema — если итог разбирает следующий шаг автоматически |
| `prompt.platform_version` | Версия системного промпта платформы | L0 | S9 | версия образа Harness | промпт поставляется с образом и меняется вместе с ним | — | — | изменение — только новым образом Harness с проверкой на тестовых задачах |
| `prompt.cache` | Кэш стабильного префикса промпта у провайдера | L0 | S9 | вкл | слои 1–4 стабильны между шагами — дешевле и быстрее | выкл | вкл | выкл — если провайдер не поддерживает |
| `request.timeout_s` | Таймаут одного вызова модели | L0 | S9 | 120 | долгий ответ с размышлениями укладывается в 2 мин | 10 | 600 | p95 длительности вызова по LiteLLM |
| `workspace.publish` | Что публиковать по итогу запуска | L2 | S1 | вложения + PR | результат там, где его ждёт пользователь | ничего | вложения, PR, папка задачи | куда смотрит следующий шаг процесса |
| `limits.max_steps` | Шагов цикла | L2 | S1 | 30 | типичный запуск ~9 шагов (поток Harness) × 3 запас | 5 | 200 | p95 шагов по статистике запусков (3.9); больше 200 — признак зацикливания, ограничивает бюджет |
| `limits.max_tokens` | Токенов на запуск | L2 | S1 | 200 000 | ~55 тыс. токенов на запуск по профилю нагрузки × 3–4 | 20 000 | потолок `budget.per_run_tokens` L0 | p95 токенов запуска; не выше потолка L0 и бюджета запуска в $ |
| `compaction.threshold` | Когда сжимать историю | L2 | S1 | 80% окна | оставляет 20% окна на ответ модели и вывод тула | 50% окна | 90% окна | ниже — частое сжатие, теряются детали; выше — переполнение при большом выводе тула (`max_result_kb` 64 ≈ 16 тыс. токенов) |
| `approval.tools` | Тулы с паузой на подтверждение | L2 | S1 | из guardrails | единый источник правил — guardrails | пусто | все тулы агента | уровень автономии R0–R5 и необратимость действия |
| `hooks` | Подключённые hooks | L0 | S9 | G2 | проверка каждого действия включена | G2 | G2, аудит, маскирование | G2 обязателен, если `g2.enabled`; дополнительные — по требованиям безопасности |
| `checkpoint.ttl` | Сколько хранить состояние | L0 | S9 | 7 дней | подтверждение ждёт до 24 ч + выходные + запас | `approval_timeout` (24 ч) | 30 дней | не меньше ожидания подтверждения; больше — растёт объём S5 |

## Нагрузка и развёртывание

| | |
|---|---|
| **Нагрузка** (гипотеза, [R&D](../../../../../docs/rnd/load-profile.md)) | шаг цикла 5–20 с; ~0.1 RPS к LiteLLM на запуск; до 200 тыс. токенов на запуск |
| **Развёртывание** ([R&D](../../../../../docs/rnd/kubernetes-runtime.md)) | процесс внутри контейнера sandbox, образ `ghcr.io/demoningvi/agent-agent-harness:<версия>`; ресурсы — профиль sandbox |

Детали форматов — [потоки](../../../../../docs/how/harness.md).

## Отказы (FMEA)

| Отказ | Обнаружение | Поведение | Восстановление |
|---|---|---|---|
| LiteLLM недоступен | ошибки I8 | повтор с backoff; после `circuit.max_errors` — `failed` | запуск заново |
| MCP-сервер недоступен | таймаут I9 | ошибка тула возвращается агенту, цикл продолжается | circuit breaker |
| Checkpointer недоступен | ошибка I12 | пауза на approve невозможна — опасные действия отклоняются | восстановление БД |
| Memory API недоступен | ошибка I11 | запуск идёт без M3/M2, событие-предупреждение | повтор записи M3 в конце |
| Битое определение агента | валидация Bootstrap | запуск не стартует, `invalid_definition` | исправление определения |
