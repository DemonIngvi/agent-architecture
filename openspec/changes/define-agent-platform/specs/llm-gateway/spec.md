# Spec Delta

## Purpose

Единственная точка выхода агентов к LLM-провайдерам: маршрутизация по алиасам моделей, учёт и лимиты токенов, fallback и применение G4. Обоснование: [R&D](../../../../../docs/rnd/llm-gateway.md).

## ADDED Requirements

### Requirement: Алиасы моделей
Агенты SHALL обращаться к моделям по алиасам; соответствие алиаса провайдеру и модели MUST настраиваться в шлюзе без изменения агентов.

#### Scenario: Перенаправление алиаса
- **WHEN** администратор переназначает алиас на другую модель
- **THEN** новые вызовы по алиасу идут в новую модель

#### Scenario: Неизвестный алиас
- **WHEN** агент обращается к несуществующему алиасу
- **THEN** вызов отклоняется с ошибкой алиаса

#### Scenario: Смена во время запуска
- **WHEN** алиас переназначен, пока идёт запуск
- **THEN** следующие вызовы запуска идут в новую модель, событие пишется в таймлайн

<a id="r-llm-01"></a>**ID:** `R-LLM-01` · **Реализует задача:** [1.1](../../../../../docs/tasks/1.1-mock-llm-litellm.md)

### Requirement: Учёт токенов
Шлюз SHALL учитывать токены и стоимость каждого вызова с привязкой к агенту и `run_id`.

#### Scenario: Подсчёт по запуску
- **WHEN** запуск завершён
- **THEN** известны суммарные токены и $ этого запуска

#### Scenario: Стрим
- **WHEN** ответ модели пришёл стримом
- **THEN** токены учтены по завершении стрима

#### Scenario: Ошибка провайдера
- **WHEN** провайдер вернул ошибку
- **THEN** неуспешный вызов учитывается отдельно, без стоимости ответа

<a id="r-llm-02"></a>**ID:** `R-LLM-02` · **Реализует задача:** [1.1](../../../../../docs/tasks/1.1-mock-llm-litellm.md), [3.5](../../../../../docs/tasks/3.5-icplan-type-actions-cost.md)

### Requirement: Атрибуция затрат
Каждый вызов модели SHALL нести ключ агента и метаданные запуска (`run_id`, задача); вызов без них MUST отклоняться.

#### Scenario: Вызов без метаданных
- **WHEN** приходит вызов без `run_id`
- **THEN** вызов отклоняется, затраты не теряются без привязки

#### Scenario: Вызов с метаданными
- **WHEN** вызов содержит `run_id` и задачу
- **THEN** затраты привязаны к запуску и задаче

#### Scenario: Чужой ключ
- **WHEN** вызов идёт с ключом другого агента
- **THEN** затраты записываются на агента ключа, событие несоответствия в аудит

<a id="r-llm-03"></a>**ID:** `R-LLM-03` · **Реализует задача:** [3.5](../../../../../docs/tasks/3.5-icplan-type-actions-cost.md)

### Requirement: Mock-модель для разработки
Шлюз SHALL позволять направить алиас на mock-модель со сценарными ответами (текст, вызов тула, ошибка, задержка) без изменения агентов.

#### Scenario: Разработка без ключа провайдера
- **WHEN** алиас `team-default` направлен на mock
- **THEN** агент получает ответы сценария, затраты считаются по сценарию

#### Scenario: Сценарий с вызовом тула
- **WHEN** сценарий mock содержит `tool_call`
- **THEN** агент получает корректный `tool_calls`

#### Scenario: Нет подходящего сценария
- **WHEN** запрос не совпал ни с одним сценарием
- **THEN** mock возвращает ответ по умолчанию и отмечает это в логе

<a id="r-llm-04"></a>**ID:** `R-LLM-04` · **Реализует задача:** [1.1](../../../../../docs/tasks/1.1-mock-llm-litellm.md)

### Requirement: Лимиты
Шлюз MUST отклонять вызовы сверх лимитов токенов, $ или частоты для агента.

#### Scenario: Превышен rate limit
- **WHEN** агент превысил лимит частоты запросов
- **THEN** вызов отклоняется с ошибкой лимита

#### Scenario: В пределах лимита
- **WHEN** агент вызывает модель ниже лимитов
- **THEN** вызов проходит

#### Scenario: Исчерпан бюджет ключа
- **WHEN** бюджет virtual key исчерпан
- **THEN** вызов отклоняется до обращения к провайдеру

<a id="r-llm-05"></a>**ID:** `R-LLM-05` · **Реализует задача:** [4.5](../../../../../docs/tasks/4.5-litellm-budgets-fallback-g4.md)

### Requirement: Fallback
Шлюз SHALL поддерживать резервную модель для алиаса на случай недоступности основной.

#### Scenario: Провайдер недоступен
- **WHEN** основная модель вернула ошибку недоступности
- **THEN** запрос выполняется резервной моделью, факт фиксируется в трейсе

#### Scenario: Резерв не задан
- **WHEN** основная модель недоступна, fallback не настроен
- **THEN** вызов завершается ошибкой, Harness применяет повтор

#### Scenario: Резерв тоже недоступен
- **WHEN** основная и резервная модели недоступны
- **THEN** ошибка `all_providers_failed`

<a id="r-llm-06"></a>**ID:** `R-LLM-06` · **Реализует задача:** [4.5](../../../../../docs/tasks/4.5-litellm-budgets-fallback-g4.md)

### Requirement: Несколько провайдеров
Шлюз SHALL поддерживать облачных провайдеров и локальные модели через единый интерфейс.

#### Scenario: Локальная модель
- **WHEN** алиас агента указывает на локальную модель
- **THEN** агент работает без изменений в своём определении

#### Scenario: Облачный провайдер
- **WHEN** алиас указывает на облачную модель
- **THEN** агент работает без изменений

#### Scenario: Нет ключа провайдера
- **WHEN** у провайдера не задан ключ
- **THEN** алиас помечен недоступным, вызов отклоняется

<a id="r-llm-07"></a>**ID:** `R-LLM-07` · **Реализует задача:** [1.1](../../../../../docs/tasks/1.1-mock-llm-litellm.md)

### Requirement: Конфигурация модуля
Модуль SHALL брать свои параметры (6, таблица «Параметры модуля» в `interfaces.md`) с уровней L0 (S9 (`litellm config.yaml`)), L1 (S6): значение — с самого конкретного уровня; значение вне границ «Мин»–«Макс» таблицы MUST отклоняться с ошибкой, называющей параметр и границы.

#### Scenario: Значение по умолчанию
- **WHEN** `drop_params` (отбрасывать параметры, которые модель не…) не задан в конфигурации
- **THEN** применяется значение по умолчанию: true

#### Scenario: Граница от другого параметра
- **WHEN** `key.max_budget` задан больше, чем `budget.daily_usd`
- **THEN** значение отклонено: `key.max_budget` не может быть больше `budget.daily_usd`

#### Scenario: Недопустимое значение
- **WHEN** `model_list` задан вне допустимых значений (1 алиас … —)
- **THEN** значение отклонено, ошибка называет `model_list` и допустимые значения

<a id="r-llm-08"></a>**ID:** `R-LLM-08` · **Реализует задача:** [1.1](../../../../../docs/tasks/1.1-mock-llm-litellm.md)

### Requirement: Хранилища данных
Модуль SHALL хранить свои данные только в S6 (PostgreSQL 17 (тот же кластер), БД `litellm`) (`interfaces.md`); данные S9 — доступ только через API или конфигурацию владельца. Секреты MUST NOT храниться в БД и git.

#### Scenario: Запись в своё хранилище
- **WHEN** модуль сохраняет virtual keys, бюджеты, журнал затрат
- **THEN** запись попадает в S6 (PostgreSQL 17 (тот же кластер), БД `litellm`)

#### Scenario: S6 недоступно
- **WHEN** S6 (PostgreSQL 17 (тот же кластер), БД `litellm`) не отвечает
- **THEN** проверка бюджетов невозможна — вызовы отклоняются

#### Scenario: Доступ вне своих хранилищ
- **WHEN** код llm-gateway обращается к таблицам вне S6, S9
- **THEN** доступа нет: роль БД llm-gateway ограничена S6, S9

<a id="r-llm-09"></a>**ID:** `R-LLM-09` · **Реализует задача:** [1.1](../../../../../docs/tasks/1.1-mock-llm-litellm.md)

### Requirement: Интерфейсы обмена
Интерфейсы модуля (I8, I13, I14, I15, I22) SHALL соблюдать протокол, формат, аутентификацию, таймаут и политику повтора из `interfaces.md`; неидемпотентные вызовы MUST NOT повторяться автоматически.

#### Scenario: Таймаут I8
- **WHEN** Harness → LiteLLM (I8) не ответил за 120 с
- **THEN** вызов прерывается; повтор: 2 раза с backoff

#### Scenario: Аутентификация I13
- **WHEN** собеседник по I13 отклонил учётные данные (ключ провайдера в LiteLLM (Secret))
- **THEN** вызов не повторяется, событие с причиной

#### Scenario: Неидемпотентный вызов I8
- **WHEN** вызов I8 (Harness → LiteLLM) прервался сбоем сети
- **THEN** автоматического повтора нет, решение принимает вызывающий

<a id="r-llm-10"></a>**ID:** `R-LLM-10` · **Реализует задача:** [1.1](../../../../../docs/tasks/1.1-mock-llm-litellm.md)

### Requirement: Поведение при отказах зависимостей
Модуль SHALL вести себя при отказах зависимостей по таблице FMEA (`interfaces.md`): отказ обнаруживается, поведение предсказуемо и безопасно (fail-closed для проверок безопасности), восстановление не теряет данные.

#### Scenario: Провайдер недоступен
- **WHEN** провайдер недоступен
- **THEN** fallback-модель; если нет — ошибка вызова

#### Scenario: БД `litellm` недоступна
- **WHEN** бд `litellm` недоступна
- **THEN** проверка бюджетов невозможна — вызовы отклоняются

#### Scenario: Нет ключа провайдера
- **WHEN** нет ключа провайдера
- **THEN** алиас недоступен

#### Scenario: LiteLLM упал
- **WHEN** litellm упал
- **THEN** вызовы Harness получают ошибку, circuit breaker

<a id="r-llm-11"></a>**ID:** `R-LLM-11` · **Реализует задача:** [1.1](../../../../../docs/tasks/1.1-mock-llm-litellm.md), [4.5](../../../../../docs/tasks/4.5-litellm-budgets-fallback-g4.md)

### Requirement: Нагрузка и производительность
Модуль SHALL выдерживать профиль нагрузки (`interfaces.md`, «Нагрузка и развёртывание»): 0.4–1 RPS, ~55 тыс. токенов/мин в пике; ответ модели 5–20 с, стрим. Превышение профиля MUST приводить к очереди или отказу с причиной, а не к деградации всей платформы.

#### Scenario: Пик профиля
- **WHEN** нагрузка достигает профиля: 0.4–1 RPS
- **THEN** выполняется: профиль выдерживается без ошибок

#### Scenario: Превышение профиля
- **WHEN** нагрузка вдвое выше профиля (0.4–1 RPS)
- **THEN** лишние вызовы ждут в очереди или получают отказ с причиной, активные запуски не страдают

#### Scenario: Замер
- **WHEN** нагрузочный тест 4.8 на профиле «0.4–1 RPS»
- **THEN** фактические значения (профиль выдерживается без ошибок) записаны и сравнены с профилем

<a id="r-llm-12"></a>**ID:** `R-LLM-12` · **Реализует задача:** [4.8](../../../../../docs/tasks/4.8-load-test.md)

### Requirement: Развёртывание
Модуль SHALL разворачиваться так: LiteLLM — Deployment `litellm` в `itsaplan-agents`, 2 реплики за Service ClusterIP; БД `litellm` через PgBouncer; админка без ingress. Ресурсы MUST задаваться requests / limits, версии образов — закреплены; публичный доступ — только через ingress, если он указан.

#### Scenario: Установка
- **WHEN** выполняется `helm install`: LiteLLM — Deployment `litellm` в `itsaplan-agents`, 2 реплики за Service ClusterIP; БД `litellm` через PgBouncer; админка без ingress
- **THEN** объекты созданы в своём namespace с заданными requests / limits, проверки готовности зелёные

#### Scenario: Обновление
- **WHEN** выходит новая версия образа `litellm` (2 реплики)
- **THEN** `litellm` заменяется по одной реплике; работа, начатая на старой версии, доделывается

#### Scenario: Нехватка ресурсов
- **WHEN** узлу не хватает ресурсов для пода `litellm`
- **THEN** под `litellm` ждёт размещения, событие эксплуатации
