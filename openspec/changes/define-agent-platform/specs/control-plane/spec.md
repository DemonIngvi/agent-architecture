# Spec Delta

## Purpose

API управления платформой — CRUD над ресурсами Registry и просмотр запусков; CLI и UI — оболочки над тем же API. Обоснование: [R&D](../../../../../docs/rnd/config-storage.md).

## ADDED Requirements

### Requirement: Управление ресурсами
Control Plane SHALL предоставлять создание, чтение, изменение и архивирование всех ресурсов Registry.

#### Scenario: Изменение промпта
- **WHEN** администратор изменяет промпт через API
- **THEN** создаётся новая версия промпта в Registry

### Requirement: Единый API для всех клиентов
CLI и UI SHALL работать только через API Control Plane; прямой доступ к хранилищу Registry MUST быть недоступен клиентам.

#### Scenario: Действие через CLI
- **WHEN** администратор создаёт агента через CLI
- **THEN** результат идентичен созданию через API

### Requirement: Импорт декларативных конфигов
Control Plane SHALL принимать определения ресурсов в виде файлов конфигурации (YAML).

#### Scenario: Загрузка YAML
- **WHEN** администратор загружает YAML с определением агента
- **THEN** агент создаётся после валидации связей Registry

### Requirement: Просмотр запусков
Control Plane SHALL показывать список запусков с фильтрами по агенту, статусу и периоду, а также затраты токенов/$.

#### Scenario: Затраты по агенту
- **WHEN** администратор запрашивает затраты агента за период
- **THEN** возвращается сумма токенов и $ по запускам этого агента

### Requirement: Доступ по ролям
Control Plane MUST требовать аутентификацию и разграничивать права на чтение и изменение ресурсов.

#### Scenario: Нет прав
- **WHEN** пользователь без права изменения пытается изменить агента
- **THEN** запрос отклоняется с ошибкой доступа
