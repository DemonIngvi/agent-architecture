# Spec Delta

## Purpose

Platform module — модуль ICPlan для настроек агентов, которых нет в ICPlan: алиасы моделей, бюджеты, профили sandbox и памяти, данные guardrails, параметры планирования, версии определений. UI — экраны ICPlan. Обоснование: [R&D](../../../../../docs/rnd/config-storage.md).

## ADDED Requirements

### Requirement: Настройки агента
Модуль SHALL хранить для агента: алиас модели, бюджеты (запуск, сутки), лимиты запуска, профиль sandbox, профиль памяти, данные guardrails (разрешённые тулы, тулы с подтверждением), флаги планирования (`parallel`, `max`), allowlist репозиториев.

#### Scenario: Сохранение настроек
- **WHEN** администратор задаёт агенту бюджет 5 $ в сутки и профиль sandbox `light`
- **THEN** настройки сохранены и видны в карточке агента в ICPlan

#### Scenario: Недопустимое значение
- **WHEN** администратор задаёт отрицательный бюджет или несуществующий профиль
- **THEN** сохранение отклоняется с указанием поля и причины

### Requirement: Хранение в БД ICPlan
Настройки MUST храниться в БД ICPlan в отдельной схеме модуля; доступ исполнителей SHALL идти через API модуля, а не напрямую к таблицам.

#### Scenario: Чтение Runner
- **WHEN** Agent Runner запрашивает настройки агента перед запуском
- **THEN** получает их через API модуля

### Requirement: Применение к следующему запуску
Изменение настроек SHALL применяться к следующим запускам и MUST NOT менять активные запуски.

#### Scenario: Смена бюджета во время запуска
- **WHEN** администратор уменьшает бюджет, пока идёт запуск
- **THEN** активный запуск работает по прежним настройкам, следующий — по новым

### Requirement: Версии определения агента
Каждое изменение определения агента SHALL создавать версию; запуск MAY указывать версию явно, иначе MUST использоваться последняя.

#### Scenario: Запуск на прежней версии
- **WHEN** в запуске указана версия 3, а последняя — 5
- **THEN** агент исполняется по версии 3

### Requirement: Экспорт и импорт YAML
Модуль SHALL экспортировать определение агента с настройками в YAML `agent/v1` и импортировать его, проверяя схему и ссылки.

#### Scenario: Перенос в prod
- **WHEN** администратор импортирует YAML, выгруженный из dev
- **THEN** в prod создаётся новая версия агента с тем же содержимым

#### Scenario: Битая ссылка при импорте
- **WHEN** YAML ссылается на несуществующий MCP-сервер
- **THEN** импорт отклоняется с указанием ссылки

### Requirement: Раздача настроек исполнителям
Модуль SHALL передавать алиасы и бюджеты в LiteLLM, а данные правил — в OPA; рассинхронизация MUST обнаруживаться и показываться администратору.

#### Scenario: Новое правило
- **WHEN** администратор добавляет тул в список с подтверждением
- **THEN** следующий вызов этого тула агентом ждёт approve (данные в OPA обновлены)

### Requirement: Права на настройки
Изменять настройки SHALL только роли с правом управления агентами; остальные MUST получать отказ.

#### Scenario: Нет прав
- **WHEN** участник без права пытается изменить бюджет агента
- **THEN** запрос отклоняется с ошибкой доступа
