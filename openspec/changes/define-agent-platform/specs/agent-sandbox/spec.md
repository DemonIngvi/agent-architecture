# Spec Delta

## Purpose

Изолированная среда исполнения, создаваемая на каждый запуск агента, чтобы запуски не влияли друг на друга и на хост.

## ADDED Requirements

### Requirement: Среда на каждый запуск
Система SHALL выделять отдельный sandbox на каждый запуск и MUST NOT переиспользовать его между запусками.

#### Scenario: Два параллельных запуска
- **WHEN** один агент запущен дважды параллельно
- **THEN** у запусков разные sandbox и они не видят файлы друг друга

### Requirement: Тёплый пул
Система SHALL держать по каждому sandbox-профилю заранее запущенные sandbox (размер пула — параметр профиля); запуск SHALL забирать готовый sandbox из пула, а после запуска sandbox MUST уничтожаться, а пул — доливаться.

#### Scenario: Быстрый старт
- **WHEN** в пуле профиля есть свободный sandbox
- **THEN** запуск начинается без создания контейнера, после завершения контейнер уничтожен, в пуле снова N свободных

#### Scenario: Пул пуст
- **WHEN** свободных sandbox в пуле нет
- **THEN** sandbox создаётся заново, запуск ждёт его старта

### Requirement: Эфемерный workspace
Рабочие файлы запуска SHALL лежать в `/workspace` внутри sandbox и MUST уничтожаться вместе с ним; результаты SHALL сохраняться вне sandbox: код — веткой и PR в целевой репозиторий, документы и артефакты — в задачу ICPlan, состояние задачи и лог — в БД.

#### Scenario: После запуска
- **WHEN** запуск завершился
- **THEN** `/workspace` удалён, код в ветке `agent/<KEY>`, артефакты во вложениях задачи

### Requirement: Доступ к репозиториям
Sandbox SHALL получать доступ только к репозиториям из allowlist агента с указанным уровнем (read или write); токен MUST быть короткоживущим, выдаваться на запуск и подставляться прокси или credential helper, а не через env. Запись в защищённые ветки MUST быть запрещена.

#### Scenario: Репозиторий вне allowlist
- **WHEN** агент пытается клонировать репозиторий не из allowlist
- **THEN** доступ отклонён

#### Scenario: Push в main
- **WHEN** агент пытается сделать push в защищённую ветку
- **THEN** push отклонён, разрешена только ветка с префиксом агента

### Requirement: Профиль sandbox
Параметры sandbox (образ, CPU, RAM, диск, сетевые правила) SHALL задаваться sandbox-профилем из определения агента.

#### Scenario: Тяжёлый агент
- **WHEN** агент ссылается на профиль с увеличенной RAM
- **THEN** его sandbox создаётся с этой RAM

### Requirement: Сетевая изоляция
Sandbox MUST разрешать исходящие соединения только к LLM Gateway, Memory Service, разрешённым MCP/тулам и доменам из allowlist профиля.

#### Scenario: Запрещённый домен
- **WHEN** агент обращается к домену вне allowlist
- **THEN** соединение блокируется и событие фиксируется

### Requirement: Секреты
Секреты MUST NOT передаваться в sandbox в открытом виде; доступ к внешним системам SHALL идти через прокси с подстановкой учётных данных.

#### Scenario: Вызов тула с ключом
- **WHEN** тул обращается к внешнему API
- **THEN** ключ подставляется прокси, агент его не видит
