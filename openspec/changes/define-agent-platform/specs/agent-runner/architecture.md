# agent-runner — схема

← [spec.md](spec.md)

Схема в формате [FORMAT.md](../../../../../FORMAT.md). Легенда: ✓ есть · ~ частично · · не начато · ↗ соседний компонент.

## Схема

```
┌──────────────────────────────────────────────────────────────────────────┐
│ ↗ ICPlan · Run Queue                                                     │
└──────────────────────────────────────────────────────────────────────────┘
                  ↓ опрос по ключу агента · стрим и итог ↑
┌─ Agent Runner [G1] ──────────────────────────────────────────────────────┐
│ ┌────────────────────┐  ┌────────────────────┐  ┌──────────────────────┐ │
│ │ Poller ·           │  │ Scheduler ·        │  │ Admission [G1] ·     │ │
│ └────────────────────┘  └────────────────────┘  └──────────────────────┘ │
│                                    ↓                                     │
│ ┌─────────────────────────────────┐  ┌─────────────────────────────────┐ │
│ │ Sandbox claim ·                 │  │ Токены репозиториев ·           │ │
│ └─────────────────────────────────┘  └─────────────────────────────────┘ │
│                                    ↓                                     │
│ ┌─────────────────────────────────┐  ┌─────────────────────────────────┐ │
│ │ Run supervisor ·                │  │ Event relay ·                   │ │
│ └─────────────────────────────────┘  └─────────────────────────────────┘ │
│                                    ↓                                     │
│ ┌──────────────────────────────────────────────────────────────────────┐ │
│ │ Finalizer ·                                                          │ │
│ └──────────────────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────────┘
                                     ↓
┌──────────────────────┐  ┌──────────────────────┐  ┌──────────────────────┐
│ ↗ Sandbox            │  │ ↗ Platform module    │  │ ↗ Observability      │
└──────────────────────┘  └──────────────────────┘  └──────────────────────┘
```

## Блоки

| Блок | Задача | Статус |
|---|---|---|
| Poller | забирает запуск из очереди | ⬜ не начато |
| Scheduler | слоты: глобальный, агента, модели, задачи; sequential / parallel | ⬜ не начато |
| Admission | допуск, бюджет, kill switch | ⬜ не начато |
| Sandbox claim | берёт контейнер из тёплого пула | ⬜ не начато |
| Токены репозиториев | короткоживущие, на запуск | ⬜ не начато |
| Run supervisor | старт Harness, таймаут, отмена | ⬜ не начато |
| Event relay | события Harness → стрим в ICPlan | ⬜ не начато |
| Finalizer | итог в задачу, destroy sandbox | ⬜ не начато |

## Расширения и настройка

```
poll_interval_ms                   → Задержка старта против нагрузки на ICPlan
concurrency                        → Пропускная способность
timeout_s                          → Зависшие запуски не тратят ресурсы
retry                              → Устойчивость против дублей действий
agents                             → Какие агенты исполняются нашей платформой
guardrails.g1.enabled              → Защита от перерасхода до старта
scheduling.mode                    → Вся платформа по одному запуску или по лимитам слотов
scheduling.global_max              → Нагрузка на хост и модели
```

## Плюсы / минусы

| ➕ | ➖ |
|---|---|
| Каждый запуск изолирован и под контролем лимитов и бюджета | Своя логика слотов — нужны тесты на гонки |
| Минимум доработок ICPlan: для него мы — обычный внешний раннер | Возможно голодание долго ждущих запусков — нужна защита |
| Одна точка, где виден жизненный цикл запуска |  |
