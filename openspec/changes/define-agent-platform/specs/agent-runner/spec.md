# Spec Delta

## Purpose

Исполняет задачу, назначенную ICPlan конкретному агенту: поднимает изолированную среду, контролирует лимиты запуска, возвращает результат и убирает среду. Не выбирает агента и не планирует задачи. Обоснование: [R&D](../../../../../docs/rnd/runner-and-scheduling.md).

## ADDED Requirements

### Requirement: Запуск задачи по agent_id
Система SHALL принимать задачу с указанным `agent_id` и запускать именно этого агента по его актуальной (или явно указанной) версии определения из Registry.

#### Scenario: Успешный запуск
- **WHEN** ICPlan отправляет задачу с существующим `agent_id`
- **THEN** система создаёт запуск с уникальным `run_id`, поднимает sandbox и возвращает `run_id` со статусом `starting`

#### Scenario: Неизвестный агент
- **WHEN** задача содержит `agent_id`, которого нет в Registry
- **THEN** система отклоняет задачу с ошибкой `agent_not_found` и не создаёт sandbox

### Requirement: Планирование по слотам
Runner SHALL запускать взятый из очереди запуск, только когда свободны все его слоты: глобальный, агента, модели и задачи; иначе запуск MUST ждать в статусе `queued` в порядке очереди (`fifo` или `priority`).

#### Scenario: Занят слот модели
- **WHEN** у модели `team-default` заняты все слоты, а агент свободен
- **THEN** запуск ждёт в `queued` и стартует при освобождении слота модели

### Requirement: Режим последовательно или параллельно
Режим `scheduling.mode` SHALL задаваться конфигурацией: `sequential` — одновременно не более одного запуска на всю платформу; `parallel` — по лимитам слотов. Агент с `parallel: false` MUST исполняться строго по одному в любом режиме.

#### Scenario: Последовательный режим
- **WHEN** включён `sequential` и в очереди три запуска разных агентов
- **THEN** они выполняются по одному в порядке очереди

### Requirement: Один запуск на задачу
Runner MUST NOT запускать второй запуск по задаче, пока активен первый (`per_issue: 1`).

#### Scenario: Два агента на одну задачу
- **WHEN** по задаче уже идёт запуск, а в очереди появился второй
- **THEN** второй ждёт завершения первого

### Requirement: Общие слоты для нескольких Runner
Несколько экземпляров Runner SHALL использовать общие слоты, чтобы лимиты соблюдались суммарно.

#### Scenario: Два экземпляра
- **WHEN** работают два Runner и `global_max: 2`
- **THEN** одновременно идут не более двух запусков на оба экземпляра

### Requirement: Статусы запуска
Система SHALL вести статус каждого запуска: `queued`, `starting`, `running`, `succeeded`, `failed`, `cancelled`, `limit_exceeded`, и отдавать его по `run_id` и событиями.

#### Scenario: Запрос статуса
- **WHEN** ICPlan запрашивает статус по `run_id`
- **THEN** система возвращает текущий статус, потраченные токены/$ и время

### Requirement: Возврат результата
Система SHALL по завершении запуска вернуть результат агента в формате, объявленном в определении агента.

#### Scenario: Успешное завершение
- **WHEN** агент завершает работу с результатом
- **THEN** статус становится `succeeded`, результат доступен по `run_id`

### Requirement: Отмена запуска
Система SHALL позволять отменить активный запуск.

#### Scenario: Отмена
- **WHEN** ICPlan отменяет запуск
- **THEN** агент останавливается, sandbox уничтожается, статус `cancelled`

### Requirement: Очистка среды
Система MUST уничтожать sandbox после любого терминального статуса.

#### Scenario: Падение агента
- **WHEN** запуск завершается со статусом `failed`
- **THEN** sandbox уничтожен, логи и трейсы сохранены в Observability
