← [spec.md](spec.md) · [схема](architecture.md) · [трассировка](traceability.md) · [правила](../../../../../docs/rules/spec-criteria.md)

## Уровни конфигурации

| Уровень | Что | Где хранится | Область |
|---|---|---|---|
| L0 | Конфиг деплоя | S9 | платформа целиком: адреса, переключатели G1–G4, режим планирования, потолки лимитов |
| L1 | Platform module | S2 | агент: бюджеты, профили, данные guardrails, флаги планирования |
| L2 | Определение агента | S1 (+ YAML импорт) | агент: модель, инструкция, тулы, навыки, MCP, лимиты запуска |
| L3 | Запуск | задача ICPlan / `Run` | версия агента, критерии приёмки, задание |

Правило: значение берётся с самого конкретного уровня (L3 → L0), но не выше потолка L0.

## Параметры модуля

Значения и границы пересматриваются по статистике запусков (3.9) и нагрузочному тесту (4.8); правило — [виды спек, таблица параметров](../../../../../docs/rules/spec-kinds.md#params).

| Параметр | Что задаёт | Уровень | Хранилище | По умолчанию | Почему так по умолчанию | Мин | Макс | На что опираться при выборе |
|---|---|---|---|---|---|---|---|---|
| `events.level` | Детализация событий | L0 | S9 | тулы + итоги | все вызовы LLM — объём ×10 и риск утечки | итоги | всё | «всё» — для отладки на короткий срок |
| `retention_days` | Срок хранения событий | L0 | S9 | 90 | квартал для разборов и статистики | 7 | 365 | объём S3 / БД и требования аудита |
| `cost.source` | Откуда затраты | L0 | S9 | LiteLLM spend log | единственный учёт токенов и $ | LiteLLM spend log | LiteLLM spend log | — |

## Шаблоны маскирования

Применяются при записи события (до хранения) и в M1 / M2. Совпадение заменяется на `***` с типом.

| Тип | Шаблон |
|---|---|
| Ключи моделей | `sk-[A-Za-z0-9_-]{20,}` |
| GitHub | `ghp_[A-Za-z0-9]{36}`, `github_pat_[A-Za-z0-9_]{50,}` |
| GitLab / Gitea | `glpat-[A-Za-z0-9_-]{20}`, токены из Secret по значению |
| AWS / S3 | `AKIA[0-9A-Z]{16}`, `aws_secret_access_key\s*=\s*\S+` |
| Slack / Telegram | `xox[abpr]-[A-Za-z0-9-]+`, `\d{8,10}:[A-Za-z0-9_-]{35}` |
| JWT и Bearer | `eyJ[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+`, `Bearer\s+\S+` |
| Приватные ключи | `-----BEGIN [A-Z ]*PRIVATE KEY-----` … `-----END …-----` |
| Пары ключ-значение | `(password\|passwd\|secret\|token\|api_key)\s*[=:]\s*\S+` |
| Значения Secret платформы | точное совпадение со значениями секретов запуска |

## Хранилища данных

| ID | Хранилище | Что хранит | Владелец | Резервирование / срок |
|---|---|---|---|---|
| S3 | Postgres ICPlan, схема `platform`, таблицы `run_event`, `scheduler_slot` | события запусков, слоты планировщика | Agent Runner / Observability | события — 90 дней; слоты — оперативные |

## Отказы (FMEA)

| Отказ | Обнаружение | Поведение | Восстановление |
|---|---|---|---|
| Нет записи событий | ошибка I2 | буфер в Runner, досылка | — |
| Нет цены модели | пустая цена в LiteLLM | токены учтены, стоимость «неизвестна» | задать цену |
| Переполнение таблицы событий | размер таблицы | очистка по сроку, уровень детализации снижается | изменение `retention_days` |
| Postgres событий (S3) недоступен | ошибки записи `run_event` | события буферизуются у Runner, запуск продолжается; таймлайн временно неполный | досылка по `seq` без дублей |
