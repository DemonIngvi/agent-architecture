# agent-memory — конфигурация, данные, интерфейсы, отказы

← [spec.md](spec.md) · [схема](architecture.md) · [трассировка](traceability.md) · [правила](../../../../../docs/rules/spec-criteria.md)

## Уровни конфигурации

| Уровень | Что | Где хранится | Область |
|---|---|---|---|
| L0 | Конфиг деплоя | S9 | платформа целиком: адреса, переключатели G1–G4, режим планирования, потолки лимитов |
| L1 | Platform module | S2 | агент: бюджеты, профили, данные guardrails, флаги планирования |
| L2 | Определение агента | S1 (+ YAML импорт) | агент: модель, инструкция, тулы, навыки, MCP, лимиты запуска |
| L3 | Запуск | задача ICPlan / `Run` | версия агента, критерии приёмки, задание |

Правило: значение берётся с самого конкретного уровня (L3 → L0), но не выше потолка L0.

## Параметры модуля

Значения и границы пересматриваются по статистике запусков (3.9) и нагрузочному тесту (4.8); правило — [виды спек, таблица параметров](../../../../../docs/rules/spec-kinds.md#params).

| Параметр | Что задаёт | Уровень | Хранилище | По умолчанию | Почему так по умолчанию | Мин | Макс | Тип | На что опираться при выборе |
|---|---|---|---|---|---|---|---|---|---|
| `m3_max_kb` | Предельный размер записи M3 | L1 | S2 | 16 | состояние задачи — кратко: сделано, дальше, блокировки | 2 | 64 |  | 64 КБ ≈ 16 тыс. токенов — 8% окна; больше — в M3 кладут результат вместо состояния |
| `read` | Какие уровни читать | L1 | S2 | M2, M3, M5, M6 | M1 длинная — есть итоги M2; M4 — после MVP | M3 | M0–M6 (M4 после MVP) | список уровней памяти | роль агента: исполнителю — M2, M3; аналитику — ещё M6; минимум, нужный для задачи |
| `write` | Какие уровни агент пишет | L1 | S2 | M3 | M1 и M2 пишутся автоматически; агент пишет только состояние задачи | нет | M3, M4 (после MVP) | список уровней памяти | агенту, накапливающему знания, — M4 после MVP |
| `m2_last_runs` | Сколько прошлых запусков в контекст | L1 | S2 | 3 | прошлый шаг + 2 попытки (лимит шага 3) | 0 | 10 |  | итог запуска ~1–2 тыс. токенов; 10 итогов ≈ 10% окна 200 тыс. |
| `retention` | Сроки хранения; для M1 и M2 — срок чтения: старше срока Memory не отдаёт, строки форка удаляет ICPlan (D25) | L1 | S2 | M1 30 д, M2 180 д, M3 до закрытия задачи, M4 до замены факта (`valid_to`) | M1 — оперативная; M2 — для статистики за полгода; M3 нужна, пока задача открыта; M4 — факт действует, пока его не заменил новый (после MVP) | M1 7 д, M2 30 д | M1 90 д, M2 365 д | список уровней памяти | объём БД и требования к персональным данным в переписке |
| `scope` | Область записи: задача, агент, проект, команда | L1 | S2 | задача | наименьшая видимость по умолчанию | задача | команда | одно из: задача, агент, проект, команда | шире — только для общих знаний; утечка между проектами исключена политикой |
| `learning_ttl_days` | TTL записи обучения без использования (О11) | L1 | S2 | 28 | как у Copilot Memory; к калибровке на пробной пачке | 1 | 365 | число [дней] | доля записей, устаревших к моменту использования (fitness F6); границы — наша оценка |
| `quarantine_n` | Подтверждений нового правила до применения (О12) | L1 | S2 | 3 | оценка, к калибровке (agent-chain.md, ворота G9) | 1 | 10 | число | шум повторов эталонного набора; границы — наша оценка |

## Правила записи по уровням {#write-rules}

Что, когда и кем пишется в каждый уровень и какие проверки проходят **до** записи. Запись, не прошедшая проверку, не выполняется; причина — в событиях запуска.

| Уровень | Когда пишется | Что пишется | Кто запускает | Проверки до записи | При отказе проверки |
|---|---|---|---|---|---|
| M0 | на каждом шаге цикла | сообщения модели, вывод тулов (обрезанный до `max_result_kb`) | Harness | размер окна (сжатие при 80%) | сжатие истории, итог сжатия в M0 |
| M1 | на каждое сообщение в треде, чате, комментарии | текст сообщения, автор, время | ICPlan автоматически | маскирование секретов; уровень M1 разрешён профилем чтения следующих запусков | сообщение пишется с маской; без M1 в профиле — не читается агентом |
| M2 | в конце запуска; при вердикте пользователя | статус, итог (до 2 тыс. символов), затраты, вердикт и заметка | Runner; ICPlan (вердикт) | идемпотентность по `run_id`; маскирование; вердикт — один на запуск | повтор — без дубля; второй вердикт заменяет первый с записью в истории |
| M3 | когда агент продвинулся: шаг сделан, найдена блокировка, перед завершением | `M3Record`: сделано, дальше, блокировки | агент тулом памяти | M3 в профиле записи; область видимости (задача агента); схема `M3Record`; размер ≤ `m3_max_kb`; нет секретов; версия не старше текущей | отказ тулу с причиной; агент исправляет или продолжает без записи |
| M4 | после MVP | факты с источником | агент тулом / администратор импортом | после MVP: дедупликация, источник обязателен, область видимости | — |
| M5 | при изменении агента | инструкция, навыки | администратор (Registry) | валидация определения агента | версия не сохраняется |
| M6 | при изменении документа проекта | документы проекта | пользователи ICPlan | права ICPlan; агенту запись запрещена | агенту — отказ тула |

## Адаптеры обучения {#adapters}

Внутренние контракты ядра ([D28](../../design.md), [R&D](../../../../../docs/rnd/agent-chain.md#e9)): движок каждого вида заменяется без правок ядра (сценарий С4); плагины не импортируют внутренности ядра. Реализация по умолчанию — за каждым адаптером; все адаптеры проверяет контрактный тест (fitness F4: две реализации, 100%).

| Адаптер | Вид | Операции | Реализация по умолчанию | Не берём |
|---|---|---|---|---|
| `MemoryStore` | факты | `write` (с источником, исходом, TTL), `search`, `delete`, `ttl` | Mem0 (Apache-2.0) на pgvector (HNSW); Graphiti — только если понадобятся временные факты | LangMem (завязан на LangGraph) |
| `PlaybookStore` | плейбук | приращения helpful/harmful, детерминированный merge, чтение, удаление | паттерн ACE: код свой по схеме | перезапись плейбука LLM |
| `SkillRegistry` | навыки | регистрация с верификатором (О5), версии, чтение | формат Agent Skills (name, description, тело до 5000 токенов), версии в git | самогенерируемые навыки без верификатора |
| `PromptOptimizer` | оптимизация промптов | пакетный запуск на отложенном наборе, результат — предложение | DSPy + GEPA (MIT), пакетно | непрерывная оптимизация |
| `SnapshotStore` | снимки | создать, список, восстановить (перенос указателя), удалить по сроку | неизменяемые версии + указатель; формат по образцу Letta Agent File | — |

Снимки и указатель описывает [agent-registry R-REG-13, R-REG-14](../agent-registry/spec.md#r-reg-13).

## Отказы (FMEA)

| Отказ | Обнаружение | Поведение | Восстановление |
|---|---|---|---|
| БД недоступна | ошибка Memory API | чтение — пустой контекст с предупреждением; запись — повтор | восстановление БД |
| Конфликт записи M3 | две записи одной области | последняя версия, прежняя в истории | — |
| Очистка M3 не прошла | ошибка `POST /retention/run`, задание CronJob неуспешно | записи остаются; M3 закрытых задач не отдаётся в контекст; уведомление эксплуатации | повтор задания CronJob |
| Профиль памяти не задан | нет профиля у агента | применяются значения по умолчанию из таблицы параметров | администратор задаёт профиль |
