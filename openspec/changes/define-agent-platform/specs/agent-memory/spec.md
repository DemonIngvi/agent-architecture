# Spec Delta

## Purpose

Память агентов по видам знания M0–M6: от контекста одного запуска до организационных документов, с понятным моментом записи и местом хранения каждого уровня. Обоснование: [R&D](../../../../../docs/rnd/memory-model.md).

## ADDED Requirements

<a id="r-mem-01"></a>
### Requirement: Уровни памяти M0–M6
Система SHALL поддерживать уровни: M0 рабочая (контекст запуска), M1 сессионная (переписка в треде), M2 эпизодическая (запуски и их итоги), M3 задачная (состояние работы по задаче), M4 семантическая (факты с поиском по смыслу), M5 процедурная (инструкция и навыки), M6 организационная (документы проекта).

#### Scenario: Завершение запуска
- **WHEN** запуск завершён
- **THEN** M0 уничтожается вместе с sandbox, M1–M6 сохраняются

#### Scenario: Чтение M6
- **WHEN** агенту нужен документ проекта
- **THEN** он читает его тулом `get_document`, запись в M6 агенту недоступна

#### Scenario: Неизвестный уровень
- **WHEN** профиль ссылается на несуществующий уровень
- **THEN** профиль не сохраняется, ошибка валидации

**ID:** `R-MEM-01` · **Реализует задача:** [2.5](../../../../../docs/tasks/2.5-memory-m2-m3.md), [2.4](../../../../../docs/tasks/2.4-mcp-itsaplan-core.md), [2.3](../../../../../docs/tasks/2.3-config-from-icplan.md)

<a id="r-mem-02"></a>
### Requirement: Область видимости как атрибут
Каждая запись M1–M6 SHALL иметь область видимости (задача, агент, проект, команда); доступ агента MUST определяться профилем памяти и областью записи.

#### Scenario: Чужая область
- **WHEN** агент без доступа к области «команда» запрашивает такую запись
- **THEN** запрос отклоняется

#### Scenario: Своя область
- **WHEN** агент читает M3 своей задачи
- **THEN** запись возвращается

#### Scenario: Запись в чужую область
- **WHEN** агент пытается записать в область команды без права
- **THEN** запись отклоняется и попадает в аудит

**ID:** `R-MEM-02` · **Реализует задача:** [2.5](../../../../../docs/tasks/2.5-memory-m2-m3.md)

<a id="r-mem-03"></a>
### Requirement: Автоматическая запись M1 и M2
Платформа SHALL сама записывать M1 (каждое сообщение треда) и M2 (старт, итог, ошибка, токены запуска), без участия агента.

#### Scenario: Итог запуска
- **WHEN** запуск завершился
- **THEN** в M2 есть запись с итогом, статусом и токенами

#### Scenario: Ошибочный запуск
- **WHEN** запуск завершился ошибкой
- **THEN** в M2 есть запись с ошибкой и причиной

#### Scenario: Хранилище недоступно
- **WHEN** БД ICPlan недоступна при записи M2
- **THEN** Runner повторяет отправку итога (`/agent-runs/{id}/result`), ICPlan записывает M2 без дублей по `run_id`

**ID:** `R-MEM-03` · **Реализует задача:** [2.1](../../../../../docs/tasks/2.1-runner-external.md)

<a id="r-mem-04"></a>
### Requirement: Состояние задачи M3
Агент SHALL записывать состояние работы по задаче (сделано, дальше, блокеры) через тул; перед каждым запуском по задаче платформа SHALL добавлять M3 в контекст. M3 шага SHALL содержать передачу следующему: ссылки на артефакты, вопросы, предложенные критерии (D20).

#### Scenario: Следующий этап
- **WHEN** агент B берёт задачу после агента A
- **THEN** контекст B содержит M3, записанное A

#### Scenario: M3 ещё нет
- **WHEN** первый агент берёт задачу
- **THEN** контекст без M3, агент работает с нуля

#### Scenario: Конфликт записи
- **WHEN** два запуска пытаются записать M3 одновременно
- **THEN** сохраняется последняя версия, предыдущая остаётся в истории

**ID:** `R-MEM-04` · **Реализует задача:** [2.5](../../../../../docs/tasks/2.5-memory-m2-m3.md)

<a id="r-mem-05"></a>
### Requirement: История запусков в контексте
Перед запуском по задаче платформа SHALL добавлять в контекст краткие итоги последних N запусков этой задачи (M2).

#### Scenario: Повторный запуск
- **WHEN** агент повторно запускается по задаче
- **THEN** видит итоги прошлых запусков

#### Scenario: Запусков больше N
- **WHEN** у задачи 10 запусков, N = 3
- **THEN** в контекст попадают итоги трёх последних

#### Scenario: Нет истории
- **WHEN** задача запускается впервые
- **THEN** раздел истории в контексте пуст

**ID:** `R-MEM-05` · **Реализует задача:** [2.5](../../../../../docs/tasks/2.5-memory-m2-m3.md)

<a id="r-mem-06"></a>
### Requirement: Семантическая память M4 — после MVP
M4 SHALL вводиться вместе с RAG: запись фактов агентом через тул, поиск по смыслу, хранилище — векторное расширение основной БД.

#### Scenario: Поиск факта
- **WHEN** M4 включена и агент ищет факт по смыслу
- **THEN** получает записи из разрешённых ему областей

#### Scenario: M4 выключена
- **WHEN** профиль не включает M4
- **THEN** тул поиска по смыслу агенту недоступен

#### Scenario: Нет результатов
- **WHEN** поиск не нашёл похожих фактов
- **THEN** агент получает пустой ответ без ошибки

#### Scenario: Противоречащий факт
- **WHEN** агент записывает факт, противоречащий факту в той же области
- **THEN** старый факт помечается устаревшим со ссылкой на новый, поиск выдаёт новый

#### Scenario: Срок действия
- **WHEN** у факта истёк срок «действует по»
- **THEN** поиск по умолчанию его не выдаёт

#### Scenario: Секрет в факте
- **WHEN** текст факта содержит секрет
- **THEN** значение маскируется до записи

**ID:** `R-MEM-06` · **Реализует задача:** [бэклог](../../../../../docs/BACKLOG.md)

<a id="r-mem-07"></a>
### Requirement: Управление памятью
Администратор SHALL иметь возможность просматривать, редактировать и удалять записи M1–M4.

#### Scenario: Удаление ошибочного факта
- **WHEN** администратор удаляет запись M3 или M4
- **THEN** последующие запуски её не получают

#### Scenario: Нет прав
- **WHEN** участник без права пытается удалить запись
- **THEN** отказ в доступе

#### Scenario: Правка записи
- **WHEN** администратор исправляет запись M3
- **THEN** следующий запуск получает исправленную версию

**ID:** `R-MEM-07` · **Реализует задача:** [2.5](../../../../../docs/tasks/2.5-memory-m2-m3.md)

<a id="r-mem-08"></a>
### Requirement: Срок хранения
Записи M1–M4 MUST становиться недоступными для чтения по истечении срока хранения из профиля памяти. M3 и M4 Memory API SHALL удалять сам; M1 и M2 лежат в таблицах форка: Memory не отдаёт записи старше срока, строки удаляет ICPlan по своему сроку (R-ICP-19, D25).

#### Scenario: Истёк срок
- **WHEN** срок хранения записи истёк
- **THEN** запись недоступна для чтения

#### Scenario: M1 и M2 старше срока
- **WHEN** сообщение `agent_chat_message` старше срока M1 и итог запуска в `agent_run` старше срока M2 профиля агента
- **THEN** Memory не отдаёт ни сообщение, ни итог в контекст; строки обеих таблиц остаются на месте

#### Scenario: Срок не истёк
- **WHEN** запись младше срока
- **THEN** запись доступна

#### Scenario: M3 закрытой задачи
- **WHEN** задача закрыта, после закрытия выполнен очередной `POST /retention/run` (CronJob)
- **THEN** M3 задачи удалена, M2 остаётся; до этого запуска M3 закрытой задачи не отдаётся в контекст

#### Scenario: Удаление в журнале
- **WHEN** `POST /retention/run` удалил записи M3
- **THEN** ответ `{deleted: {m3}}` и запись в журнале Memory API: сколько записей и по какому сроку удалено

#### Scenario: Сбой очистки
- **WHEN** `POST /retention/run` завершился ошибкой (БД недоступна)
- **THEN** записи остаются, задание CronJob помечено неуспешным и повторяется; неуспешное задание поднимает уведомление эксплуатации

**ID:** `R-MEM-08` · **Реализует задача:** [2.5](../../../../../docs/tasks/2.5-memory-m2-m3.md)

<a id="r-mem-15"></a>
### Requirement: Проверки записи в память
Запись в каждый уровень памяти SHALL идти по правилам таблицы «Правила записи по уровням» (`interfaces.md`): в своё время, своим инициатором и после проверок — профиль записи, область видимости, схема и размер, отсутствие секретов, идемпотентность. Запись, не прошедшая проверку, MUST NOT выполняться; причина MUST возвращаться инициатору и попадать в события запуска.

#### Scenario: Секрет в M3
- **WHEN** агент пишет в M3 запись с токеном доступа
- **THEN** запись отклонена, тулу возвращена причина «секрет в записи», событие

#### Scenario: Уровень не в профиле
- **WHEN** агент с профилем записи «нет» вызывает запись M3
- **THEN** запись отклонена с причиной «уровень не разрешён профилем»

#### Scenario: Повтор итога запуска
- **WHEN** Runner повторно отправил итог запуска с тем же `run_id`
- **THEN** в M2 одна запись, дубля нет

#### Scenario: Слишком большая запись
- **WHEN** запись M3 больше `m3_max_kb`
- **THEN** запись отклонена с границей в причине

**ID:** `R-MEM-15` · **Реализует задача:** [2.5](../../../../../docs/tasks/2.5-memory-m2-m3.md)

<a id="r-mem-16"></a>
### Requirement: Предложения агента по навыкам и плейбуку
Агент MAY предлагать изменение своих навыков и плейбука (M5) как предложение с обоснованием и ссылкой на запуски; предложение MUST NOT менять M5 само. Применять предложение SHALL администратор новой версией настроек агента после прогона регрессионного набора эталонных задач и утверждения человеком; версию SHALL быть возможно откатить. Правило «M5 меняет только администратор» сохраняется в части применения. [R&D](../../../../../docs/rnd/agent-chain.md#e9), D27.

#### Scenario: Агент предлагает изменение
- **WHEN** агент по итогам запусков записывает предложение «добавить в навык проверку миграций»
- **THEN** предложение сохранено со ссылкой на запуски, определение агента не изменилось, администратор видит предложение в очереди

#### Scenario: Применение после регрессии
- **WHEN** администратор принимает предложение, регрессионный набор пройден без ухудшения и человек утвердил
- **THEN** создаётся новая версия настроек (4.4), следующий запуск использует её

#### Scenario: Регрессия ухудшилась
- **WHEN** на регрессионном наборе результат хуже текущей версии
- **THEN** версия не создаётся, предложение возвращается с результатом набора

#### Scenario: Откат
- **WHEN** администратор откатывает версию, созданную из предложения
- **THEN** действует предыдущая версия настроек, предложение помечено «откатено»

**ID:** `R-MEM-16` · **Реализует задача:** [4.4](../../../../../docs/tasks/4.4-platform-module.md)

<a id="r-mem-17"></a>
### Requirement: Записи обучения — источник, исход, TTL, счётчики
Модуль SHALL принимать запись обучения (факт, правило плейбука, навык) только с источником (запуск или задача), исходом, версией и TTL (`learning_ttl_days`), вести счётчики helpful/harmful и дедупликацию, помечать тип записи «справка, не правило» и применять новое правило только после `quarantine_n` подтверждений (ограничения О1, О3, О9, О11, О12 [каталога](../guardrails/spec.md#r-grd-23)). Запись без источника MUST отклоняться; запись старше TTL без использования MUST NOT отдаваться агенту без проверки актуальности.

#### Scenario: Запись без источника
- **WHEN** в память пытаются записать правило без ссылки на запуск или задачу
- **THEN** запись отклонена, в журнале причина «нет источника»

#### Scenario: Справка не становится правилом
- **WHEN** запись помечена типом «справка»
- **THEN** в контекст агента она попадает в разделе справки, а не в разделе правил

#### Scenario: Карантин нового правила
- **WHEN** новое правило подтверждено менее `quarantine_n` раз
- **THEN** правило не применяется к запускам; после `quarantine_n`-го подтверждения становится доступным

#### Scenario: Просроченная запись
- **WHEN** запись не использовалась дольше `learning_ttl_days`
- **THEN** перед использованием её актуальность проверяется; не подтверждена — запись помечается устаревшей и не отдаётся

**ID:** `R-MEM-17` · **Реализует задача:** [4.4](../../../../../docs/tasks/4.4-platform-module.md)

<a id="r-mem-18"></a>
### Requirement: Режимы обучения по видам, просмотр, правка и удаление памяти
Модуль SHALL выполнять для каждого вида обучения (`facts`, `playbook`, `skills`, `prompt_opt`) эффективный режим `off`, `suggest` или `apply_gated` (по умолчанию `off` для всех видов), который вычисляет [политика уровней control-plane](../control-plane/spec.md#r-cp-15). При режиме `off` модуль MUST NOT создавать новые записи этого вида и MUST NOT удалять накопленные. Пользователь с правом на проект SHALL просматривать, править и удалять записи; удаление действует со следующего запуска. Контракты хранилищ — адаптеры `MemoryStore`, `PlaybookStore`, `SkillRegistry`, `PromptOptimizer` ([interfaces.md](interfaces.md#adapters)).

#### Scenario: Выключение
- **WHEN** администратор переводит вид «факты» из `suggest` в `off`
- **THEN** новые записи не создаются в течение 1 минуты, накопленные записи сохранены (потерь 0)

#### Scenario: Удаление записи
- **WHEN** пользователь удаляет запись памяти в экране 4.4
- **THEN** со следующего запуска запись не отдаётся агенту, удаление видно в журнале изменений

#### Scenario: Правка записи
- **WHEN** пользователь правит текст записи
- **THEN** сохраняется новая редакция с автором и временем, прежняя остаётся в журнале

#### Scenario: Режим по умолчанию
- **WHEN** у агента не задан режим вида «плейбук»
- **THEN** действует `off`: предложений и записей плейбука нет

**ID:** `R-MEM-18` · **Реализует задача:** [4.4](../../../../../docs/tasks/4.4-platform-module.md)

<a id="r-mem-09"></a>
### Requirement: Конфигурация модуля
Модуль SHALL брать свои параметры (8, таблица «Параметры модуля» в `interfaces.md`) с уровней L1 (S2): значение — с самого конкретного уровня; значение вне границ «Мин»–«Макс» таблицы MUST отклоняться с ошибкой, называющей параметр и границы.

#### Scenario: Значение по умолчанию
- **WHEN** `m3_max_kb` (предельный размер записи M3) не задан в конфигурации
- **THEN** применяется значение по умолчанию: 16

#### Scenario: Выше максимума
- **WHEN** `m3_max_kb` задан больше 64
- **THEN** значение отклонено, ошибка называет `m3_max_kb` и границы 2–64

#### Scenario: Ниже минимума
- **WHEN** `m2_last_runs` задан меньше 0
- **THEN** значение отклонено, ошибка называет `m2_last_runs` и границы 0–10

**ID:** `R-MEM-09` · **Реализует задача:** [2.5](../../../../../docs/tasks/2.5-memory-m2-m3.md), [2.8](../../../../../docs/tasks/2.8-config-storage-interfaces-fmea.md)

<a id="r-mem-10"></a>
### Requirement: Хранилища данных
Модуль SHALL хранить свои данные только в S4 (Postgres ICPlan, схема `memory`) (`interfaces.md`); данные S1 — доступ только через API или конфигурацию владельца. Секреты MUST NOT храниться в БД и git.

#### Scenario: Запись в своё хранилище
- **WHEN** модуль сохраняет состояние задач (M3); факты (M4)
- **THEN** запись попадает в S4 (Postgres ICPlan, схема `memory`)

#### Scenario: S4 недоступно
- **WHEN** S4 (Postgres ICPlan, схема `memory`) не отвечает
- **THEN** чтение — пустой контекст с предупреждением; запись — повтор

#### Scenario: Доступ вне своих хранилищ
- **WHEN** код agent-memory обращается к таблицам вне S4
- **THEN** доступа нет: роль БД agent-memory ограничена S4

**ID:** `R-MEM-10` · **Реализует задача:** [2.5](../../../../../docs/tasks/2.5-memory-m2-m3.md)

<a id="r-mem-11"></a>
### Requirement: Интерфейсы обмена
Интерфейсы модуля (I11, I2, I22) SHALL соблюдать протокол, формат, аутентификацию, таймаут и политику повтора из `interfaces.md`; неидемпотентные вызовы MUST NOT повторяться автоматически.

#### Scenario: Таймаут I11
- **WHEN** Harness → Memory API (I11) не ответил за 2 с
- **THEN** вызов прерывается; повтор: 2 раза

#### Scenario: Аутентификация I2
- **WHEN** собеседник по I2 отклонил учётные данные (bearer API-ключ агента)
- **THEN** вызов не повторяется, событие с причиной

#### Scenario: Повтор I2 без дублей
- **WHEN** вызов I2 повторён после сбоя
- **THEN** дубля нет: да, по (run_id, seq)

**ID:** `R-MEM-11` · **Реализует задача:** [2.5](../../../../../docs/tasks/2.5-memory-m2-m3.md)

<a id="r-mem-12"></a>
### Requirement: Поведение при отказах зависимостей
Модуль SHALL вести себя при отказах зависимостей по таблице FMEA (`interfaces.md`): отказ обнаруживается, поведение предсказуемо и безопасно (fail-closed для проверок безопасности), восстановление не теряет данные.

#### Scenario: БД недоступна
- **WHEN** бд недоступна
- **THEN** чтение — пустой контекст с предупреждением; запись — повтор

#### Scenario: Конфликт записи M3
- **WHEN** конфликт записи m3
- **THEN** последняя версия, прежняя в истории

#### Scenario: Очистка M3 не прошла
- **WHEN** очистка M3 не прошла: ошибка `POST /retention/run`, задание CronJob неуспешно
- **THEN** записи остаются; M3 закрытых задач не отдаётся в контекст; уведомление эксплуатации, задание CronJob повторяется

#### Scenario: Профиль памяти не задан
- **WHEN** профиль памяти агента не задан
- **THEN** применяются значения по умолчанию из таблицы параметров (`read`, `write`, `scope`)

**ID:** `R-MEM-12` · **Реализует задача:** [2.5](../../../../../docs/tasks/2.5-memory-m2-m3.md)

<a id="r-mem-13"></a>
### Requirement: Нагрузка и производительность
Модуль SHALL выдерживать профиль нагрузки (`interfaces.md`, «Нагрузка и развёртывание»): ~1 RPS чтения и записи; запись M3 до 16 КБ (`m3_max_kb`); p95 < 200 мс. Превышение профиля MUST приводить к очереди или отказу с причиной, а не к деградации всей платформы.

#### Scenario: Пик профиля
- **WHEN** нагрузка достигает профиля: ~1 RPS чтения и записи
- **THEN** выполняется: запись M3 до 16 КБ (`m3_max_kb`); p95 < 200 мс

#### Scenario: Превышение профиля
- **WHEN** нагрузка вдвое выше профиля (~1 RPS чтения и записи)
- **THEN** лишние вызовы ждут в очереди или получают отказ с причиной, активные запуски не страдают

#### Scenario: Замер
- **WHEN** нагрузочный тест 4.8 на профиле «~1 RPS чтения и записи»
- **THEN** фактические значения (запись M3 до 16 КБ (`m3_max_kb`); p95 < 200 мс) записаны и сравнены с профилем

**ID:** `R-MEM-13` · **Реализует задача:** [4.8](../../../../../docs/tasks/4.8-load-test.md)

### Requirement: Развёртывание
Модуль SHALL разворачиваться так: Memory API — Deployment в `itsaplan-agents`, 1–2 реплики, Service ClusterIP; данные — Postgres через PgBouncer. Ресурсы MUST задаваться requests / limits, версии образов — закреплены; публичный доступ — только через ingress, если он указан.

#### Scenario: Установка
- **WHEN** выполняется `helm install`: Memory API — Deployment в `itsaplan-agents`, 1–2 реплики, Service ClusterIP; данные — Postgres через PgBouncer
- **THEN** объекты созданы в своём namespace с заданными requests / limits, проверки готовности зелёные

#### Scenario: Обновление
- **WHEN** выходит новая версия образа `memory-api` (1–2 реплики)
- **THEN** `memory-api` заменяется по одной реплике; работа, начатая на старой версии, доделывается

#### Scenario: Нехватка ресурсов
- **WHEN** узлу не хватает ресурсов для пода `memory-api`
- **THEN** под `memory-api` ждёт размещения, событие эксплуатации
