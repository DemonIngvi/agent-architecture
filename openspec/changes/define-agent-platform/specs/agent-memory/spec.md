# Spec Delta

## Purpose

Память агентов по видам знания M0–M6: от контекста одного запуска до организационных документов, с понятным моментом записи и местом хранения каждого уровня. Обоснование: [R&D](../../../../../docs/rnd/memory-model.md).

## ADDED Requirements

### Requirement: Уровни памяти M0–M6
Система SHALL поддерживать уровни: M0 рабочая (контекст запуска), M1 сессионная (переписка в треде), M2 эпизодическая (запуски и их итоги), M3 задачная (состояние работы по задаче), M4 семантическая (факты с поиском по смыслу), M5 процедурная (инструкция и навыки), M6 организационная (документы проекта).

#### Scenario: Завершение запуска
- **WHEN** запуск завершён
- **THEN** M0 уничтожается вместе с sandbox, M1–M6 сохраняются

#### Scenario: Чтение M6
- **WHEN** агенту нужен документ проекта
- **THEN** он читает его тулом `get_document`, запись в M6 агенту недоступна

#### Scenario: Неизвестный уровень
- **WHEN** профиль ссылается на несуществующий уровень
- **THEN** профиль не сохраняется, ошибка валидации

<a id="r-mem-01"></a>**ID:** `R-MEM-01` · **Реализует задача:** [2.5](../../../../../docs/tasks/2.5-memory-m2-m3.md)

### Requirement: Область видимости как атрибут
Каждая запись M1–M6 SHALL иметь область видимости (агент, проект, команда); доступ агента MUST определяться профилем памяти и областью записи.

#### Scenario: Чужая область
- **WHEN** агент без доступа к области «команда» запрашивает такую запись
- **THEN** запрос отклоняется

#### Scenario: Своя область
- **WHEN** агент читает M3 своей задачи
- **THEN** запись возвращается

#### Scenario: Запись в чужую область
- **WHEN** агент пытается записать в область команды без права
- **THEN** запись отклоняется и попадает в аудит

<a id="r-mem-02"></a>**ID:** `R-MEM-02` · **Реализует задача:** [2.5](../../../../../docs/tasks/2.5-memory-m2-m3.md)

### Requirement: Автоматическая запись M1 и M2
Платформа SHALL сама записывать M1 (каждое сообщение треда) и M2 (старт, итог, ошибка, токены запуска), без участия агента.

#### Scenario: Итог запуска
- **WHEN** запуск завершился
- **THEN** в M2 есть запись с итогом, статусом и токенами

#### Scenario: Ошибочный запуск
- **WHEN** запуск завершился ошибкой
- **THEN** в M2 есть запись с ошибкой и причиной

#### Scenario: Хранилище недоступно
- **WHEN** БД недоступна при записи M2
- **THEN** Runner повторяет запись; итог не теряется

<a id="r-mem-03"></a>**ID:** `R-MEM-03` · **Реализует задача:** [2.1](../../../../../docs/tasks/2.1-runner-external.md)

### Requirement: Состояние задачи M3
Агент SHALL записывать состояние работы по задаче (сделано, дальше, блокеры) через тул; перед каждым запуском по задаче платформа SHALL добавлять M3 в контекст.

#### Scenario: Следующий этап
- **WHEN** агент B берёт задачу после агента A
- **THEN** контекст B содержит M3, записанное A

#### Scenario: M3 ещё нет
- **WHEN** первый агент берёт задачу
- **THEN** контекст без M3, агент работает с нуля

#### Scenario: Конфликт записи
- **WHEN** два запуска пытаются записать M3 одновременно
- **THEN** сохраняется последняя версия, предыдущая остаётся в истории

<a id="r-mem-04"></a>**ID:** `R-MEM-04` · **Реализует задача:** [2.5](../../../../../docs/tasks/2.5-memory-m2-m3.md)

### Requirement: История запусков в контексте
Перед запуском по задаче платформа SHALL добавлять в контекст краткие итоги последних N запусков этой задачи (M2).

#### Scenario: Повторный запуск
- **WHEN** агент повторно запускается по задаче
- **THEN** видит итоги прошлых запусков

#### Scenario: Запусков больше N
- **WHEN** у задачи 10 запусков, N = 3
- **THEN** в контекст попадают итоги трёх последних

#### Scenario: Нет истории
- **WHEN** задача запускается впервые
- **THEN** раздел истории в контексте пуст

<a id="r-mem-05"></a>**ID:** `R-MEM-05` · **Реализует задача:** [2.5](../../../../../docs/tasks/2.5-memory-m2-m3.md)

### Requirement: Семантическая память M4 — после MVP
M4 SHALL вводиться вместе с RAG: запись фактов агентом через тул, поиск по смыслу, хранилище — векторное расширение основной БД.

#### Scenario: Поиск факта
- **WHEN** M4 включена и агент ищет факт по смыслу
- **THEN** получает записи из разрешённых ему областей

#### Scenario: M4 выключена
- **WHEN** профиль не включает M4
- **THEN** тул поиска по смыслу агенту недоступен

#### Scenario: Нет результатов
- **WHEN** поиск не нашёл похожих фактов
- **THEN** агент получает пустой ответ без ошибки

<a id="r-mem-06"></a>**ID:** `R-MEM-06` · **Реализует задача:** [бэклог](../../../../../docs/BACKLOG.md)

### Requirement: Управление памятью
Администратор SHALL иметь возможность просматривать, редактировать и удалять записи M1–M4.

#### Scenario: Удаление ошибочного факта
- **WHEN** администратор удаляет запись M3 или M4
- **THEN** последующие запуски её не получают

#### Scenario: Нет прав
- **WHEN** участник без права пытается удалить запись
- **THEN** отказ в доступе

#### Scenario: Правка записи
- **WHEN** администратор исправляет запись M3
- **THEN** следующий запуск получает исправленную версию

<a id="r-mem-07"></a>**ID:** `R-MEM-07` · **Реализует задача:** [2.5](../../../../../docs/tasks/2.5-memory-m2-m3.md)

### Requirement: Срок хранения
Записи M1–M4 MUST удаляться по истечении срока хранения из профиля памяти.

#### Scenario: Истёк срок
- **WHEN** срок хранения записи истёк
- **THEN** запись недоступна для чтения

#### Scenario: Срок не истёк
- **WHEN** запись младше срока
- **THEN** запись доступна

#### Scenario: M3 закрытой задачи
- **WHEN** задача закрыта
- **THEN** M3 удаляется по профилю, M2 остаётся

<a id="r-mem-08"></a>**ID:** `R-MEM-08` · **Реализует задача:** [2.5](../../../../../docs/tasks/2.5-memory-m2-m3.md)

### Requirement: Проверки записи в память
Запись в каждый уровень памяти SHALL идти по правилам таблицы «Правила записи по уровням» (`interfaces.md`): в своё время, своим инициатором и после проверок — профиль записи, область видимости, схема и размер, отсутствие секретов, идемпотентность. Запись, не прошедшая проверку, MUST NOT выполняться; причина MUST возвращаться инициатору и попадать в события запуска.

#### Scenario: Секрет в M3
- **WHEN** агент пишет в M3 запись с токеном доступа
- **THEN** запись отклонена, тулу возвращена причина «секрет в записи», событие

#### Scenario: Уровень не в профиле
- **WHEN** агент с профилем записи «нет» вызывает запись M3
- **THEN** запись отклонена с причиной «уровень не разрешён профилем»

#### Scenario: Повтор итога запуска
- **WHEN** Runner повторно отправил итог запуска с тем же `run_id`
- **THEN** в M2 одна запись, дубля нет

#### Scenario: Слишком большая запись
- **WHEN** запись M3 больше `m3_max_kb`
- **THEN** запись отклонена с границей в причине

<a id="r-mem-15"></a>**ID:** `R-MEM-15` · **Реализует задача:** [2.5](../../../../../docs/tasks/2.5-memory-m2-m3.md)

### Requirement: Конфигурация модуля
Модуль SHALL брать свои параметры (6, таблица «Параметры модуля» в `interfaces.md`) с уровней L1 (S2): значение — с самого конкретного уровня; значение вне границ «Мин»–«Макс» таблицы MUST отклоняться с ошибкой, называющей параметр и границы.

#### Scenario: Значение по умолчанию
- **WHEN** `m3_max_kb` (предельный размер записи M3) не задан в конфигурации
- **THEN** применяется значение по умолчанию: 16

#### Scenario: Выше максимума
- **WHEN** `m3_max_kb` задан больше 64
- **THEN** значение отклонено, ошибка называет `m3_max_kb` и границы 2–64

#### Scenario: Ниже минимума
- **WHEN** `m2_last_runs` задан меньше 0
- **THEN** значение отклонено, ошибка называет `m2_last_runs` и границы 0–10

<a id="r-mem-09"></a>**ID:** `R-MEM-09` · **Реализует задача:** [2.5](../../../../../docs/tasks/2.5-memory-m2-m3.md), [2.8](../../../../../docs/tasks/2.8-config-storage-interfaces-fmea.md)

### Requirement: Хранилища данных
Модуль SHALL хранить и читать свои данные только в S1 (PostgreSQL 17 (CloudNativePG), БД `itsaplan`), S4 (Postgres ICPlan, схема `platform`) (`interfaces.md`); к данным других модулей — только через их API. Секреты MUST NOT храниться в БД и git.

#### Scenario: Запись в своё хранилище
- **WHEN** модуль сохраняет состояние задач (M3); факты (M4)
- **THEN** запись попадает в S4 (Postgres ICPlan, схема `platform`)

#### Scenario: S4 недоступно
- **WHEN** S4 (Postgres ICPlan, схема `platform`) не отвечает
- **THEN** операция завершается ошибкой без частичной записи, поведение — по FMEA, событие оператору

#### Scenario: Прямой доступ к чужим данным
- **WHEN** код модуля обращается к таблицам другого модуля
- **THEN** доступа нет: роль БД ограничена своими хранилищами

<a id="r-mem-10"></a>**ID:** `R-MEM-10` · **Реализует задача:** [2.5](../../../../../docs/tasks/2.5-memory-m2-m3.md)

### Requirement: Интерфейсы обмена
Интерфейсы модуля (I11, I2, I22) SHALL соблюдать протокол, формат, аутентификацию, таймаут и политику повтора из `interfaces.md`; неидемпотентные вызовы MUST NOT повторяться автоматически.

#### Scenario: Таймаут I11
- **WHEN** Harness → Memory API (I11) не ответил за 2 с
- **THEN** вызов прерывается; повтор: 2 раза

#### Scenario: Аутентификация I2
- **WHEN** собеседник по I2 отклонил учётные данные (bearer API-ключ агента)
- **THEN** вызов не повторяется, событие с причиной

#### Scenario: Повтор I2 без дублей
- **WHEN** вызов I2 повторён после сбоя
- **THEN** дубля нет: да, по (run_id, seq)

<a id="r-mem-11"></a>**ID:** `R-MEM-11` · **Реализует задача:** [2.5](../../../../../docs/tasks/2.5-memory-m2-m3.md)

### Requirement: Поведение при отказах зависимостей
Модуль SHALL вести себя при отказах зависимостей по таблице FMEA (`interfaces.md`): отказ обнаруживается, поведение предсказуемо и безопасно (fail-closed для проверок безопасности), восстановление не теряет данные.

#### Scenario: БД недоступна
- **WHEN** бд недоступна
- **THEN** чтение — пустой контекст с предупреждением; запись — повтор

#### Scenario: Конфликт записи M3
- **WHEN** конфликт записи m3
- **THEN** последняя версия, прежняя в истории

#### Scenario: Профиль памяти не задан
- **WHEN** профиль памяти не задан
- **THEN** используется профиль по умолчанию из L0

<a id="r-mem-12"></a>**ID:** `R-MEM-12` · **Реализует задача:** [2.5](../../../../../docs/tasks/2.5-memory-m2-m3.md)

### Requirement: Нагрузка и производительность
Модуль SHALL выдерживать нагрузку профиля (`interfaces.md`, раздел «Нагрузка и развёртывание»): ~1 RPS чтения и записи; M3 до 10 КБ на задачу; p95 < 200 мс. Превышение профиля MUST приводить к очереди или отказу с причиной, а не к деградации всей платформы.

#### Scenario: Пиковая нагрузка профиля
- **WHEN** нагрузка достигает пика профиля
- **THEN** целевые показатели времени ответа и пропускной способности выполняются

#### Scenario: Превышение профиля
- **WHEN** нагрузка превышает профиль
- **THEN** лишние запросы ждут в очереди или получают отказ с причиной, остальные обслуживаются

#### Scenario: Замер
- **WHEN** выполняется нагрузочный тест
- **THEN** фактические показатели записаны и сравнены с профилем

<a id="r-mem-13"></a>**ID:** `R-MEM-13` · **Реализует задача:** [4.8](../../../../../docs/tasks/4.8-load-test.md)

### Requirement: Развёртывание
Модуль SHALL разворачиваться так: Memory API — Deployment в `itsaplan-agents`, 1–2 реплики, Service ClusterIP; данные — Postgres через PgBouncer. Ресурсы MUST задаваться requests / limits, публичный доступ — только через ingress, если указан.

#### Scenario: Установка
- **WHEN** модуль разворачивается в кластере
- **THEN** объекты созданы в указанном namespace с заданными ресурсами

#### Scenario: Нехватка ресурсов
- **WHEN** узлу не хватает ресурсов для пода модуля
- **THEN** под ждёт размещения, событие для оператора

#### Scenario: Обновление
- **WHEN** выходит новая версия модуля
- **THEN** обновление проходит без потери данных и по правилам Helm-релиза
