# guardrails — конфигурация, данные, интерфейсы, отказы

← [spec.md](spec.md) · [схема](architecture.md) · [трассировка](traceability.md) · [правила](../../../../../docs/rules/spec-criteria.md)

## Уровни конфигурации

| Уровень | Что | Где хранится | Область |
|---|---|---|---|
| L0 | Конфиг деплоя | S9 | платформа целиком: адреса, переключатели G1–G4, режим планирования, потолки лимитов |
| L1 | Platform module | S2 | агент: бюджеты, профили, данные guardrails, флаги планирования |
| L2 | Определение агента | S1 (+ YAML импорт) | агент: модель, инструкция, тулы, навыки, MCP, лимиты запуска |
| L3 | Запуск | задача ICPlan / `Run` | версия агента, критерии приёмки, задание |

Правило: значение берётся с самого конкретного уровня (L3 → L0), но не выше потолка L0.

## Параметры модуля

Значения и границы пересматриваются по статистике запусков (3.9) и нагрузочному тесту (4.8); правило — [виды спек, таблица параметров](../../../../../docs/rules/spec-kinds.md#params).

| Параметр | Что задаёт | Уровень | Хранилище | По умолчанию | Почему так по умолчанию | Мин | Макс | На что опираться при выборе |
|---|---|---|---|---|---|---|---|---|
| `opa.cache_ttl_s` | Кэш решения OPA для одинакового входа в запуске | L0 | S9 | 60 | повторы одного вызова в запуске не ждут OPA | 0 | 300 | дольше — изменённые правила позже действуют на идущие запуски |
| `engine` | Движок решений | L0 | S9 | opa | решение D6 | opa | opa | единственный вариант MVP |
| `g1.enabled … g4.enabled` | Включение точек | L0 | S9 | g1–g3 вкл, g4 выкл | G4 (модерация LLM) добавляет задержку и стоимость | все выкл (dev) | все вкл | prod: G1–G3 обязательно; G4 — при внешних пользователях и персональных данных |
| `on_engine_error` | Поведение при недоступности OPA | L0 | S9 | deny | fail-closed | deny | allow | allow — только dev |
| `tools_allow / approval` | Данные правил агента | L1 | S2 | из агента | единый источник — настройки агента | пусто | тулы агента | наименьшие права |
| `autonomy_level` | Уровень автономии R0–R5 (политика подтверждений) | L1 | S2 | R2 | подтверждение опасных действий — баланс скорости и контроля | R0 | R5 | новому агенту R1–R2; повышать по доле возвратов и инцидентов (3.9) |
| `Rego-правила` | Логика проверок | L0 | S8 | allowlist + approval | базовые правила D6 | — | — | правила в git с тестами `opa test` |
| `loop.repeat_calls` | Повторов одинакового вызова до стопа | L0 | S9 | 3 | 2 повтора бывают законны (после ошибки), третий — цикл | 2 | 10 | доля ложных остановок в статистике |
| `loop.no_progress_steps` | Шагов без прогресса до стопа | L0 | S9 | 8 | ~25% от `max_steps` 30 | 3 | `limits.max_steps` | p95 шагов на поиск решения |
| `limits.idle_s` | Простой без событий | L1 | S2 | 300 | равно аренде запуска ICPlan | 60 | `timeout_s` | самый долгий нормальный вызов тула или модели |
| `budget.run / agent_day / project_month` | Иерархия бюджетов | L1 | S2 | 1 $ / 5 $ / задаётся | запуск ≈ 200 тыс. токенов ≈ 0,6–1 $ | 0,1 $ / 0 $ / 0 $ | run ≤ agent_day ≤ project_month / 20 | фактические затраты (3.9) и бюджет команды |
| `anomaly.step_x_median` | Порог скачка расхода шага | L0 | S9 | 5 | шаг в 5 раз дороже медианы — огромный контекст или вывод тула | 2 | 20 | ниже — ложные остановки; выше — поздняя реакция |
| `circuit.max_errors` | Ошибок подряд до стопа | L0 | S9 | 3 | как `AGENT_RUN_MAX_ATTEMPTS` ICPlan | 1 | 10 | частота временных сбоев провайдера |
| `kill_switch` | Аварийная остановка агента или платформы | L1 | S2 | выкл | нормальная работа | выкл | вкл | вкл — при инциденте |

## Хранилища данных

| ID | Хранилище | Что хранит | Владелец | Резервирование / срок |
|---|---|---|---|---|
| S2 | Postgres ICPlan, схема `platform` | настройки агентов, версии, профили sandbox и памяти, данные guardrails, параметры планирования | Platform module | вместе с S1 |
| S8 | git: репозитории продукта; репозиторий политик Rego | код агентов (ветки, PR); правила guardrails | git-провайдер | история git |
| S9 | Конфиг деплоя: `values.yaml` (git, без секретов) + Secret / `.env` (вне git) | параметры платформы, адреса, переключатели guardrails, секреты | эксплуатация | версии в git; секреты — вне git |
| S11 | OPA в памяти (bundle) | правила и данные для решений | Guardrails | не источник правды — пересобирается из S2 и S8 |

## Нагрузка и развёртывание

| | |
|---|---|

## Отказы (FMEA)

| Отказ | Обнаружение | Поведение | Восстановление |
|---|---|---|---|
| OPA недоступен | таймаут I5 / I10 | по `on_engine_error`: deny (по умолчанию) или allow с пометкой | восстановление OPA |
| Битый Rego | `opa test` / ошибка загрузки bundle | OPA остаётся на прежнем bundle | исправление в git |
| Точка выключена | конфиг L0 | проверка не выполняется, запись в лог старта | включение конфигом |
| Нет данных правил агента | пустые данные | deny всех тулов кроме явно разрешённых в L0 | заполнение в Platform module |
