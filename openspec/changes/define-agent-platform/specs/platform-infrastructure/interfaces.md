# platform-infrastructure — конфигурация, данные, интерфейсы, отказы

← [spec.md](spec.md) · [схема](architecture.md) · [трассировка](traceability.md) · [правила](../../../../../docs/rules/spec-criteria.md)

## Уровни конфигурации

| Уровень | Что | Где хранится | Область |
|---|---|---|---|
| L0 | Конфиг деплоя | S9 | платформа целиком: адреса, переключатели G1–G4, режим планирования, потолки лимитов |
| L1 | Platform module | S2 | агент: бюджеты, профили, данные guardrails, флаги планирования |
| L2 | Определение агента | S1 (+ YAML импорт) | агент: модель, инструкция, тулы, навыки, MCP, лимиты запуска |
| L3 | Запуск | задача ICPlan / `Run` | версия агента, критерии приёмки, задание |

Правило: значение берётся с самого конкретного уровня (L3 → L0), но не выше потолка L0.

## Параметры модуля

Значения и границы пересматриваются по статистике запусков (3.9) и нагрузочному тесту (4.8); правило — [виды спек, таблица параметров](../../../../../docs/rules/spec-kinds.md#params).

| Параметр | Что задаёт | Уровень | Хранилище | По умолчанию | Почему так по умолчанию | Мин | Макс | Тип | На что опираться при выборе |
|---|---|---|---|---|---|---|---|---|---|
| `k3s.version` | Версия кластера | L0 | S9 | v1.37.1+k3s1 | актуальная стабильная (TECHNOLOGIES.md) | минимальная, поддерживаемая чартами | последний патч минорной версии | строка | совместимость Helm-чартов ICPlan и LiteLLM |
| `ingress.host / tls` | Домен и сертификат | L0 | S9 | ACME | автоматическое продление сертификата | ACME | свой сертификат | строка / одно из: ACME, свой сертификат | свой — во внутренней сети без доступа к ACME |
| `<сервис>.replicas` | Число реплик | L0 | S9 | api 2, LiteLLM 2, OPA 2, остальные 1 | 2 — обновление без простоя | 1 | ёмкость узла и соединений Postgres | число | 1 — dev; больше 2 — по нагрузочному тесту (4.8) |
| `<сервис>.resources` | requests / limits | L0 | S9 | по таблице сайзинга | профиль нагрузки (R&D) | requests по таблице сайзинга | ёмкость узла | строка | замер нагрузочного теста (4.8) |
| `pgbouncer.pool_mode / size` | Режим и размер пула | L0 | S9 | transaction / 30 | 30 соединений к Postgres с запасом при `max_connections` 100 | session / 10 | transaction / `max_connections` − служебные | одно из: transaction, session / число | совместимость сервисов с transaction-режимом (открытый вопрос) |
| `postgres.backup.target` | Куда класть копии | L0 | S9 | S3 вне узла | копия переживает потерю узла | S3 вне узла | S3 вне узла | ссылка S3 | обязательно вне узла |
| `objectStorage.endpoint` | Адрес S3 | L0 | S9 | RustFS в кластере | как в ICPlan | RustFS в кластере | внешний S3 | строка | внешний — при росте объёма |
| `networkPolicy.enabled` | Сетевые политики | L0 | S9 | true | изоляция по умолчанию | false | true |  | false — только локально |

## Хранилища данных

| ID | Хранилище | Что хранит | Владелец | Резервирование / срок |
|---|---|---|---|---|
| S1 | PostgreSQL 17 (CloudNativePG), БД `itsaplan`, схема `public` | задачи, агенты, `agent_run`, `issue_activity`, статусы, документы | ICPlan | базовые копии + WAL в S3 вне узла |
| S6 | PostgreSQL 17 (тот же кластер), БД `litellm` | virtual keys, бюджеты, журнал затрат | LiteLLM | журнал затрат — по политике LiteLLM |
| S7 | RustFS (S3 API), бакет `planner-attachments` | вложения задач, артефакты агентов, резервные копии | ICPlan / Инфраструктура | копия вне узла |
| S9 | Конфиг деплоя: `values.yaml` (git, без секретов) + Secret / `.env` (вне git) | параметры платформы, адреса, переключатели guardrails, секреты | эксплуатация | версии в git; секреты — вне git |

## Нагрузка и развёртывание

| | |
|---|---|
| **Нагрузка** (гипотеза, [R&D](../../../../../docs/rnd/load-profile.md)) | ~20 RPS к API ICPlan и до 6 запусков агентов в пике; потребление ~13 ГБ RAM и ~5 vCPU не более ёмкости узла 8 vCPU / 32 ГБ / 400 ГБ; запас под 10 обычных или 4–5 «coder» запусков |
| **Развёртывание** ([R&D](../../../../../docs/rnd/kubernetes-runtime.md)) | k3s один узел; namespaces `itsaplan-core`, `itsaplan-data`, `itsaplan-agents`, `itsaplan-platform`; Traefik ingress; CloudNativePG + PgBouncer; RustFS |

Детали форматов — [потоки](../../../../../docs/how/infrastructure.md).

## Отказы (FMEA)

| Отказ | Обнаружение | Поведение | Восстановление |
|---|---|---|---|
| Узел недоступен | health-check узла | вся платформа недоступна (один узел) | восстановление узла, данные — из бэкапа вне узла |
| Postgres недоступен | проверки готовности сервисов | сервисы не готовы, запуски не стартуют | CloudNativePG перезапускает; восстановление из бэкапа |
| PgBouncer исчерпал пул | ожидание соединения | запросы ждут до таймаута, ошибка с причиной | увеличить пул, найти утечку соединений |
| Истёк TLS-сертификат | мониторинг срока | Traefik обновляет по ACME; при сбое — предупреждение | ручное обновление |
| Переполнен диск | метрика диска | запись в БД и хранилище останавливается | очистка по срокам, расширение диска |
| RustFS (S7) недоступен | проверка готовности RustFS, ошибки S3 API | вложения и артефакты не сохраняются, итоги публикуются без вложений; копии БД вне площадки не затронуты | перезапуск пода; данные — с тома; вложения дозагружаются повтором |
