# Spec Delta

## Purpose

Единый версионируемый каталог ресурсов платформы и декларативных определений агентов, из которых агент собирается без написания кода. Обоснование: [R&D](../../../../../docs/rnd/config-storage.md).

## ADDED Requirements

<a id="r-reg-01"></a>
### Requirement: Каталог ресурсов
Registry (ICPlan) SHALL хранить ресурсы типов `model`, `skill`, `tool`, `mcp_server`, `agent` (инструкция, проекты, версия); бюджеты, профили sandbox и памяти, данные guardrails, уровень автономии и политику доступа SHALL хранить Platform module (control-plane).

#### Scenario: Регистрация ресурса
- **WHEN** администратор добавляет ресурс любого из типов
- **THEN** ресурс получает идентификатор и версию и становится доступен для ссылок

#### Scenario: Дубликат
- **WHEN** добавляется ресурс с существующим идентификатором
- **THEN** добавление отклоняется

#### Scenario: Неизвестный тип
- **WHEN** добавляется ресурс неподдерживаемого типа
- **THEN** отказ с перечнем допустимых типов

**ID:** `R-REG-01` · **Реализует задача:** [1.2](../../../../../docs/tasks/1.2-agent-definition-yaml.md)

<a id="r-reg-02"></a>
### Requirement: Определение агента
Определение агента SHALL состоять из: модель (алиас), инструкция и формат результата, навыки, тулы и MCP-серверы (ссылки на ресурсы Registry), проекты, версия. Профили памяти и sandbox, данные guardrails и автономия — настройки агента в Platform module (control-plane).

#### Scenario: Добавление агента без кода
- **WHEN** администратор сохраняет новое определение агента
- **THEN** агент доступен для запуска по `agent_id` без изменения кода платформы

#### Scenario: Обязательное поле отсутствует
- **WHEN** в определении нет модели
- **THEN** сохранение отклоняется с указанием поля

#### Scenario: Выключение агента
- **WHEN** агент выключен (`agent.enabled = false`, R-ICP-17)
- **THEN** новые запуски не создаются, история сохраняется

**ID:** `R-REG-02` · **Реализует задача:** [1.2](../../../../../docs/tasks/1.2-agent-definition-yaml.md), [2.3](../../../../../docs/tasks/2.3-config-from-icplan.md)

<a id="r-reg-03"></a>
### Requirement: Версионирование
Каждое изменение ресурса SHALL создавать новую версию; прежние версии MUST оставаться доступными.

#### Scenario: Запуск на прежней версии
- **WHEN** задача указывает конкретную версию агента
- **THEN** запуск использует эту версию, даже если есть более новая

#### Scenario: Новая версия
- **WHEN** администратор меняет инструкцию
- **THEN** создаётся новая версия, прежние доступны

#### Scenario: Несуществующая версия
- **WHEN** задача указывает версию, которой нет
- **THEN** запуск отклоняется с ошибкой версии

**ID:** `R-REG-03` · **Реализует задача:** [4.4](../../../../../docs/tasks/4.4-platform-module.md)

<a id="r-reg-04"></a>
### Requirement: Источник правды и экспорт
Определения агентов SHALL храниться в БД ICPlan как источнике правды; система SHALL поддерживать экспорт и импорт определений в YAML для ревью и переноса между окружениями.

#### Scenario: Перенос в prod
- **WHEN** администратор экспортирует агента из dev и импортирует в prod
- **THEN** в prod создаётся новая версия агента с тем же содержимым

#### Scenario: Экспорт
- **WHEN** администратор выгружает агента
- **THEN** получает YAML `agent/v1` без секретов

#### Scenario: Импорт с другой схемой
- **WHEN** YAML другой major-версии схемы (`agent/v2` при поддержке `agent/v1`)
- **THEN** импорт отклоняется с указанием поддерживаемой версии

#### Scenario: Импорт с незнакомыми полями
- **WHEN** YAML той же major-версии содержит поля, которых нет в схеме
- **THEN** импорт выполняется, незнакомые поля перечислены в предупреждении и не сохраняются

**ID:** `R-REG-04` · **Реализует задача:** [4.4](../../../../../docs/tasks/4.4-platform-module.md)

<a id="r-reg-05"></a>
### Requirement: Валидация связей
Registry MUST отклонять сохранение определения агента со ссылками на несуществующие ресурсы.

#### Scenario: Битая ссылка
- **WHEN** определение агента ссылается на несуществующий скилл
- **THEN** сохранение отклоняется с указанием битой ссылки

#### Scenario: Все ссылки верны
- **WHEN** определение ссылается на существующие ресурсы
- **THEN** сохранение проходит

#### Scenario: Удаление используемого ресурса
- **WHEN** удаляют MCP-сервер, на который ссылается агент
- **THEN** удаление отклоняется со списком агентов

**ID:** `R-REG-05` · **Реализует задача:** [1.2](../../../../../docs/tasks/1.2-agent-definition-yaml.md)

<a id="r-reg-06"></a>
### Requirement: Смена модели агента
Смена модели агента SHALL выполняться изменением ссылки на модель в определении, без изменения остальных частей.

#### Scenario: Замена модели
- **WHEN** администратор меняет модель агента
- **THEN** новые запуски используют новую модель, активные запуски не затронуты

#### Scenario: Модель без доступа
- **WHEN** новая модель не настроена в шлюзе
- **THEN** смена отклоняется

#### Scenario: Откат модели
- **WHEN** администратор возвращает прежнюю модель
- **THEN** следующий запуск идёт на прежней модели

#### Scenario: Шлюз недоступен
- **WHEN** LiteLLM недоступен в момент сохранения агента со сменой модели
- **THEN** смена модели не сохраняется, администратор видит причину «проверить модель нельзя»; правка без смены модели сохраняется

**ID:** `R-REG-06` · **Реализует задача:** [2.3](../../../../../docs/tasks/2.3-config-from-icplan.md)

<a id="r-reg-07"></a>
### Requirement: Конфигурация модуля
Модуль SHALL брать свои параметры (7, таблица «Параметры модуля» в `interfaces.md`) с уровней L2 (S1), L3 (запуск): значение — с самого конкретного уровня; значение вне границ «Мин»–«Макс» таблицы MUST отклоняться с ошибкой, называющей параметр и границы. Изменение настройки SHALL действовать со следующего запуска; обязательные поля MUST проверяться при сохранении.

#### Scenario: Значение по умолчанию
- **WHEN** `agent.tools` (тулы агента из каталога) не задан в настройках
- **THEN** применяется значение по умолчанию: нет

#### Scenario: Нет обязательного поля
- **WHEN** настройку сохраняют без `agent.model`
- **THEN** сохранение отклонено, ошибка называет `agent.model`

#### Scenario: Изменение настройки
- **WHEN** `agent.model` изменён во время запуска
- **THEN** активный запуск работает со старым значением, новое — со следующего

**ID:** `R-REG-07` · **Реализует задача:** [2.3](../../../../../docs/tasks/2.3-config-from-icplan.md)

<a id="r-reg-08"></a>
### Requirement: Хранилища данных
Модуль SHALL хранить свои данные только в S1 (PostgreSQL 17 (CloudNativePG), БД `itsaplan`) (`interfaces.md`); данные S2 — доступ только через API или конфигурацию владельца. Секреты MUST NOT храниться в БД и git.

#### Scenario: Запись в своё хранилище
- **WHEN** модуль сохраняет определения агентов: модель, инструкция, тулы, навыки, MCP-серверы,…
- **THEN** запись попадает в S1 (PostgreSQL 17 (CloudNativePG), БД `itsaplan`)

#### Scenario: S1 недоступно
- **WHEN** S1 (PostgreSQL 17 (CloudNativePG), БД `itsaplan`) не отвечает
- **THEN** определения не читаются — запуски не стартуют

#### Scenario: Доступ вне своих хранилищ
- **WHEN** код agent-registry обращается к таблицам вне S1
- **THEN** доступа нет: роль БД agent-registry ограничена S1

**ID:** `R-REG-08` · **Реализует задача:** [2.3](../../../../../docs/tasks/2.3-config-from-icplan.md), [4.4](../../../../../docs/tasks/4.4-platform-module.md)

<a id="r-reg-09"></a>
### Requirement: Интерфейсы обмена
Интерфейсы модуля (I20, I1) SHALL соблюдать протокол, формат, аутентификацию, таймаут и политику повтора из `interfaces.md`; неидемпотентные вызовы MUST NOT повторяться автоматически.

#### Scenario: Таймаут I1
- **WHEN** ICPlan → Agent Runner: определение агента в выданном запуске (`/agent-runs/claim`) (I1) не ответил за 10 с
- **THEN** вызов прерывается; повтор: backoff до 60 с

#### Scenario: Права по I20
- **WHEN** пользователь без права изменения меняет определения агентов: модель, инструкция, тулы, навыки, MCP-серверы, проекты, версии
- **THEN** API ICPlan отклоняет запрос (403), данные не меняются, событие в журнале

#### Scenario: Повтор I1 без дублей
- **WHEN** вызов I1 повторён после сбоя
- **THEN** дубля нет: аренда: выдаётся одному Runner

**ID:** `R-REG-09` · **Реализует задача:** [2.3](../../../../../docs/tasks/2.3-config-from-icplan.md)

<a id="r-reg-10"></a>
### Requirement: Поведение при отказах зависимостей
Модуль SHALL вести себя при отказах зависимостей по таблице FMEA (`interfaces.md`): отказ обнаруживается, поведение предсказуемо и безопасно (fail-closed для проверок безопасности), восстановление не теряет данные.

#### Scenario: БД ICPlan недоступна
- **WHEN** бд icplan недоступна
- **THEN** определения не читаются — запуски не стартуют

#### Scenario: Удалён ресурс, на который ссылаются
- **WHEN** удалён ресурс, на который ссылаются
- **THEN** удаление отклоняется

#### Scenario: Импорт с неверной схемой
- **WHEN** импорт с неверной схемой
- **THEN** импорт отклоняется

**ID:** `R-REG-10` · **Реализует задача:** [2.3](../../../../../docs/tasks/2.3-config-from-icplan.md)

<a id="r-reg-11"></a>
### Requirement: Нагрузка и производительность
Модуль SHALL выдерживать профиль нагрузки (`interfaces.md`, «Нагрузка и развёртывание»): чтение определения на каждый запуск (~30 в час в пике); изменения — единицы в день. Превышение профиля MUST приводить к очереди или отказу с причиной, а не к деградации всей платформы.

#### Scenario: Пик профиля
- **WHEN** нагрузка достигает профиля: чтение определения на каждый запуск (~30 в час в пике)
- **THEN** выполняется: профиль выдерживается без ошибок

#### Scenario: Превышение профиля
- **WHEN** нагрузка вдвое выше профиля (чтение определения на каждый запуск (~30 в час в пике))
- **THEN** API ICPlan отвечает отказом с причиной на лишние запросы, интерфейс пользователей не деградирует

#### Scenario: Замер
- **WHEN** нагрузочный тест 4.8 на профиле «чтение определения на каждый запуск (~30 в час в пике)»
- **THEN** фактические значения (профиль выдерживается без ошибок) записаны и сравнены с профилем

**ID:** `R-REG-11` · **Реализует задача:** [4.8](../../../../../docs/tasks/4.8-load-test.md)

<a id="r-reg-12"></a>
### Requirement: Развёртывание
Модуль SHALL разворачиваться так: часть ICPlan api (Deployment `api` в `itsaplan-core`). Ресурсы MUST задаваться requests / limits, версии образов — закреплены; публичный доступ — только через ingress, если он указан.

#### Scenario: Установка в составе ICPlan
- **WHEN** разворачивается релиз ICPlan (часть ICPlan api (Deployment `api` в `itsaplan-core`)) с модулем agent-registry
- **THEN** миграции agent-registry применены до старта `api`, модуль доступен в ICPlan

#### Scenario: Обновление
- **WHEN** выходит новая версия форка ICPlan с изменениями agent-registry
- **THEN** миграции agent-registry обратно совместимы, `api` обновляется по одной реплике без простоя

#### Scenario: Откат
- **WHEN** версия с изменениями agent-registry не прошла проверки готовности
- **THEN** Helm откатывает ревизию, данные agent-registry сохранены

**ID:** `R-REG-12` · **Реализует задача:** [4.6](../../../../../docs/tasks/4.6-k8s-helm-ingress.md)
