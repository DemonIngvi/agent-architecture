# Spec Delta

## Purpose

Контракт уровня C1 между ICPlan и Agent Platform: ICPlan ставит запуски в свою очередь, Agent Runner забирает их как внешний раннер (pull), стримит шаги и итог обратно, получает решения пользователя. Обоснование: [R&D](../../../../../docs/rnd/runner-and-scheduling.md).

## ADDED Requirements

### Requirement: Агент платформы как внешний агент ICPlan
Агент, исполняемый платформой, SHALL быть заведён в ICPlan с типом «внешний»; его запуски MUST исполняться только Agent Runner по API-ключу агента.

#### Scenario: Делегирование агенту платформы
- **WHEN** пользователь делегирует задачу внешнему агенту платформы
- **THEN** запуск появляется в очереди ICPlan и забирается Agent Runner

#### Scenario: Внутренний агент
- **WHEN** задача делегирована внутреннему агенту ICPlan
- **THEN** запуск исполняет ICPlan, Agent Runner его не забирает

#### Scenario: Неверный ключ агента
- **WHEN** Agent Runner опрашивает очередь с отозванным ключом
- **THEN** ICPlan отвечает отказом в доступе, запуски не выдаются

<a id="r-icp-01"></a>**ID:** `R-ICP-01` · **Реализует задача:** [2.1](../../../../../docs/tasks/2.1-runner-external.md)

### Requirement: Получение запуска из очереди (pull)
Agent Runner SHALL получать запуски, опрашивая очередь ICPlan; ICPlan MUST NOT вызывать платформу напрямую.

#### Scenario: Платформа недоступна
- **WHEN** Agent Runner остановлен, а задача делегирована
- **THEN** запуск ждёт в очереди и исполняется после запуска Runner

#### Scenario: Пустая очередь
- **WHEN** в очереди нет запусков
- **THEN** Runner ждёт интервал опроса и повторяет запрос без ошибок

#### Scenario: ICPlan недоступен
- **WHEN** очередь ICPlan не отвечает
- **THEN** Runner повторяет опрос с растущей задержкой и пишет событие о недоступности

<a id="r-icp-02"></a>**ID:** `R-ICP-02` · **Реализует задача:** [2.1](../../../../../docs/tasks/2.1-runner-external.md)

### Requirement: Однократная выдача запуска
Запуск SHALL выдаваться одному экземпляру Runner; повторный опрос MUST NOT приводить к двойному исполнению.

#### Scenario: Два Runner опрашивают одновременно
- **WHEN** два экземпляра Runner опросили очередь в один момент
- **THEN** запуск получил ровно один из них

#### Scenario: Runner упал после получения
- **WHEN** Runner получил запуск и упал до старта
- **THEN** по истечении аренды запуск возвращается в очередь и выдаётся снова

#### Scenario: Повторный опрос того же Runner
- **WHEN** Runner повторно опрашивает очередь с уже взятым запуском
- **THEN** второй раз этот запуск не выдаётся

<a id="r-icp-03"></a>**ID:** `R-ICP-03` · **Реализует задача:** [2.1](../../../../../docs/tasks/2.1-runner-external.md), [2.7](../../../../../docs/tasks/2.7-runner-scheduler.md)

### Requirement: Стрим шагов и итог в задачу
Runner SHALL передавать в ICPlan шаги запуска по мере работы и итог; итог MUST публиковаться в задаче комментарием от имени агента, вложения — в задачу.

#### Scenario: Итог с вложением
- **WHEN** агент завершил работу с файлом-результатом
- **THEN** в задаче комментарий агента и вложение

#### Scenario: Итог без вложений
- **WHEN** агент завершил работу текстовым итогом
- **THEN** в задаче один комментарий агента

#### Scenario: Обрыв стрима
- **WHEN** соединение со стримом прервалось посреди запуска
- **THEN** Runner дошлёт пропущенные шаги по порядковым номерам, дубли не появляются

<a id="r-icp-04"></a>**ID:** `R-ICP-04` · **Реализует задача:** [2.1](../../../../../docs/tasks/2.1-runner-external.md), [3.3](../../../../../docs/tasks/3.3-run-events-timeline.md)

### Requirement: Подтверждения и ответы
ICPlan SHALL показывать в задаче запрос агента на подтверждение действия или вопрос и передавать решение пользователя в Runner.

#### Scenario: Подтверждение действия
- **WHEN** агент ждёт подтверждения и пользователь нажал «одобрить»
- **THEN** действие выполняется, запуск продолжается

#### Scenario: Отказ
- **WHEN** пользователь нажал «отклонить»
- **THEN** агент получает отказ и продолжает без этого действия или завершает запуск

#### Scenario: Нет прав на подтверждение
- **WHEN** участник без права подтверждения нажимает «одобрить»
- **THEN** решение отклоняется, запрос остаётся открытым

<a id="r-icp-05"></a>**ID:** `R-ICP-05` · **Реализует задача:** [3.4](../../../../../docs/tasks/3.4-icplan-approve-ui.md)

### Requirement: Уведомление о решении пользователя
Когда агент ждёт подтверждения или ответа, ICPlan SHALL уведомить исполнителя задачи (и участников с правом подтверждения) и показать срок ожидания; повторное уведомление MUST NOT отправляться чаще, чем раз в заданный интервал. Источник: US-ICP-03.

#### Scenario: Запрос подтверждения
- **WHEN** агент перешёл в ожидание подтверждения
- **THEN** исполнитель задачи получает уведомление со ссылкой на задачу и сроком

#### Scenario: Нет исполнителя
- **WHEN** у задачи нет исполнителя
- **THEN** уведомление получают участники с правом подтверждения в проекте

#### Scenario: Повтор уведомления
- **WHEN** решение не принято, а интервал повтора не истёк
- **THEN** второе уведомление не отправляется

<a id="r-icp-06"></a>**ID:** `R-ICP-06` · **Реализует задача:** [3.4](../../../../../docs/tasks/3.4-icplan-approve-ui.md)

### Requirement: Отмена из ICPlan
Отмена запуска в ICPlan SHALL останавливать его в платформе со статусом `cancelled`.

#### Scenario: Отмена
- **WHEN** пользователь отменяет запуск
- **THEN** Runner останавливает Harness и уничтожает sandbox

#### Scenario: Отмена завершённого запуска
- **WHEN** пользователь отменяет уже завершённый запуск
- **THEN** статус не меняется, пользователь видит сообщение

#### Scenario: Отмена во время ожидания подтверждения
- **WHEN** запуск ждёт approve и его отменяют
- **THEN** запуск завершается `cancelled`, запрос подтверждения закрывается

<a id="r-icp-07"></a>**ID:** `R-ICP-07` · **Реализует задача:** [2.1](../../../../../docs/tasks/2.1-runner-external.md)

### Requirement: Каталог агентов платформы
ICPlan SHALL показывать агентов платформы в общем списке агентов с их описанием и статусом в сети.

#### Scenario: Runner не в сети
- **WHEN** Agent Runner не опрашивает очередь дольше порога
- **THEN** агенты платформы отмечены «не в сети»

#### Scenario: Runner в сети
- **WHEN** Runner опрашивает очередь
- **THEN** агенты платформы отмечены «в сети»

#### Scenario: Агент отключён в платформе
- **WHEN** агент отключён в Platform module
- **THEN** в списке ICPlan он помечен недоступным, делегирование предупреждает

<a id="r-icp-08"></a>**ID:** `R-ICP-08` · **Реализует задача:** [2.3](../../../../../docs/tasks/2.3-config-from-icplan.md)

### Requirement: Версия протокола
Протокол раннера SHALL иметь версию; несовместимые изменения MUST выпускаться новой версией, Runner MUST сообщать поддерживаемую версию.

#### Scenario: Несовместимая версия
- **WHEN** ICPlan обновлён до протокола, который Runner не поддерживает
- **THEN** Runner не забирает запуски и сообщает о несовместимости

#### Scenario: Совместимая версия
- **WHEN** версии протокола ICPlan и Runner совпадают
- **THEN** запуски выдаются как обычно

#### Scenario: Минорное обновление
- **WHEN** ICPlan добавил необязательное поле в протокол
- **THEN** Runner продолжает работать, поле игнорируется

<a id="r-icp-09"></a>**ID:** `R-ICP-09` · **Реализует задача:** [2.1](../../../../../docs/tasks/2.1-runner-external.md)

### Requirement: Конфигурация модуля
Модуль SHALL брать свои параметры (9, таблица «Параметры модуля» в `interfaces.md`) с уровней L2 (S1): значение — с самого конкретного уровня. Без обязательного `Модель агента`, `Инструкция агента` модуль MUST NOT стартовать.

#### Scenario: Значение по умолчанию
- **WHEN** `Статусы доски` (этапы процесса) не задан на уровне L2
- **THEN** применяется значение по умолчанию: по проекту

#### Scenario: Нет обязательного параметра
- **WHEN** при старте не задан `Модель агента` (провайдер и модель (алиас))
- **THEN** модуль не стартует, ошибка называет `Модель агента` и уровень L2

#### Scenario: Неверное значение
- **WHEN** `Агент шага процесса` задан неверного типа или вне допустимых значений
- **THEN** модуль не стартует, ошибка называет `Агент шага процесса` и уровень L2

<a id="r-icp-10"></a>**ID:** `R-ICP-10` · **Реализует задача:** [2.1](../../../../../docs/tasks/2.1-runner-external.md)

### Requirement: Хранилища данных
Модуль SHALL хранить и читать свои данные только в S1 (PostgreSQL 17 (CloudNativePG), БД `itsaplan`), S7 (RustFS (S3 API), бакет `planner-attachments`) (`interfaces.md`); к данным других модулей — только через их API. Секреты MUST NOT храниться в БД и git.

#### Scenario: Запись в своё хранилище
- **WHEN** модуль сохраняет задачи, агенты, `agent_run`, `issue_activity`, статусы, документы
- **THEN** запись попадает в S1 (PostgreSQL 17 (CloudNativePG), БД `itsaplan`)

#### Scenario: S1 недоступно
- **WHEN** S1 (PostgreSQL 17 (CloudNativePG), БД `itsaplan`) не отвечает
- **THEN** операция завершается ошибкой без частичной записи, поведение — по FMEA, событие оператору

#### Scenario: Прямой доступ к чужим данным
- **WHEN** код модуля обращается к таблицам другого модуля
- **THEN** доступа нет: роль БД ограничена своими хранилищами

<a id="r-icp-11"></a>**ID:** `R-ICP-11` · **Реализует задача:** [2.1](../../../../../docs/tasks/2.1-runner-external.md)

### Requirement: Интерфейсы обмена
Интерфейсы модуля (I1, I2, I3, I19, I20, I21) SHALL соблюдать протокол, формат, аутентификацию, таймаут и политику повтора из `interfaces.md`; неидемпотентные вызовы MUST NOT повторяться автоматически.

#### Scenario: Таймаут I1
- **WHEN** ICPlan Run Queue → Agent Runner (I1) не ответил за 10 с
- **THEN** вызов прерывается; повтор: backoff до 60 с

#### Scenario: Аутентификация I2
- **WHEN** собеседник по I2 отклонил учётные данные (bearer API-ключ агента)
- **THEN** вызов не повторяется, событие с причиной

#### Scenario: Повтор I2 без дублей
- **WHEN** вызов I2 повторён после сбоя
- **THEN** дубля нет: да, по (run_id, seq)

<a id="r-icp-12"></a>**ID:** `R-ICP-12` · **Реализует задача:** [2.1](../../../../../docs/tasks/2.1-runner-external.md)

### Requirement: Поведение при отказах зависимостей
Модуль SHALL вести себя при отказах зависимостей по таблице FMEA (`interfaces.md`): отказ обнаруживается, поведение предсказуемо и безопасно (fail-closed для проверок безопасности), восстановление не теряет данные.

#### Scenario: Runner не в сети
- **WHEN** runner не в сети
- **THEN** агенты платформы «не в сети», запуски ждут

#### Scenario: Несовместимая версия протокола
- **WHEN** несовместимая версия протокола
- **THEN** Runner не берёт запуски

#### Scenario: Объектное хранилище недоступно
- **WHEN** объектное хранилище RustFS недоступно
- **THEN** итог публикуется без вложений, повтор загрузки

<a id="r-icp-13"></a>**ID:** `R-ICP-13` · **Реализует задача:** [2.1](../../../../../docs/tasks/2.1-runner-external.md), [2.6](../../../../../docs/tasks/2.6-e2e-icplan.md)

### Requirement: Нагрузка и производительность
Модуль SHALL выдерживать нагрузку профиля (`interfaces.md`, раздел «Нагрузка и развёртывание»): API ICPlan ~20 RPS пик (UI 8, Runner 3, события 4, MCP 1), p95 < 300 мс; 15 одновременных пользователей. Превышение профиля MUST приводить к очереди или отказу с причиной, а не к деградации всей платформы.

#### Scenario: Пиковая нагрузка профиля
- **WHEN** нагрузка достигает пика профиля
- **THEN** целевые показатели времени ответа и пропускной способности выполняются

#### Scenario: Превышение профиля
- **WHEN** нагрузка превышает профиль
- **THEN** лишние запросы ждут в очереди или получают отказ с причиной, остальные обслуживаются

#### Scenario: Замер
- **WHEN** выполняется нагрузочный тест
- **THEN** фактические показатели записаны и сравнены с профилем

<a id="r-icp-14"></a>**ID:** `R-ICP-14` · **Реализует задача:** [4.8](../../../../../docs/tasks/4.8-load-test.md)

### Requirement: Развёртывание
Модуль SHALL разворачиваться так: ICPlan: Deployment `web` (1–2), `api` (2), `worker` (1), `bot` (1) в `itsaplan-core`; вход — Traefik Ingress (HTTPS). Ресурсы MUST задаваться requests / limits, публичный доступ — только через ingress, если указан.

#### Scenario: Установка
- **WHEN** модуль разворачивается в кластере
- **THEN** объекты созданы в указанном namespace с заданными ресурсами

#### Scenario: Нехватка ресурсов
- **WHEN** узлу не хватает ресурсов для пода модуля
- **THEN** под ждёт размещения, событие для оператора

#### Scenario: Обновление
- **WHEN** выходит новая версия модуля
- **THEN** обновление проходит без потери данных и по правилам Helm-релиза
