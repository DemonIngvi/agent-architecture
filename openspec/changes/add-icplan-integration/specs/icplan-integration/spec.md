# Spec Delta

## Purpose

Контракт уровня C1 между ICPlan и Agent Platform: ICPlan ставит запуски в свою очередь, Agent Runner забирает их как внешний раннер (pull), стримит шаги и итог обратно, получает решения пользователя. Обоснование: [R&D](../../../../../docs/rnd/runner-and-scheduling.md).

## ADDED Requirements

### Requirement: Агент платформы как внешний агент ICPlan
Агент, исполняемый платформой, SHALL быть заведён в ICPlan с типом «внешний»; его запуски MUST исполняться только Agent Runner по API-ключу агента.

#### Scenario: Делегирование агенту платформы
- **WHEN** пользователь делегирует задачу внешнему агенту платформы
- **THEN** запуск появляется в очереди ICPlan и забирается Agent Runner

#### Scenario: Внутренний агент
- **WHEN** задача делегирована внутреннему агенту ICPlan
- **THEN** запуск исполняет ICPlan, Agent Runner его не забирает

#### Scenario: Неверный ключ агента
- **WHEN** Agent Runner опрашивает очередь с отозванным ключом
- **THEN** ICPlan отвечает отказом в доступе, запуски не выдаются

### Requirement: Получение запуска из очереди (pull)
Agent Runner SHALL получать запуски, опрашивая очередь ICPlan; ICPlan MUST NOT вызывать платформу напрямую.

#### Scenario: Платформа недоступна
- **WHEN** Agent Runner остановлен, а задача делегирована
- **THEN** запуск ждёт в очереди и исполняется после запуска Runner

#### Scenario: Пустая очередь
- **WHEN** в очереди нет запусков
- **THEN** Runner ждёт интервал опроса и повторяет запрос без ошибок

#### Scenario: ICPlan недоступен
- **WHEN** очередь ICPlan не отвечает
- **THEN** Runner повторяет опрос с растущей задержкой и пишет событие о недоступности

### Requirement: Однократная выдача запуска
Запуск SHALL выдаваться одному экземпляру Runner; повторный опрос MUST NOT приводить к двойному исполнению.

#### Scenario: Два Runner опрашивают одновременно
- **WHEN** два экземпляра Runner опросили очередь в один момент
- **THEN** запуск получил ровно один из них

#### Scenario: Runner упал после получения
- **WHEN** Runner получил запуск и упал до старта
- **THEN** по истечении аренды запуск возвращается в очередь и выдаётся снова

#### Scenario: Повторный опрос того же Runner
- **WHEN** Runner повторно опрашивает очередь с уже взятым запуском
- **THEN** второй раз этот запуск не выдаётся

### Requirement: Стрим шагов и итог в задачу
Runner SHALL передавать в ICPlan шаги запуска по мере работы и итог; итог MUST публиковаться в задаче комментарием от имени агента, вложения — в задачу.

#### Scenario: Итог с вложением
- **WHEN** агент завершил работу с файлом-результатом
- **THEN** в задаче комментарий агента и вложение

#### Scenario: Итог без вложений
- **WHEN** агент завершил работу текстовым итогом
- **THEN** в задаче один комментарий агента

#### Scenario: Обрыв стрима
- **WHEN** соединение со стримом прервалось посреди запуска
- **THEN** Runner дошлёт пропущенные шаги по порядковым номерам, дубли не появляются

### Requirement: Подтверждения и ответы
ICPlan SHALL показывать в задаче запрос агента на подтверждение действия или вопрос и передавать решение пользователя в Runner.

#### Scenario: Подтверждение действия
- **WHEN** агент ждёт подтверждения и пользователь нажал «одобрить»
- **THEN** действие выполняется, запуск продолжается

#### Scenario: Отказ
- **WHEN** пользователь нажал «отклонить»
- **THEN** агент получает отказ и продолжает без этого действия или завершает запуск

#### Scenario: Нет прав на подтверждение
- **WHEN** участник без права подтверждения нажимает «одобрить»
- **THEN** решение отклоняется, запрос остаётся открытым

### Requirement: Отмена из ICPlan
Отмена запуска в ICPlan SHALL останавливать его в платформе со статусом `cancelled`.

#### Scenario: Отмена
- **WHEN** пользователь отменяет запуск
- **THEN** Runner останавливает Harness и уничтожает sandbox

#### Scenario: Отмена завершённого запуска
- **WHEN** пользователь отменяет уже завершённый запуск
- **THEN** статус не меняется, пользователь видит сообщение

#### Scenario: Отмена во время ожидания подтверждения
- **WHEN** запуск ждёт approve и его отменяют
- **THEN** запуск завершается `cancelled`, запрос подтверждения закрывается

### Requirement: Каталог агентов платформы
ICPlan SHALL показывать агентов платформы в общем списке агентов с их описанием и статусом в сети.

#### Scenario: Runner не в сети
- **WHEN** Agent Runner не опрашивает очередь дольше порога
- **THEN** агенты платформы отмечены «не в сети»

#### Scenario: Runner в сети
- **WHEN** Runner опрашивает очередь
- **THEN** агенты платформы отмечены «в сети»

#### Scenario: Агент отключён в платформе
- **WHEN** агент отключён в Platform module
- **THEN** в списке ICPlan он помечен недоступным, делегирование предупреждает

### Requirement: Версия протокола
Протокол раннера SHALL иметь версию; несовместимые изменения MUST выпускаться новой версией, Runner MUST сообщать поддерживаемую версию.

#### Scenario: Несовместимая версия
- **WHEN** ICPlan обновлён до протокола, который Runner не поддерживает
- **THEN** Runner не забирает запуски и сообщает о несовместимости

#### Scenario: Совместимая версия
- **WHEN** версии протокола ICPlan и Runner совпадают
- **THEN** запуски выдаются как обычно

#### Scenario: Минорное обновление
- **WHEN** ICPlan добавил необязательное поле в протокол
- **THEN** Runner продолжает работать, поле игнорируется
