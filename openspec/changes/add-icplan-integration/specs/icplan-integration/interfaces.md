# icplan-integration — конфигурация, данные, интерфейсы, отказы

← [spec.md](spec.md) · [схема](architecture.md) · [трассировка](traceability.md) · [правила](../../../../../docs/rules/spec-criteria.md)

## Уровни конфигурации

| Уровень | Что | Где хранится | Область |
|---|---|---|---|
| L0 | Конфиг деплоя | S9 | платформа целиком: адреса, переключатели G1–G4, режим планирования, потолки лимитов |
| L1 | Platform module | S2 | агент: бюджеты, профили, данные guardrails, флаги планирования |
| L2 | Определение агента | S1 (+ YAML импорт) | агент: модель, инструкция, тулы, навыки, MCP, лимиты запуска |
| L3 | Запуск | задача ICPlan / `Run` | версия агента, критерии приёмки, задание |

Правило: значение берётся с самого конкретного уровня (L3 → L0), но не выше потолка L0.

## Параметры модуля

Значения и границы пересматриваются по статистике запусков (3.9) и нагрузочному тесту (4.8); правило — [виды спек, таблица параметров](../../../../../docs/rules/spec-kinds.md#params).

| Параметр | Что задаёт | Уровень | Хранилище | По умолчанию | Почему так по умолчанию | Мин | Макс | На что опираться при выборе |
|---|---|---|---|---|---|---|---|---|
| `agent.kind` | Внутренний агент ICPlan или внешний (наш Runner) | L2 | S1 | internal | значение по умолчанию ICPlan; агент платформы создаётся явно как external | internal | external | external — если агента исполняет платформа (Runner, sandbox, guardrails); internal — простой ответ модели внутри ICPlan |
| `agent.enabled` | Агент включён: создаются и выдаются запуски | L2 | S1 | да | новый агент сразу участвует в работе | нет | да | выключать на время инцидента, обслуживания, исчерпания бюджета |
| `agent.runner_scope` | Чьи запуски получает Runner: создателя агента или команды | L2 | S1 | team | значение по умолчанию ICPlan; агенты платформы — общие для команды | owner | team | owner — личный агент, раннер получает только запуски создателя (приватность) |
| `agent.delegation_delay_sec` | Задержка запуска после делегирования | L2 | S1 | 120 | значение ICPlan: время дописать задачу после делегирования человеком | 0 | 86400 | 0 — для шагов процесса (задачу ставит не человек); больше 120 — если задачи описывают долго; 86400 — ограничение CHECK в БД ICPlan |
| `AGENT_RUN_LEASE_SECONDS` | Аренда выданного запуска до повторной выдачи | L0 | S9 | 300 | значение ICPlan; heartbeat Runner продлевает аренду | 3 × интервал heartbeat Runner | 3600 | короче — быстрее повтор после падения Runner, но риск двойного исполнения при задержке heartbeat; длиннее — дольше простой задачи после падения |
| `runner.offline_after_s` | Порог «платформа не в сети» без опроса | L0 | S9 | 60 | 20 пропущенных опросов при опросе раз в 3 с | 5 × `poll_interval_ms` | 600 | ниже — ложные «не в сети» при сетевых паузах; выше — пользователь дольше не узнаёт о падении |
| `protocol.version` | Поддерживаемая версия протокола раннера | L0 | S9 | 0.5 (`@itsaplan/runner` 0.5.2 в форке) | версия пакета протокола форка; сейчас форк её не передаёт — доработка: Runner шлёт заголовок `x-runner-protocol` в `claim` и heartbeat, ICPlan отвечает 426 при несовпадении major (R-ICP-09) | версия ICPlan (major) | версия ICPlan (major) | major должен совпадать с ICPlan; при несовпадении Runner не берёт запуски |
| `project.mcp_enabled` | Доступ агентов к API ICPlan через MCP (колонка `project.mcp_enabled` форка) | L2 | S1 | выключен | значение ICPlan: MCP выключен по умолчанию | выключен | включён | включать в проектах, где работают агенты платформы; без MCP агент не прочитает задачу |

## Отказы (FMEA)

| Отказ | Обнаружение | Поведение | Восстановление |
|---|---|---|---|
| Runner не в сети | нет опроса дольше порога | агенты платформы «не в сети», запуски ждут | запуск Runner |
| Несовместимая версия протокола | проверка версии | Runner не берёт запуски | обновление Runner |
| Объектное хранилище недоступно | ошибка I19 | итог публикуется без вложений, повтор загрузки | досылка вложений |
| БД ICPlan (S1) недоступна | ошибки API ICPlan, `/health` api не готов | выдача запусков и приём итогов останавливаются; Runner повторяет с backoff, итог держит до восстановления | итог и события досылаются по `seq` без дублей |
