# icplan-integration — схема (C1)

```
┌─────────────────── ICPlan ───────────────────┐
│ задачи, планирование, выбор агента           │
└───┬──────────┬──────────┬─────────────▲──────┘
    │ агенты?  │ запуск,  │ approve,    │ события:
    │ каталог  │ отмена   │ ответ агенту│ статус, вопрос,
    │          │          │             │ результат
┌───▼──────────▼──────────▼─────────────┴──────┐
│ Integration API: REST + MCP-сервер           │
│ auth, квоты, идемпотентность, версия API     │
│┌──────┐  ┌───────┐ ┌──────────┐  ┌─────────┐ │
││Агенты│  │ Runs  │ │Approvals │  │ Events  │ │
│└──┬───┘  └───┬───┘ └────┬─────┘  └────▲────┘ │
└───┼──────────┼──────────┼─────────────┼──────┘
    ▼          ▼          ▼             │
Registry  Agent Runner Harness/G2   Runner/Obs
```

## Блоки

| Блок | Задача | Нужен? |
|---|---|---|
| Integration API | Единый вход: auth, квоты, идемпотентность, версия | Да — скрывает C2 |
| Агенты | `list_agents`, `describe_agent` — выбор агента | Да |
| Runs | `start_run`, `get_run`, `cancel_run`, `get_artifacts` | Да — ядро |
| Approvals | `approve_action`, `answer_run` | Да — требование G2 |
| Events | `status`, `needs_approval`, `question`, `done` | Да — push вместо polling |

## Расширения

```
новый канал      → адаптер (gRPC/очередь) ──▶ Integration API
новый инструмент → метод API ───────────────▶ автоматически MCP tool
новый агент      → Registry ────────────────▶ виден в list_agents
```

## Плюсы / минусы по модулям

| Модуль | ➕ | ➖ |
|---|---|---|
| Integration API | Стабильный контракт, C2 меняется свободно | Версионирование, обратная совместимость |
| MCP-поверхность | ICPlan-агент вызывает как тулы | Дублирует REST |
| Агенты | Осознанный выбор агента | Описания надо держать актуальными |
| Runs | Идемпотентность от двойного запуска | Долгие задачи: таймауты, возобновление |
| Approvals | Безопасность опасных действий | Запуск висит — нужен таймаут ожидания |
| Events | Реакция в реальном времени | Доставка: ретраи, дубли, порядок |

                                       ▼
                                ┌──────────────┐  да  ┌──────────────┐
                                │4 Нужен       ├─────▶│ Пользователь │
                                │ approve?     │◀─────┤ OK / отказ   │
                                └──────┬───────┘      └──────────────┘
                                       ▼ нет / после OK
                                ┌──────────────┐ нет ┌──────────────┐
                                │5 Quality     ├────▶│ повтор / стоп│

## Роли по этапам

| Этап | Агент делает | Польз. видит | Польз. управляет | Админ видит | Админ управляет |
|---|---|---|---|---|---|
| 1 Доска | — | список досок | выбор доски | — | доступные доски |
| 2 Задача | — | форма входа | вход задачи | — | шаблон входа |
| 3 Работа | цикл LLM/тулы, события | таймлайн, артефакты, сообщения | отмена | + трейс, $ | лимиты, kill |
| 4 Approve | ждёт | что агент хочет сделать | OK / отказ | журнал решений | какие действия требуют approve |
| 5 Quality gate | самопроверка (+валидатор) | итог gate | принять вручную / повтор | статистика | условия gate |
| 6 Смена статуса | — | передача след. агенту | — | — | Actions по статусам |

## ICPlan: есть / реализовать

Источник: документация `D:\АИ агент\Архитектура`, форк `itsaplan`. Требует проверки в UI.
✅ есть · ⚠️ частично · ❌ нет

| Функция трекера | ICPlan | Чего не хватает | Кто делает |
|---|---|---|---|
| Доска и процесс (статусы) | ✅ | — | ICPlan |
| Шаблон задачи | ✅ Issue Templates | — | ICPlan |
| Агент — делегат задачи (запуск) | ✅ поле «Делегат», упоминание | — | ICPlan |
| Automation: статус → запуск агента | ❌ автоназначение ставит только исполнителя, запуск — только по делегату | автоподхват по статусу/типу/действию | ICPlan — [icplan-agent-autopickup](../../../icplan-agent-autopickup/tasks.md) |
| Quality gate (критерии приёмки) | ⚠️ поле (Custom Fields) | проверка результата по gate | Платформа |
| Каталог агентов | ⚠️ только свои | агенты платформы | ICPlan ← `list_agents` |
| Ход выполнения (активность задачи) | ⚠️ только итог запуска | пошаговый лог агента | ICPlan ← Events |
| Комментарии задачи | ✅ | — | ICPlan |
| Вложения задачи | ⚠️ | промежуточные результаты агента | ICPlan ← `get_artifacts` |
| Согласование (approval) | ❌ | approve действия агента | ICPlan → `approve_action` |
| Вебхуки входящие | ⚠️ есть REST/MCP API | приём событий платформы | ICPlan |
| Затраты по задаче | ❌ | токены и $ на задачу | ICPlan ← `get_run` |
| Integration API | ❌ | целиком | Платформа |
