## 1. Агент-делегат статуса

- [ ] 1.1 Поле `autoDelegateUserId` у колонки (миграция, API колонок, проверка, что агент — участник проекта). **Зачем:** этап процесса = статус; без поля нет автоподхвата. **Приёмка:** интеграционный тест: PATCH колонки с агентом сохраняется, с не-участником — 400.
- [ ] 1.2 При входе задачи в колонку ставить делегата из `autoDelegateUserId`. **Зачем:** ключевой сценарий «перевёл в статус — агент взял». **Приёмка:** тест: перевод задачи создаёт запуск агента.
- [ ] 1.3 UI: выбор агента-делегата в настройках статуса. **Зачем:** пользователь настраивает процесс сам. **Приёмка:** в Настройки проекта → Статусы есть поле, сохраняется.

## 2. Агент-делегат типа задачи

- [ ] 2.1 Поле `autoDelegateUserId` у типа задачи. **Зачем:** разные типы — разные исполнители без лишних статусов. **Приёмка:** тест сохранения и проверки участника.
- [ ] 2.2 Делегирование при создании задачи типа и при смене типа. **Зачем:** задача сразу уходит в работу. **Приёмка:** тест: создание задачи типа создаёт запуск.
- [ ] 2.3 UI: поле в настройках типов задач. **Приёмка:** поле в Настройки проекта → Типы задач.

## 3. Эффект Действия «делегировать агенту» (T-04)

- [ ] 3.1 Новый тип эффекта `delegate_agent` в `actions`. **Зачем:** условия сложнее статуса и типа (метка, поле). **Приёмка:** тест: действие по метке создаёт запуск.
- [ ] 3.2 UI: выбор агента в редакторе действий. **Приёмка:** агенты доступны в списке эффекта.

## 4. Правила и надёжность

- [ ] 4.1 Приоритет: явный → статус → тип → действие. **Зачем:** предсказуемость, когда правил несколько. **Приёмка:** тест на конфликт статус/тип.
- [ ] 4.2 Защита от дублей: не ставить запуск при активном запуске агента по задаче. **Зачем:** нет двойной работы и трат. **Приёмка:** тест двойного перевода.
- [ ] 4.3 Очистка ссылок на агента в статусах, типах, действиях при выходе агента из проекта. **Зачем:** без висящих правил. **Приёмка:** тест снятия проекта у агента.

## 5. Передача между этапами и видимость

- [ ] 5.1 В задание запуска добавлять ссылку на итог предыдущего запуска по задаче. **Зачем:** следующий агент продолжает, а не начинает с нуля. **Приёмка:** тест: промпт содержит ссылку на комментарий предыдущего агента.
- [ ] 5.2 Запись в истории задачи «агент взял задачу по правилу …». **Зачем:** пользователь понимает, почему агент начал работу. **Приёмка:** событие видно в истории.
