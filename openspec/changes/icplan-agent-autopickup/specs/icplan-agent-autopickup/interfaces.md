## Уровни конфигурации

| Уровень | Что | Где хранится | Область |
|---|---|---|---|
| L0 | Конфиг деплоя | S9 | платформа целиком: адреса, переключатели G1–G4, режим планирования, потолки лимитов |
| L1 | Platform module | S2 | агент: бюджеты, профили, данные guardrails, флаги планирования |
| L2 | Определение агента | S1 (+ YAML импорт) | агент: модель, инструкция, тулы, навыки, MCP, лимиты запуска |
| L3 | Запуск | задача ICPlan / `Run` | версия агента, критерии приёмки, задание |

Правило: значение берётся с самого конкретного уровня (L3 → L0), но не выше потолка L0.

## Параметры модуля

Значения и границы пересматриваются по статистике запусков (3.9) и нагрузочному тесту (4.8); правило — [виды спек, таблица параметров](../../../../../docs/rules/spec-kinds.md#params).

| Параметр | Что задаёт | Уровень | Хранилище | По умолчанию | Почему так по умолчанию | Мин | Макс | На что опираться при выборе |
|---|---|---|---|---|---|---|---|---|
| `process.issue_type` | Тип задачи, которому принадлежит процесс | L2 | S1 | — (обязательный) | процесс задаётся для типа | тип проекта | тип проекта | у типа не более одного процесса |
| `step.column` | Колонка шага процесса | L2 | S1 | — (обязательный) | шаг = колонка | колонка проекта | колонка проекта | колонка не повторяется в процессе |
| `step.agent` | Агент шага (пусто — ручной шаг) | L2 | S1 | нет | шаг ручной, пока агента не назначили | нет | агент — участник проекта | агент, проверенный на тестовой задаче (US-ICP-24) |
| `step.on_success / on_failure` | Переходы шага по итогу запуска | L2 | S1 | следующий шаг / остаться | линейный процесс, ошибка не двигает задачу | шаг процесса | шаг, другой процесс, «завершить» | куда должна уйти задача по итогу |
| `step.max_runs` | Лимит запусков на шаге | L2 | S1 | 3 | как `AGENT_RUN_MAX_ATTEMPTS` ICPlan: запуск + 2 доработки | 1 | 10 | больше 10 — проблема постановки, нужен человек |
| `step.require_review` | Проверка пользователем после шага | L2 | S1 | выкл | процесс автоматический по умолчанию | выкл | вкл | вкл — для необратимых и внешних шагов (релиз, отправка клиенту) |
| `issue.review_with_me` | Проверять со мной все шаги задачи | L3 | S1 | выкл | решает пользователь для важной задачи | выкл | вкл | важность задачи |
| `issue.process_paused` | Процесс по задаче остановлен | L3 | S1 | нет | процесс идёт | нет | да | да — пока пользователь разбирается |
| `review_reminder_hours` | Напоминание о непроверенном результате | L0 | S9 | 24 | рабочий день | 1 | 168 | ритм работы команды |
| `Действия` | Условие → эффект «делегировать агенту» | L2 | S1 | нет | автоматизация — по выбору администратора | нет | Действия проекта | признаки, которых нет в процессе (метка, поле) |

## Отказы (FMEA)

| Отказ | Обнаружение | Поведение | Восстановление |
|---|---|---|---|
| Агент правила не участник проекта | проверка при срабатывании | запуск не создаётся, предупреждение в истории | администратор правит правило |
| Очередь недоступна | ошибка постановки | делегат установлен, запуск ставится повторно | повтор постановки |
| Цикл переходов (задача возвращается на шаг) | повторы одного правила по задаче | защита от дублей и лимит запусков на шаге (`step.max_runs`) | правка процесса |
| БД ICPlan (S1) недоступна | ошибки чтения процесса и записи переходов | переход по итогу запуска не выполняется, итог сохраняется в очереди событий ICPlan worker | worker повторяет переход после восстановления, идемпотентно по `run_id` |
