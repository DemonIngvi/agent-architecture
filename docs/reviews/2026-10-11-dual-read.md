# Проверка двумя читателями: модели данных и интеграции (11.10.2026)

← [Правило](../rules/dual-read.md) · [Модель данных](../../data-model.md#models) · [типы данных и интерфейсы](../flows/data-types.md)

Два независимых агента-читателя без контекста и без доступа к исходникам прочли раздел «Контракты обмена» и матрицу интерфейсов и по одной форме объяснили каждую модель (что это, кто → кому, почему так, почему такие имена, поля, что непонятно) и каждый I-код.

## Раунд 1

**Итог.** Смысл моделей и полей оба читателя поняли **одинаково** (совпадение почти полное) — сноски «почему так» читаются однозначно. Одно **расхождение** — направление I4 и I7. Главное — **«совпало, но непонятно»**: оба независимо отметили одни и те же пробелы, то есть в тексте не хватало конкретики.

| Объект | Читатель 1 | Читатель 2 | Вердикт | Что исправлено в источнике |
|---|---|---|---|---|
| Стрелка I4, I7 | I4: данные идут Platform module → Runner, стрелка обратная | I4: «видимо, это запрос; ответ идёт обратно» | разошлось | в матрице: стрелка — кто вызывает; у I7 — что идёт в каждую сторону; `UserMessage` в I7 |
| I20 | «ICPlan → ICPlan», самоссылка | стороны не указаны | непонятно | «ICPlan web → ICPlan api» |
| `Run.rule` | `type` дублирует `trigger`; `step` = «SDD» или `sdd`? | то же | непонятно | `rule = {process, step}`, `step` = `ProcessStep.id`; пример исправлен |
| `Run.trigger`, аренда | значения и срок аренды не объяснены | то же | непонятно | значения расшифрованы; аренда 300 с и heartbeat (I3) в `attempts` |
| Heartbeat | повторная доставка решений не описана | то же | непонятно | повтор до появления `seq` в событиях, отброс повтора по `runId` + `seq` / `id` |
| RunBundle | нет `prompt` / `systemPrompt`; `instruction` против `instructions`; L0–L3, `returnNote` не определены | то же | непонятно | поля добавлены; `instructions` как в ICPlan; слияние L0 → L3; `returnNote` = `Verdict.note` |
| WorkspaceSource `handoff` | не объяснено | не объяснено | непонятно | значение не определено ни в одном решении (D18 — только read и write); удалено из перечня прав |
| Criterion `origin`, приоритет | где reviewer; `agent:<шаг>` против `agent:analyst` | то же | непонятно | `<username>`; порядок: user и reviewer > process > agent |
| RunEvent, пример | `seq` 8 против 9; `delta` в `TEXT_MESSAGE_END` | то же | непонятно | пример согласован (`seq` 8); `*_END` хранит собранный текст в `delta` — описано в поле |
| AgUiEvent `value`, `runId` | схемы `CUSTOM` не описаны; `runId` строка против int | то же | непонятно | схема `value` по каждому `name`; `runId` строкой по AG-UI, `threadId` = `issueIdentifier` |
| RunResult `reason` | как соотносится со `status`; что в `gate.failed[]` | то же | непонятно | `done` → success, остальное → failed; `failed: Criterion[]` |
| ApprovalDecision | применим ли `scope` к `answer`; формат `by` | то же | непонятно | `scope` только для `approve`; `by` = `username` |
| UserMessage | поля без описаний; как доходит до Harness | то же | непонятно | описания; путь I3 → I7 |
| Verdict | что после вердикта; связь с `returnNote`; нет автора | то же | непонятно | `accepted` → `onSuccess`, `rejected` → `onFailure`; `note` → `returnNote`; поле `by` |
| Process / ProcessStep | `{step\|process\|done}`; `maxRuns` обязательное и «по умолчанию»; `criteriaApproval` против `requireReview`; шаг `help` не определён; нет `version` в примере | то же | непонятно | форматы и значения расшифрованы; `maxRuns` необязательное; пример с шагом `help` и `version` |
| Идентификатор агента | int, «analyst», «agent:analyst», «agent-7», «dev» | то же | непонятно | правило: в JSON — `agentId` (int), автор — `username`; `PolicyInput.agentId` = ключ `data.agents`; `key_alias` = `agent:<agentId>` |
| Бюджеты | три формы без единиц | то же | непонятно | лимиты `{runUsd, dayUsd}` (в бандле `run_usd`, `day_usd`), в G1 — потрачено `spent {runUsd, dayUsd, monthUsd}` |
| PolicyDecision | `allow=false` + `approval=true` — запрет или ожидание? | то же | непонятно | три исхода описаны в полях; источник — наш контракт (было 📘) |
| AgentDefinition | `apiVersion` при «snake_case»; `memory_profile.read` нет; `timeout_s` против `ttlSeconds` | то же | непонятно | `apiVersion` — заголовок формата как в Kubernetes; правило единиц: конфиг `_s`, JSON `Sec` (`ttlSec`, как `delaySec` в ICPlan) |
| RunSummary | источник 🧩, хотя данные форка; `runId` против `id`; M2 не определена | то же | непонятно | `id` как в API ICPlan; сноска: модель наша, данные и имена форка; M2 определена |
| SandboxClaim | запрос и ответ в одной модели; runc / runsc | то же | непонятно | `sandboxId`, `readyMs` — «в ответе»; runc / runsc объяснены |
| RepoGrant | нет токена; `branchPrefix` в примере — имя ветки | то же | непонятно | токен подставляет прокси; пример `agent/` |
| McpToolCall, пример | агент двигает задачу в «Ревью», хотя колонку не меняет | то же | **противоречие** | пример заменён на комментарий |
| M3Record | `issueId` обязателен при `scope = project`; Memory без учётных данных | то же | непонятно | `issueId` только при `scope = issue`; Memory API — сервис, токен запуска |
| ChatCompletionRequest `metadata` | помечено 📘, ключи свои; `issue_key` = ? | то же | непонятно | ключи расшифрованы: `issue_key` = `issueIdentifier` |
| CostAggregate | период; как из `run_id` получить `issueId` | то же | непонятно | за всё время задачи; через `agent_run` |
| Т8, защита | «при `events.level: всё`, кроме `events.level: всё`» | то же | **противоречие** | текст исправлен |
| Коды и термины | D, R, L0–L3, M0–M6, G, R0–R5, «шаг», Memory, RustFS не определены | то же | непонятно | раздел [«Термины и коды»](../../data-model.md#terms); «шаг процесса» и «итерация цикла» разведены |
| Таблицы | `int \| null` ломает столбцы | то же | дефект | `|` экранируется |
| Легенда | 🛠 не описан | то же | непонятно | легенда ✅ / 🛠 / 📘 / 🧩 |
| Вложенные модели | AgentDefinition, RunSummary, Criterion, AgUiEvent, ProcessStep без I-кода | то же | непонятно | у модели — «вложена в: …» |

Попутно найдено при исправлении: в спеке agent-registry строка I1 обещала «`Run` с агентом и версией» — в форке их нет; исправлено. Ссылка на параметр `memory.m2_max_chars`, добавленная автором при исправлении, — такого параметра нет; заменена на требование R-HRN-07.
