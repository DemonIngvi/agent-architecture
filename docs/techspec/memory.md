# Техспека: Memory

← [Все техспеки](README.md) · [компонент](../../components/memory/index.md) · [правило](../rules/tech-spec.md)

**Что разворачивается:** Memory API: чтение M1–M3, запись M3 с проверками, очистка по срокам.

## Образы

| Образ | База | Что внутри | Как собирается | Откуда берём | Тег | Пользователь | Порты | Проверка готовности |
|---|---|---|---|---|---|---|---|---|
| memory-api | `python:3.12-slim` | Memory API (FastAPI), задачи очистки | `memory/Dockerfile`, `uv.lock` | `ghcr.io/demoningvi/memory-api` | semver платформы | uid 10001 | 8085 | `GET /ready` (БД доступна) |

## Запуск

| | |
|---|---|
| **Namespace** | `itsaplan-agents` |
| **Реплики** | 1–2 |
| **Очистка** | CronJob `memory-retention` раз в сутки |

## Переменные и секреты

| Переменная | Зачем | Откуда |
|---|---|---|
| `DATABASE_URL` | БД ICPlan, роль только на свои таблицы | Secret `memory-db` |
| `MASK_PATTERNS` | шаблоны маскирования | ConfigMap (из observability) |

## Сборка и поставка

1. Сборка в GitHub Actions по тегу `vX.Y.Z` репозитория компонента; базовые образы закреплены по digest
2. Многостадийный Dockerfile: стадия сборки → минимальный образ запуска без компиляторов и менеджеров пакетов
3. SBOM (`syft`) и проверка уязвимостей (`trivy`, блокирует выпуск при critical)
4. Публикация в `ghcr.io/demoningvi/<имя>:<версия>` и `:<версия>-<sha>`; тег `latest` не используется
5. Кластер тянет образы с pull-секретом `ghcr-pull` (Secret в namespace)

## Проверка после развёртывания

- [ ] Запись M3 с секретом отклонена
- [ ] Чтение контекста задачи возвращает M1–M3
