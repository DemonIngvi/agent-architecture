## Сборка и поставка

1. Код модуля в `apps/api/src/modules/platform` форка
2. Миграции `packages/db/drizzle/platform_*`
3. Сборка в GitHub Actions по тегу `vX.Y.Z` репозитория компонента; базовые образы закреплены по digest
4. Многостадийный Dockerfile: стадия сборки → минимальный образ запуска без компиляторов и менеджеров пакетов
5. SBOM (`syft`) и проверка уязвимостей (`trivy`, блокирует выпуск при critical)
6. Публикация в `ghcr.io/demoningvi/<имя>:<версия>` и `:<версия>-<sha>`; тег `latest` не используется
7. Кластер тянет образы с pull-секретом `ghcr-pull` (Secret в namespace)

## Обновление и откат

Данные модуля — в схеме `platform` БД ICPlan (S2, R-CP-02): настройки агентов и проектов, версии настроек (`agent_settings_version`), профили, доступы, kill switch. Обновление ICPlan из upstream схему модуля не затрагивает.

1. Порядок: сначала миграции схемы `platform` (`packages/db/drizzle/platform_*`), затем новый `itsaplan-api`; пока миграция не прошла, api не стартует.
2. Миграции только добавляют таблицы и колонки: прежняя версия api продолжает работать со схемой после миграции.
3. Откат — прежний тег и digest образа `itsaplan-api`; миграции назад не откатываются, добавленные таблицы и колонки остаются неиспользуемыми. Версии настроек и журнал сохраняются, откат настроек агента — отдельно, `POST /platform/agents/:agentId/settings/rollback` (R-CP-04).
4. Ключи: `LITELLM_MASTER_KEY` меняется в Secret `litellm-admin` с перезапуском api; пока старый ключ не заменён, изменения бюджетов помечаются «не применено» и повторяются (R-CP-11).

## Пример конфигурации

Как настройки лежат в развёртывании. Значения и границы параметров — в `interfaces.md` спеки control-plane (здесь новых не вводится); поля контрактов — в [Модели данных](../../data-model.md).

Параметр уровня L0 (`values.yaml`, S9):

```yaml
platform:
  prompt:
    guidance_max_chars: 4000   # граница 0–16000
```

Резервная модель — в `config.yaml` LiteLLM (ConfigMap), по умолчанию её нет:

```yaml
litellm_settings:
  fallbacks: [{ team-default: [team-default-fallback] }]
```
