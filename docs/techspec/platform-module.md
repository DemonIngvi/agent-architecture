| Образ | База | Что внутри | Как собирается | Откуда берём | Тег | Пользователь | Порты | Проверка готовности |

| | |
|---|---|
| **Развёртывание** | в составе `itsaplan-api` |
| **Миграции** | схема `platform` — миграции форка до старта api |

## Переменные и секреты

| Переменная | Зачем | Откуда |
|---|---|---|
| `LITELLM_ADMIN_URL`, `LITELLM_MASTER_KEY` | раздача virtual keys | Secret `litellm-admin` |
| `OPA_BUNDLE_PATH` | куда выкладывать данные бандла | values |

## Сборка и поставка

1. Код модуля в `apps/api/src/modules/platform` форка
2. Миграции `packages/db/drizzle/platform_*`
3. Сборка в GitHub Actions по тегу `vX.Y.Z` репозитория компонента; базовые образы закреплены по digest
4. Многостадийный Dockerfile: стадия сборки → минимальный образ запуска без компиляторов и менеджеров пакетов
5. SBOM (`syft`) и проверка уязвимостей (`trivy`, блокирует выпуск при critical)
6. Публикация в `ghcr.io/demoningvi/<имя>:<версия>` и `:<версия>-<sha>`; тег `latest` не используется
7. Кластер тянет образы с pull-секретом `ghcr-pull` (Secret в namespace)

## Проверка после развёртывания

- [ ] Сохранить бюджет агента → ключ LiteLLM обновлён

## Как работает {#how}

Порядок работы компонента: что за чем происходит внутри и с соседями. Поля данных — в [Модели данных](../../data-model.md), стороны и протоколы — в «Интеграциях» компонента, сквозной сценарий — в [архитектуре](../../architecture.md#interaction).

### Порядок работы


| # | Поток | От → к | Данные |
|---|---|---|---|
| 1 | Администратор меняет настройки агента | Control Plane UI → API модуля | `AgentSettings` |
| 2 | Новая версия определения агента | API модуля → БД | `AgentDefinition` + версия |
| 3 | Runner читает профиль и бюджет перед запуском | Agent Runner → API модуля | `AgentSettings` |
| 4 | Алиасы и бюджеты уходят в LiteLLM | API модуля → LiteLLM | алиас, virtual key, лимит |
| 5 | Данные правил для OPA | API модуля → OPA (bundle data) | allowlist, лимиты |
| 6 | Экспорт / импорт агента | Админ ↔ API модуля | YAML `AgentDefinition` |
