## Сборка и поставка

1. Миграции `run_event` в форке
2. Сборка в GitHub Actions по тегу `vX.Y.Z` репозитория компонента; базовые образы закреплены по digest
3. Многостадийный Dockerfile: стадия сборки → минимальный образ запуска без компиляторов и менеджеров пакетов
4. SBOM (`syft`) и проверка уязвимостей (`trivy`, блокирует выпуск при critical)
5. Публикация в `ghcr.io/demoningvi/<имя>:<версия>` и `:<версия>-<sha>`; тег `latest` не используется
6. Кластер тянет образы с pull-секретом `ghcr-pull` (Secret в namespace)

## Обновление и откат

Своего сервиса нет: код живёт в `itsaplan-api`, таблица `run_event` (S3, схема `platform`) — в БД ICPlan; обновление — по Deploy [ICPlan](icplan.md).

1. Миграция `run_event` (задача 3.3.1) применяется вместе с миграциями api до выкладки нового образа; изменение — только добавлением колонок и индексов, чтобы прежняя версия api продолжала писать события.
2. Обновление api — по одной реплике; пока реплика недоступна, Runner буферизует события и досылает по `(run_id, seq)` без дублей (R-OBS-10).
3. Откат — прежний тег образа `itsaplan-api`; события в `run_event` остаются. Откат миграции — только при отсутствии новых колонок в данных: иначе вперёд-совместимая миграция остаётся, откатывается образ.
4. Изменение `events.level` и `retention_days` (values, L0) не требует миграции: уменьшение срока удаляет старые события при следующей очистке (R-OBS-06), уровень детализации действует на новые события.
5. Резервная копия — вместе с БД ICPlan (базовые копии + WAL); ключей шифрования у Observability нет, секреты маскируются до записи (R-OBS-04).

## Пример конфигурации

Как настройки лежат в развёртывании. Значения и границы параметров — в `interfaces.md` спеки (здесь новых не вводится); поля контрактов — в [Модели данных](../../data-model.md).

Параметры уровня L0 (S9, `values.yaml` в git):

```yaml
observability:
  events:
    level: "всё"                # итоги … всё; снижать только при нехватке диска
  retention_days: 90            # 7–365
  cost:
    source: "LiteLLM spend log" # единственный допустимый источник
```
