# Deploy: MCP / Tools

← [компонент](../../components/mcp-tools/index.md) · [методология](../rules/tech-spec.md)

**Что разворачивается:** MCP-серверы: `itsaplan-core` в api ICPlan; внешние — отдельные образы; клиент MCP — в Harness.

## Образы

| Образ | База | Что внутри | Как собирается | Откуда берём | Тег | Пользователь | Порты | Проверка готовности |
|---|---|---|---|---|---|---|---|---|
| — (`itsaplan-core` в `itsaplan-api`) | — | MCP ICPlan | в составе api форка | `ghcr.io/demoningvi/itsaplan-api` | версия форка | non-root | 3000 (`/mcp`) | `/health` api |
| внешние MCP-серверы | по серверу | например, MCP git-провайдера | официальные образы серверов | реестр поставщика, закреплён digest; копия в GHCR платформы | версия сервера | non-root | по серверу | по серверу |

| | |

## Сборка и поставка

1. Новый внешний сервер: строка в TECHNOLOGIES.md, лицензия, копия образа в GHCR
2. Сборка в GitHub Actions по тегу `vX.Y.Z` репозитория компонента; базовые образы закреплены по digest
3. Многостадийный Dockerfile: стадия сборки → минимальный образ запуска без компиляторов и менеджеров пакетов
4. SBOM (`syft`) и проверка уязвимостей (`trivy`, блокирует выпуск при critical)
5. Публикация в `ghcr.io/demoningvi/<имя>:<версия>` и `:<версия>-<sha>`; тег `latest` не используется
6. Кластер тянет образы с pull-секретом `ghcr-pull` (Secret в namespace)

## Обновление и откат

Собственных таблиц и миграций у MCP / Tools нет: конфигурация серверов, тулов и навыков лежит в S1 (БД `itsaplan`) и откатывается вместе с api ICPlan — по Deploy [ICPlan](icplan.md). Секреты серверов в БД и git не хранятся (R-MCP-08).

1. `itsaplan-core` обновляется вместе с `itsaplan-api` по одной реплике: тулы доступны без перерыва больше времени переподключения клиента (R-MCP-12).
2. Внешний MCP-сервер: новый образ копируется в GHCR платформы, закрепляется по digest; сервер, не прошедший проверку готовности, остаётся недоступным, остальные работают, событие эксплуатации (R-MCP-12).
3. Откат — прежний тег и digest образа (для `itsaplan-core` — прежняя версия api); данные откатывать не нужно.
4. После обновления сервера набор его тулов сверяется с `tools/list`: новые тулы агентам не видны, пока их не добавят в allowlist (FMEA «Сервер изменил набор тулов», R-MCP-10).

## Проверка после развёртывания

- [ ] `tools/list` возвращает разрешённые тулы

## Пример конфигурации

Как настройки лежат в развёртывании. Значения и границы параметров — в `interfaces.md` спеки (здесь новых не вводится); поля контрактов — в [Модели данных](../../data-model.md).

Подключение MCP-сервера к агенту:

```yaml
mcp:
  - server: itsaplan-core
    url: http://api:3000/mcp      # агент ходит через http://agent-runner:8080/runs/<id>/mcp/itsaplan-core (D19)
    auth: { secret_ref: agent-key/analyst }   # ключ не попадает в контекст агента
    tools: [get_issue, add_comment, update_issue]
    timeout_s: 30
```
