## Сборка и поставка

1. `uv.lock` закреплён; версии в TECHNOLOGIES.md
2. Системный промпт платформы — файл в образе, версия = версия образа
3. Тесты сценариев на mock-LLM перед публикацией
4. Сборка в GitHub Actions по тегу `vX.Y.Z` репозитория компонента; базовые образы закреплены по digest
5. Многостадийный Dockerfile: стадия сборки → минимальный образ запуска без компиляторов и менеджеров пакетов
6. SBOM (`syft`) и проверка уязвимостей (`trivy`, блокирует выпуск при critical)
7. Публикация в `ghcr.io/demoningvi/<имя>:<версия>` и `:<версия>-<sha>`; тег `latest` не используется
8. Кластер тянет образы с pull-секретом `ghcr-pull` (Secret в namespace)

## Обновление и откат

Своих данных и миграций у Harness нет: рабочие файлы — в `/workspace` среды (S10, удаляется с контейнером), состояние цикла — таблица `run_checkpoint` схемы `harness_ckpt` (S5), которую пишет и мигрирует Agent Runner (I12, R-HRN-11).

1. Обновление — новый образ `agent-harness:<версия>` в `HARNESS_IMAGE` (values Agent Runner): новые запуски идут на новом образе, активные доделываются на прежнем (R-HRN-15); тёплый пул пересоздаёт контейнеры (R-SBX-13).
2. Откат образа — прежний тег и digest в `HARNESS_IMAGE`; новые запуски стартуют на прежнем образе, пул пересоздаётся.
3. Откат после миграции схемы `harness_ckpt` — по Deploy [Agent Runner](agent-runner.md): миграции и точка восстановления — у него.
4. Запуск на паузе, начатый новой версией и продолженный прежней, восстанавливается из checkpoint этой версии; совместимость формата checkpoint между версиями Harness в документах не задана — проверять на тестовых задачах перед откатом (LangGraph закреплён, 1.2.14).
5. Ключей шифрования у Harness нет: секретов в checkpoint и `/workspace` нет (R-HRN-11).
