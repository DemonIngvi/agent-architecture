# План работ по документации

← [README](../README.md)

## Иерархия

```
README.md                                   ← уровень 0: все компоненты системы
 └─▶ docs/<компонент>/README.md              ← уровень 1: карточка компонента
      └─▶ docs/<компонент>/<подкомпонент>/   ← уровень 1.N: вложенные компоненты (по необходимости)
           └─▶ openspec/specs/<модуль>/      ← уровень 2: спека OpenSpec
                ├── spec.md                     требования, параметры реализации
                └── architecture.md             схема
                     └─▶ openspec/changes/<доработка>/tasks.md   ← уровень 3: задачи (INVEST)
```

Глубину вложенности определяем по компоненту: если внутри компонента есть самостоятельные части — для каждой своя папка и карточка.

## Правила

- **Все связи — гиперссылки.** Каждый упомянутый компонент, спека, задача — ссылка на свой файл. В каждом файле — ссылка «вверх» (←) на родителя.
- **Карточка компонента:** назначение, параметры, интеграции, подкомпоненты, готовность, ссылки на спеки и задачи.
- **Задачи — по INVEST** (Independent, Negotiable, Valuable, Estimable, Small, Testable): зачем, что сделать, критерий приёмки, статус.
- **Статусы:** ✅ сделано · ⚠️ частично · ⬜ не начато. Уже сделанное тоже показываем.
- **Схемы** — ASCII в согласованном формате ([FORMAT.md](../FORMAT.md)).
- **Описание и задачи разделены:** действующее описание — `openspec/specs/`, доработки — `openspec/changes/`.
