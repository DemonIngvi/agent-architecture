# Как быстро разобраться в документации

← [README](../README.md)

## За 5 минут

1. [README.md](../README.md) — какие компоненты есть, что каждый делает, насколько готов.
2. [architecture.md](../architecture.md) — схемы C1 (система и ICPlan) и C2 (внутреннее устройство).

## За 30 минут

3. Карточка нужного компонента — `docs/<компонент>/README.md` (ссылки в таблице README).
4. Из карточки — спека (`spec.md`: что компонент обязан делать) и схема (`architecture.md`).
5. Из спеки — задачи (`tasks.md`): что сделано, что осталось и зачем.

## Как читать

| Вопрос | Куда смотреть |
|---|---|
| Что это за компонент и зачем он | Карточка компонента |
| Как он связан с другими | Схема в карточке + ссылки «Интеграции» |
| Кто что делает и что может пойти не так | [User Stories](stories/README.md): процессы BPMN и критерии приёмки |
| Какие данные куда идут | [Потоки](flows/README.md): шаги, типы данных, примеры |
| Что он обязан делать | `spec.md`, раздел Requirements; сценарии WHEN/THEN — готовые тест-кейсы |
| Что уже сделано, что нет | Колонка «Готовность» в README, статусы в `tasks.md` |
| Почему выбрано именно так | [design.md](../openspec/changes/define-agent-platform/design.md) — решения D1–D13 |
| Что отложено | [BACKLOG.md](BACKLOG.md) |
| Какие технологии, лицензии, откуда качать | [TECHNOLOGIES.md](TECHNOLOGIES.md) |
| Какие были альтернативы и почему отвергнуты | [R&D](rnd/README.md) |

## Обозначения

- ✅ сделано · ⚠️ частично · ⬜ не начато
- **[G1]–[G4]** — точки guardrails (допуск, действия, изоляция, LLM)
- **C1 / C2** — уровни модели C4: система целиком / её внутренние контейнеры
- **ICPlan** — It's a Plan, таск-трекер, через который работают пользователи
- ← в начале файла — ссылка на родительский документ

## Советы

- Идите сверху вниз: README → карточка → спека → задачи. Не начинайте со спек.
- В VS Code ссылки открываются по Ctrl+клик; Ctrl+Shift+V — предпросмотр Markdown.
- Схемы ASCII читайте в моноширинном шрифте (редактор, не предпросмотр в браузере с пропорциональным шрифтом).
