# Как читать документацию

← [README](../README.md) · [правила документации](rules/README.md) · [вкладки и их наполнение](rules/doc-types.md#tabs)

Сайт устроен так же, как меню слева: **компоненты** (у каждого одинаковые вкладки), затем общие разделы **Архитектура → Требования → R&D → План и задачи → Справка**. Каждая вкладка отвечает на свой вопрос; если факт описан в другой вкладке, здесь будет ссылка, а не копия.

## За 5 минут

1. [Главная](../README.md) — карта платформы: компоненты и связи.
2. Архитектура → [Компоненты (таблица)](../README.md) — что делает каждый компонент и насколько готов.
3. Архитектура → [Схемы C1 / C2](../architecture.md) — система вместе с ICPlan и её внутреннее устройство.

## За 30 минут

4. Откройте нужный компонент в меню. Порядок вкладок — порядок чтения:

| Вкладка | Что узнаете |
|---|---|
| **Компонент** | из каких блоков состоит, почему так, с кем связан ([интеграции](../components/agent-runner/index.md#integrations)), какими данными обменивается ([контракты](../components/agent-runner/index.md#contracts)) и что хранит ([хранилища](../components/agent-runner/index.md#stores)) |
| **Компоненты** | каждый блок: технология, ключевые параметры, почему так |
| **Потоки** | кто, кому, когда и в каком порядке передаёт данные |
| **User Stories** | кто и зачем пользуется, процесс BPMN, критерии приёмки |
| **Спеки** | что компонент обязан делать: требования и сценарии WHEN / THEN; параметры, хранилища, интерфейсы, отказы |
| **Задачи** | что сделать, оценка, приёмка |
| **API** | вызовы и структура запросов и ответов |
| **Техспека** | образы, запуск, переменные, пример конфигурации |
| **R&D** | почему выбрано именно так, какие были альтернативы |

5. Общие разделы:

| Раздел | Что там |
|---|---|
| **Архитектура** | [сквозной поток](flows/README.md), [типы данных и интерфейсы](flows/data-types.md), [модель данных](../data-model.md) (все таблицы, контракты, правило имён), [каталог API](api/README.md), [техспеки](techspec/README.md), решения OpenSpec ([design](../openspec/changes/define-agent-platform/design.md): D1–D21) |
| **Требования** | [все User Stories](stories/README.md), [покрытие](stories/coverage.md), [персоны](stories/personas.md), [спеки по компонентам](../specs-by-component/index.md) |
| **R&D** | [все исследования](rnd/README.md), [по компонентам](../rnd-by-component/index.md), [последствия R&D](../rnd-consequences.md) |
| **План и задачи** | [Roadmap](ROADMAP.md), [сводная таблица](TASKS.md), [задачи по компонентам](../tasks-by-component/index.md), [бэклог](BACKLOG.md), [план документации](PLAN.md) |
| **Справка** | эта страница, [формат схем](../FORMAT.md), [правила документации](rules/README.md), [журнал отклонений](rules/deviations.md), ревью |

## Какой вопрос — какая вкладка

| Вопрос | Куда смотреть |
|---|---|
| Что это за компонент и зачем он | Компонент |
| С кем он связан и через что | Компонент → «Интеграции» |
| Какие поля в данных, откуда они и почему так названы | Компонент → «Контракты данных» или [Модель данных](../data-model.md) |
| Что хранится в базе | Компонент → «Хранилища» или [Модель данных](../data-model.md) |
| В каком порядке идут данные | Потоки, [сквозной поток](flows/README.md) |
| Какие вызовы API и что в них | API, [каталог API](api/README.md) |
| Что компонент обязан делать | Спеки → `spec.md`; сценарии WHEN / THEN — готовые тест-кейсы |
| Какие параметры, сроки, отказы | Спеки → «Интерфейсы, данные, отказы» |
| Как развернуть и настроить | Техспека |
| Почему выбрано именно так | R&D, [design](../openspec/changes/define-agent-platform/design.md) |
| Что сделано, что нет | [сводная таблица](TASKS.md), задачи |
| Что отложено | [бэклог](BACKLOG.md) |
| Какие технологии и лицензии | [TECHNOLOGIES.md](TECHNOLOGIES.md) |

## Обозначения

- ✅ сделано / есть в ICPlan · 🛠 доработка форка · 🆕 новое · ⬜ не начато
- ✅ / 📘 / 🧩 у модели данных — подтверждено OpenAPI форка / внешняя спецификация / наш контракт (решение D…)
- **I1–I23** — интерфейсы, **S1–S11** — хранилища, **Т1–Т8** — типы данных, **M0–M6** — уровни памяти
- **G1–G4** — точки guardrails (допуск, действия, изоляция, LLM)
- **D1–D21** — решения в design, **R-…** — требования, **US-…** — истории, **О-…** — отклонения
- **C1 / C2** — уровни модели C4: система целиком / её внутренние контейнеры
- ← в начале страницы — ссылка на родительский документ
