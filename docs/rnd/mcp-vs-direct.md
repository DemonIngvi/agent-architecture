## Контекст

MCP — стандарт для тулов, которые выбирает модель. Но описания тулов занимают контекст, а вызов через модель медленнее и дороже прямого.

## Альтернативы

| Вариант | Что это и как решает вопрос | Подходит, если |
|---|---|---|
| **Гибрид по правилам R1–R7** | MCP для внешних систем и ICPlan, прямой вызов для внутреннего и критичного по задержке | много разных систем, разные требования к задержке |
| **Всё через MCP** | любой тул — MCP-сервер | всё должно быть одинаково подключаемым |
| **Только прямые / нативные** | тулы — код Harness | тулов мало и они свои |

## Сравнение по существу вопроса

Критерии выведены из вопроса; в клетках — факты. Баллы матрицы ниже следуют из этих фактов.

| Критерий (почему важен) | Гибрид по правилам R1–R7 | Всё через MCP | Только прямые / нативные |
|---|---|---|---|
| Подключить систему без кода — US-MCP-01 | да для внешних | да | нет |
| Задержка внутренних вызовов (память, OPA) | прямой вызов | лишний сетевой прыжок | прямой вызов |
| Готовые серверы (ICPlan `itsaplan-core`, git) | используются | используются | не используются |

**Почему выбрано:** внешнее — без кода через MCP, внутреннее — без лишней задержки.

## Профиль технологий

Данные GitHub API на 10.10.2026.

| Технология | Лицензия | ★ | Последний релиз | Активность | Распространённость, поток, токены, сеть |
|---|---|---|---|---|---|

Индустрия: шаг заранее известен — прямой API; шаг решает модель — MCP; прямые вызовы эффективнее по токенам и в разы быстрее в пакетных операциях.

## Последствия

**Плюсы**

- Тулы переиспользуются, секреты вне агента
- Внутренние вызовы не тратят токены

**Минусы и риски**

- Правила нужно соблюдать при каждом новом туле — ревью
