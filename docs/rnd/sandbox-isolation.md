# R&D: изоляция запусков

← [Все R&D](README.md) · компонент: Sandbox · решение: [design D1](../../openspec/changes/define-agent-platform/design.md)

## Ресурсы (ориентиры, не замеры)

| Что | RAM | Старт |
|---|---|---|
| Harness (Python + LangGraph), аналитик | 150–300 МБ | — |
| Агент-разработчик (git, сборка) | 0.5–2 ГБ | — |
| CPU | почти 0 при ожидании LLM (80–95% времени) | — |
| Docker, образ в кэше | — | 0.5–2 с |
| Pod k8s, образ в кэше | — | 2–10 с |
| Скачивание образа | — | 10–60 с |
| microVM (Firecracker) | — | 0.1–0.3 с |

## Варианты

| Модель | ➕ | ➖ |
|---|---|---|
| A. Контейнер на запуск | максимальная изоляция | 2–10 с на старт, теряются кэши |
| B. Контейнер на агента (проект AI-агент) | образ под роль | тот же холодный старт; живой — запуски видят друг друга |
| C. Контейнер на задачу | кэш между этапами | ресурсы заняты в простое |
| **D. Тёплый пул + одноразовое использование** | старт < 1 с, изоляция как у A | пул постоянно занимает ресурсы |
| E. D + снимки / том | быстро и с постоянством | сложнее всех |

Индустрия: E2B, Daytona, Modal — microVM/контейнер + тёплый пул и снимки; Codex cloud и Copilot coding agent — контейнер на задачу с кэшем окружения; Devin — VM на сессию.

## Решение

D: пул 1–2 контейнера на профиль; рабочие данные — вне контейнера (git, вложения ICPlan, БД).
