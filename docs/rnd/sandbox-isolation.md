## Контекст

Агент выполняет код и ходит в сеть — нужна граница между запусками и хостом. Старт не должен занимать секунды. Ориентиры: harness 150–300 МБ, агент-разработчик 0.5–2 ГБ, CPU почти не нужен (80–95% времени — ожидание LLM); Docker стартует 0.5–2 с, pod 2–10 с, microVM 0.1–0.3 с.

## Альтернативы

| Вариант | Что это и как решает вопрос | Подходит, если |
|---|---|---|
| **D. Тёплый пул + одноразовый** | готовые контейнеры, каждый — на один запуск | нужны изоляция и быстрый старт |
| **A. Контейнер на запуск** | новый контейнер на каждый запуск | старт в секундах допустим |
| **C. Контейнер на задачу** | один контейнер на всю задачу | шаги делят файлы на диске |
| **B. Контейнер на агента** | долгоживущий контейнер агента | агент один и доверенный |
| **E. microVM (Firecracker)** | виртуальная машина на запуск | недоверенный код, сильная изоляция |
| **Managed (E2B)** | облачные песочницы | допустим SaaS |

## Сравнение по существу вопроса

Критерии выведены из вопроса; в клетках — факты. Баллы матрицы ниже следуют из этих фактов.

| Критерий (почему важен) | D. Тёплый пул + одноразовый | A. Контейнер на запуск | C. Контейнер на задачу | B. Контейнер на агента | E. microVM (Firecracker) | Managed (E2B) |
|---|---|---|---|---|---|---|
| Утечка между запусками | нет | нет | между шагами задачи | между задачами | нет | нет |
| Старт запуска | < 1 с | секунды | секунды | мгновенно | ~1 с, нужен KVM | секунды, сеть |
| Своё железо и простота | Docker / k8s | Docker / k8s | Docker / k8s | Docker / k8s | KVM, отдельная обвязка | SaaS |

**Почему выбрано:** изоляция одноразового контейнера при старте < 1 с на обычном Docker.

## Последствия

**Плюсы**

- Старт < 1 с при изоляции как у «контейнер на запуск»
- Сбой запуска не задевает другие

**Минусы и риски**

- Пул постоянно занимает ресурсы
- Изоляция контейнера слабее microVM — для недоверенного кода позже Firecracker
