# R&D: Автоматизация правил документации — навыки, хуки и инструмент вместо чтения правил

← [Все R&D](README.md) · [методология R&D v3.1](../rules/rnd-methodology.md) · правила: [работа с документами](../rules/doc-work.md), [типы и вкладки](../rules/doc-types.md#tabs), [журнал отклонений](../rules/deviations.md)

<div class="rnd-hero" markdown>
<div class="rnd-q">Вопрос</div>
Правил документации стало много (232 КБ, около 60 тыс. токенов), агент держит их в памяти и ошибается в момент правки. Можно ли вынести правила в инструменты, навыки и хуки, чтобы агент получал нужное правило в нужный момент, а не читал всё?

<div class="rnd-a">Ответ: да, и это лучше, чем читать правила. Три слоя: **инструмент** `doctool` (тип документа по пути, короткая выжимка правил из таблиц `doc-types.md` и `doc-work.md`, быстрые проверки без сборки сайта, заготовки документов); **хуки** Claude Code (до правки — запрет править генерируемые файлы с подсказкой источника, после правки — выжимка правил и найденные расхождения); **навыки** (порядок для типовых работ: правка документа, новое R&D, изменение данных, проверка двумя читателями) — в контексте только их описания. Сами правила остаются для людей и как источник выжимок; копий правил в навыках нет.</div>

<span class="rnd-badge adopt">Adopt</span> вариант D · без новых сервисов · данные 11.10.2026
</div>

# Покрытие потребностей П1–П6

**Что показал разбор.** Три вывода:

<div class="rnd-grid" markdown>
<div markdown>
**1. Ошибки — в момент правки, а не от незнания правил**

По журналу отклонений почти все расхождения появились, когда правило было, но не вспомнилось при правке: копия вместо ссылки, правка производного документа, выдуманный параметр. Чтение 60 тыс. токенов правил этого не лечит: правило нужно **в момент правки и про этот файл** ([Э3](#e3)).
</div>
<div markdown>
**2. Claude Code умеет доставлять правило в момент правки**

Хук до правки может запретить действие и объяснить причину; хук после правки добавляет текст в разговор. Навык держит в контексте только описание, тело — при вызове; его скрипты выполняются, а не читаются ([Э4](#e4)).
</div>
<div markdown>
**3. Выжимка — из тех же таблиц, иначе правила разойдутся**

Если переписать правила в навыки, получится вторая копия — та же ошибка, что с потоками и параметрами. Поэтому выжимку по типу документа строит инструмент из таблиц `doc-types.md` и `doc-work.md`, а навыки только говорят, что запускать ([Э7](#e7)).
</div>
</div>

<div class="rnd-grid" markdown>
<div class="take" markdown>
**Берём**

- хук до правки: запрет на генерируемые файлы с указанием источника;
- хук после правки: выжимка правил типа и быстрые проверки;
- навыки на типовые работы со ссылками на методологии;
- скрипты в навыках и инструменте вместо текста правил.
</div>
<div class="adapt" markdown>
**Адаптируем**

- выжимка правил → строится из таблиц правил, не пишется руками;
- проверки сборки → быстрый режим без сборки сайта (доли секунды).
</div>
<div class="drop" markdown>
**Не берём**

- длинный CLAUDE.md с правилами: всегда в контексте и расходится с правилами;
- отдельный MCP-сервер правил: те же функции, но новый сервис.
</div>
</div>

<div class="no" markdown>
**Отсеяны до сравнения**

- **E. MCP-сервер правил** — даёт то же, что инструмент и хуки, но требует отдельного процесса и настройки подключения.
</div>
<div class="risk" markdown>
**Риски и пересмотр**

- Хуки проекта работают, только если сессия Claude Code открыта в папке репозитория; при запуске из другой папки остаются навыки и инструмент.
- Пересмотр: если хук после правки замедляет работу (> 2 с) — оставить в нём только выжимку, проверки — в навыке перед коммитом.
</div>

## Э1. Вопрос {#e1}

**Ситуация.** Правила документации — 15 файлов в `docs/rules` (232 КБ). В сборке 59 автоматических проверок.

**Осложнение.** Владелец продукта отметил: правил много, они нагружают память агента. Агент не может держать их все в контексте и вспоминает правило не тогда, когда оно нужно.

**Вопрос.** Как доставлять агенту правила так, чтобы он применял их при каждой правке, не читая всё?

**Решает:** владелец продукта. **Не решаем:** содержание правил (остаются как есть).

<span class="gate">G1</span> ✅ вопрос — выбор; есть владелец; связан с замечанием владельца и журналом отклонений.

## Э2. Потребности {#e2}

| # | Потребность | Откуда | Что ломается без неё |
|---|---|---|---|
| П1 | правило про этот файл — в момент правки | О-41…О-50 | копии вместо ссылок, правка не того документа |
| П2 | не тратить контекст на правила, которые сейчас не нужны | замечание владельца | вытеснение рабочего контекста, сжатие разговора |
| П3 | нельзя править генерируемое — только источник | О-39, О-46 | правка теряется при сборке |
| П4 | расхождение видно сразу, а не в конце | О-44…О-50 | ошибка расползается по документам |
| П5 | одно описание правил — для людей и для агента | правило «один источник» | правила в навыках расходятся с `docs/rules` |
| П6 | типовые работы (R&D, модель данных, проверка читателями) — по шагам | методологии | шаги пропускаются |

<span class="gate">G2</span> ✅ у потребностей есть источник.

## Э3. Опорное решение: как сейчас {#e3}

| # | Функция | Что делает | Потребность |
|---|---|---|---|
| F1 | Правила в `docs/rules` | агент читает их по памяти | П5 |
| F2 | Проверки в `build.py` (59) | ловят расхождения при полной сборке (минуты) | П4 частично |
| F3 | Память агента (`MEMORY.md`) | краткие указания между сессиями | П2 частично |
| F4 | Журнал отклонений | причина и правило после ошибки | — |

**Вывод этапа.** Проверки уже ловят большинство ошибок, но поздно — при сборке. Правило в момент правки агент получает только из своей памяти.

<span class="gate">G3</span> ✅ функции из репозитория (А).

## Э4. Аналоги и их ключевые функции {#e4}

Поиск 11.10.2026: документация Claude Code.

| Аналог | Ключевые функции по вопросу | Уровень |
|---|---|---|
| **Навыки Claude Code** (`.claude/skills/<имя>/SKILL.md`) | в контексте — только описание, тело загружается при вызове; скрипты навыка выполняются, а не читаются; `SKILL.md` до 500 строк, подробности — в связанных файлах | Б |

| **CLAUDE.md** | всегда в контексте, в отличие от навыков | Б |
| **Линтеры и pre-commit** (общая практика) | проверка на каждом изменении, а не в конце | В |

**Вывод этапа.** Механизмы для доставки правила в момент правки есть: хуки — для обязательного, навыки — для порядка работы, скрипты — для проверок без затрат контекста.

## Э6. Перенос и критерии {#e6}

| Слой | Что | Источник содержания |
|---|---|---|
| **Инструмент** `html-view/doctool.py` | `route <файл>` — тип, вкладка, источник, выжимка правил и методология; `check` — все проверки без сборки сайта; `generated <файл>` — источник генерируемого файла; `rnd <slug>` — заготовка R&D | таблицы `doc-types.md`, `doc-work.md`; проверки `build.py` |
| **Хуки** `.claude/settings.json` | до правки — запрет генерируемых файлов; после правки — выжимка и проверки | `doctool` |
| **Навыки** `.claude/skills/` | `doc-edit`, `doc-rnd`, `doc-data`, `doc-dual-read` — порядок работы и что запускать | ссылки на методологии, без копий правил |

| **M1** правило приходит в момент правки | П1 → базовая | хук после правки |
| **M2** копий правил нет | П5 → базовая | выжимка строится из таблиц |
| **M3** генерируемое не правится | П3 → базовая | хук до правки |
| **К1** контекст | П2 | токены до вызова |

## Э7. Отсев и встраивание {#e7}

| Вариант | M1 в момент правки | M2 без копий | M3 генерируемое | Итог |
|---|---|---|---|---|
| D. Инструмент + хуки + навыки | да | да | да | проходит |
| C. Только навыки | только если агент вызвал навык | да | нет | ✗ |
| B. Выжимка в CLAUDE.md | частично (всегда, а не в момент) | **нет** — вторая копия | нет | ✗ |
| A. Как сейчас | нет | да | нет | ✗ |

```
 Агент правит файл ──▶ хук до правки: файл генерируемый? ── да ──▶ стоп: «правь источник X»
        │ нет
        ▼
   правка ──▶ хук после правки: doctool route (выжимка из doc-types.md, doc-work.md)
                                 doctool check (быстрые проверки build.py) ──▶ замечания в разговор
   типовая работа ──▶ навык (описание всегда, тело при вызове) ──▶ методология по ссылке
```

**Изменения у соседей:** `build.py` — функция быстрых проверок; правило [работа с документами](../rules/doc-work.md) — раздел про инструменты; память агента — указатель на навыки вместо пересказа правил.

**Вывод этапа.** ==Слои встают поверх существующих правил и проверок: правила не переписываются, выжимка строится из их таблиц.==

<span class="gate">G7</span> ✅ отсев; встраивание; изменения у соседей.

## Э8. Спор ролей {#e8}

| Роль | За | Довод | Опасение | Согласится, если |
|---|---|---|---|---|
| Агент 🤖 | D | правило приходит само и только своё | хук шумит на каждой правке | выжимка короткая, проверки — только при замечаниях |

**Оппонент (за B):** «Проще один CLAUDE.md». **Ответ:** он всегда в контексте и становится второй копией правил — ровно тот класс ошибок, который мы закрываем.

**Адвокат дьявола:** «Выжимка из таблиц будет слишком общей». **Ответ:** выжимка — указатель (тип, чего нельзя, источник, методология); подробности агент открывает по ссылке, когда нужно.
