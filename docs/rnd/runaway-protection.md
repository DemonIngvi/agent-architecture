# R&D: Защита от разгона агента

← [Все R&D](README.md) · [методология R&D v3.1](../rules/rnd-methodology.md) · компонент: **Guardrails, Harness** · решение: [design D6, D18](../../openspec/changes/define-agent-platform/design.md) · спека: [guardrails](../../openspec/changes/define-agent-platform/specs/guardrails/spec.md) (R-GRD-09 – R-GRD-15)

<div class="rnd-hero" markdown>
<div class="rnd-q">Вопрос</div>
Как остановить агента, который зациклился, тратит без меры или сыплет ошибками, — до того, как уйдут деньги, и предсказуемо?

<div class="rnd-a">Ответ: детерминированные проверки в Harness и Runner (повторы, шаги без прогресса, лимиты шагов и времени, аномальный расход, серия ошибок, аварийная остановка) плюс бюджеты и лимиты ключа в LiteLLM. Разбор практик уточнил правило цикла: сравнивать не только аргументы, но и результат.</div>

<span class="rnd-badge adopt">Adopt</span> проверки в коде + LiteLLM · 0 $ · данные 11.10.2026
</div>

**Почему детерминированные проверки.** Три вывода:

<div class="rnd-grid" markdown>
<div markdown>
**1. Цикл надо ловить по поведению, а не по деньгам**

Бюджет LiteLLM срабатывает, когда деньги уже потрачены. Третий одинаковый вызов тула или восемь шагов без изменений — раньше и бесплатно. Практики называют порог 3–5 одинаковых вызовов подряд (Cursor, OpenClaw: 3 и критично 6) ([Э4](#e4)).
</div>
<div markdown>
**2. Опрос — не цикл**

Агент может законно повторять вызов: ждать статус CI, опрашивать очередь. Аргументы те же, а результат меняется. Практики отличают цикл от опроса по «новому состоянию»: отпечаток аргументов **и** результата. Наше правило R-GRD-09 смотрит только на аргументы — предлагаем уточнить ([Э6](#e6)).
</div>
<div markdown>
**3. LLM-судья — дорого и вероятностно**

Модель, которая оценивает, зациклился ли агент, видит хитрые циклы. Но каждая проверка — это вызов модели, и ответ неустойчив. Детерминированные правила тестируются и стоят ноль ([Э9](#e9)).
</div>
</div>

<div class="rnd-grid" markdown>
<div class="take" markdown>
**Берём**

- повторы вызова (3), шаги без прогресса (8);
- лимит шагов (30) и времени, простой (`limits.idle_s`);
- иерархию бюджетов: запуск, агент в сутки, проект в месяц;
- аномальный расход (5 × медиана) → подтверждение;
- серию ошибок (3), аварийную остановку.
</div>
<div class="adapt" markdown>
**Адаптируем**

- отпечаток аргументов и результата (практики) → уточнение R-GRD-09;
- два порога: предупреждение и остановка (OpenClaw: 3 и 6) → предупредить агента перед остановкой — в бэклог;
- поиск циклов в графе исполнения (статья arXiv 2607.01641) → идея для разбора запусков.
</div>
<div class="drop" markdown>
**Не берём**

- LLM-судью на каждом шаге: цена и неустойчивость;
- только лимиты провайдера: без нашей платформы;
- только лимит ходов фреймворка: не видит цикл внутри лимита.
</div>
</div>

<div class="rnd-grid" markdown>
<div class="no" markdown>
**Отсеяны до сравнения**

- **Только лимиты провайдера** — общий лимит аккаунта, нет управления по агенту.
</div>
<div class="risk" markdown>
**Риски и пересмотр**

- Ложная остановка опроса — уточнение R-GRD-09.
- Пересмотр: в разборах запусков много циклов, которые правила не поймали → LLM-судья выборочно, на остановленных запусках.
</div>

## Э1. Вопрос {#e1}

**Ситуация.** Агент может зациклиться, раздуть контекст, сыпать ошибками провайдера. Запуски идут без присмотра человека.

**Осложнение.** Бюджеты ключа в LiteLLM останавливают траты, но поздно. LLM-судья видит больше, но стоит денег.

**Вопрос.** Чем и где останавливать разгон агента?

**Решает:** владелец продукта с администратором. **Не решаем:** движок правил ([guardrails](guardrails-engine.md)), шлюз ([LLM gateway](llm-gateway.md)).

<span class="gate">G1</span> ✅ вопрос — выбор; есть владелец; связан с D6, D18.

## Э2. Потребности {#e2}

| # | Потребность | Откуда | Что ломается без неё |
|---|---|---|---|
| П1 | остановить цикл до траты бюджета | R-GRD-09 | деньги уходят на повторы |
| П2 | лимит шагов и времени, простой | R-GRD-10 | запуск висит |
| П3 | бюджеты: запуск, агент, проект | R-GRD-11 | один агент тратит месячный бюджет |
| П4 | скачок расхода — к человеку | R-GRD-12 | огромный контекст молча оплачивается |
| П5 | серия ошибок — стоп | R-GRD-13 | повторы при сбое провайдера |
| П6 | аварийная остановка агента или платформы | R-GRD-15 | нельзя остановить при инциденте |
| П7 | предсказуемо и тестируемо, без лишних трат | D6 | ложные срабатывания, цена проверки |

<span class="gate">G2</span> ✅ у потребностей есть требования.

## Э3. Опорное решение: проверки в коде + LiteLLM {#e3}

| # | Функция | Где | Потребность |
|---|---|---|---|
| F1 | Повтор вызова с теми же аргументами (`loop.repeat_calls` 3) | Harness | П1 |
| F2 | Шаги без прогресса (`loop.no_progress_steps` 8) | Harness | П1 |
| F3 | `limits.max_steps` 30, `timeout_s`, `limits.idle_s` 300 | Harness, Runner | П2 |
| F4 | `budget.run / agent_day / project_month` | Runner (G1), LiteLLM | П3 |
| F5 | `anomaly.step_x_median` 5 → `waiting_approval` | Harness | П4 |
| F6 | `circuit.max_errors` 3 | Harness | П5 |
| F7 | `kill_switch` | Runner, Platform module | П6 |

**Вывод этапа.** Опорное решение закрывает все потребности; вопрос — точность правила цикла.

<span class="gate">G3</span> ✅ функции из спеки guardrails (А).

## Э4. Альтернативы и их ключевые функции {#e4}

## Э5. Ценность функций {#e5}

| Функция | Решение | Как | Где |

| **M3** бюджет по агенту | П3 → базовая | ключ на агента |
| **К1** ложные срабатывания | П7 | опрос, повтор после ошибки |
| **К2** цена проверки | П7 | вызовы модели |

## Э9. Выбор {#e9}

| Потребность | Проверки + LiteLLM | Только LiteLLM | LLM-судья | Лимит ходов |
|---|---|---|---|---|
| П1 цикл до траты | с доработкой: отпечаток результата | не закрывает | закрывает | частично |
| П2 шаги, время | закрывает | не закрывает | частично | закрывает |
| П3 бюджеты | закрывает | закрывает | не закрывает | не закрывает |
| П4 скачок расхода | закрывает | не закрывает | частично | не закрывает |
| П5 серия ошибок | закрывает | частично | не закрывает | не закрывает |
| П6 аварийная остановка | закрывает | частично | не закрывает | не закрывает |
| П7 предсказуемо, дёшево | закрывает | закрывает | не закрывает | закрывает |

- **Утверждение.** Детерминированные проверки в Harness и Runner + бюджеты LiteLLM (D6, D18), с уточнением R-GRD-09.
- **Основания.** Закрывает 6 из 7 потребностей; П1 — после уточнения.
- **Связка.** Цикл дешевле поймать по поведению, а деньги ограничить бюджетом; судья нужен только там, где правила промахиваются.
- **Опровержение.** Вывод неверен, если в разборах запусков много циклов, не пойманных правилами.
