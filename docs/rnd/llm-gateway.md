## Контекст

Нужна одна точка выхода к моделям: смена модели без кода, учёт и лимиты по агенту, работа без ключей при разработке.

## Альтернативы

| Вариант | Что это и как решает вопрос | Подходит, если |
|---|---|---|
| **LiteLLM Proxy** | единый OpenAI-совместимый шлюз: алиасы, virtual keys, бюджеты, учёт | много провайдеров и учёт затрат по агентам |
| **Kong AI Gateway** | плагины ИИ для API-шлюза Kong | уже используется Kong |
| **Portkey** | шлюз и наблюдаемость (облако + открытая часть) | допустим SaaS для учёта |
| **Прямые вызовы** | Harness ходит к провайдеру напрямую | один провайдер, учёт не нужен |

## Сравнение по существу вопроса

Критерии выведены из вопроса; в клетках — факты. Баллы матрицы ниже следуют из этих фактов.

| Критерий (почему важен) | LiteLLM Proxy | Kong AI Gateway | Portkey | Прямые вызовы |
|---|---|---|---|---|
| Бюджет на агента — virtual key | есть | через плагины / enterprise | есть | нет |
| Учёт затрат по запуску | `metadata` → spend logs | плагины | есть | нет |
| mock-модель тем же адресом | алиас на mock | маршрут | маршрут | нет |
| Своё размещение без платных частей | ядро MIT | OSS + enterprise | частично | — |

**Почему выбрано:** бюджеты, учёт и подмена модели в открытом ядре.

## Последствия

**Плюсы**

- Смена модели без изменения агентов
- Учёт и бюджеты по агенту и задаче
- Mock для разработки

**Минусы и риски**

- Лишний хоп и единая точка отказа — реплики
- Часть функций — enterprise-лицензия
