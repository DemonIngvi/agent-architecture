## Контекст

RAG даёт агенту куски из больших корпусов без загрузки всего в контекст. Это механизм чтения M4/M6, новых уровней памяти не добавляет. Для кода индустрия чаще использует агентный поиск (grep / чтение файлов) — точнее векторного.

Данные GitHub API на 10.10.2026.

Разница 85–88 — в пределах погрешности (правило равенства, см. методологию): при разнице не больше 5 баллов выбираем вариант без новых компонентов. Поэтому в MVP — без RAG, когда понадобится — pgvector (уже в Postgres ICPlan), Qdrant — при росте объёма.

## Последствия

**Плюсы**

- Переход на pgvector — без новой БД
