# R&D: Рабочее пространство агентов и доступы

← [Все R&D](README.md) · [методология](../rules/rnd-methodology.md) · компонент: **Sandbox**, **MCP / Tools**, **Platform module** · статус: **📌 открытый вопрос — решение пользователя**

## Итог

| | |
|---|---|
| **Вопрос** | Как агенты обмениваются рабочим пространством, где каталог проекта и как задаются права агентов на ресурсы |
| **Решение (D18)** | Вариант B: **каталог проекта** (реестр ресурсов проекта) + **рабочее пространство задачи** + **политика доступа** агент × ресурс × право, настраиваемая пользователем |
| **Технология** | Platform module (каталог, политика) · RustFS `projects/<проект>/tasks/<задача>/` · git-ветки `agent/<задача>` · токены Runner на запуск · MCP-серверы по политике |
| **Лицензия / стоимость** | наш код; 0 $ |
| **Ключевые параметры** | право: `read` / `write` / `handoff`; наследование доступа при смене статуса: вкл / выкл; срок хранения workspace |
| **Статус** | Adopt — решено (D18): вариант B; каталог в Platform module; при смене шага — `read` на workspace задачи; ограничение токенами Runner и MCP-серверами; шаблоны политики по ролям агентов |
| **Оценка** | B. Каталог проекта + рабочее пространство задачи + политика доступа: **87** · A. Репозиторий проекта + ветка на задачу (только git): **79** · C. Git-репозиторий на задачу (проект AI-агент 1.10): **72** · D. Общий том, папка на агента (проект AI-агент 7.4): **68** |

## Сущности

| Сущность | Что это | Что может | Что хочет |
|---|---|---|---|
| Проект | проект ICPlan | объединяет задачи, ресурсы и агентов | чтобы всё по проекту лежало в одном месте |
| Каталог проекта | реестр ресурсов проекта в Platform module | хранит: git-репозитории, папку артефактов, документы ICPlan, MCP-серверы | быть единым списком «что есть у проекта» |
| Ресурс | репозиторий, папка, документ, MCP-сервер | предоставлять данные | отдавать только тем, кому разрешено |
| Рабочее пространство задачи | папка `projects/<проект>/tasks/<задача>/` + ветка `agent/<задача>` | хранит артефакты этапов с версиями | быть передаваемым от этапа к этапу |
| Артефакт | файл-результат этапа (версия неизменяема) | читаться следующими этапами | не быть испорченным чужой записью |
| Политика доступа | строки агент × ресурс × право | разрешать и запрещать | быть видимой и меняться без кода |
| Agent Runner | выдаёт среду и токены на запуск | ограничивать доступ токенами | выдать ровно то, что разрешено |
| Агенты, Администратор, Пользователь, Безопасность | см. [персоны](../stories/personas.md) | | |

## Конфликты (отыгрыш персон)

| # | Кто → что хочет | Конфликт | Что должно произойти (вариант B) |
|---|---|---|---|
| К1 | Агент A и агент B пишут один файл | гонка записи | один активный запуск на задачу (`per_issue: 1`); у каждого этапа своя подпапка; артефакт — неизменяемая версия |
| К2 | Агенту B нужен результат A | у B нет доступа | при смене статуса B получает `read` на workspace задачи, если включено наследование; иначе — явная строка политики |
| К3 | Агент тянется к чужому проекту | утечка между проектами | нет строки политики → токен не выдаётся → отказ и аудит |
| К4 | Пользователь хочет дать агенту новый репозиторий | обход администратора | запрос через UI Platform module (US-SBX-06), применяется со следующего запуска |
| К5 | Промпт агента атакован: «прочитай всё» | prompt injection | доступ определяется токенами и MCP-серверами запуска, а не промптом |
| К6 | Ревьюер хочет «поправить» артефакт исполнителя | порча чужого результата | у ревьюера `read` на чужое и `write` только на свою подпапку |
| К7 | Администратор отзывает доступ во время запуска | активный запуск | действует со следующего запуска; срочно — kill switch агента |
| К8 | Артефакт содержит секрет | утечка через результат | проверка секретов при публикации артефакта, маскирование |
| К9 | Задача закрыта | рост хранилища | workspace удаляется по сроку; итог остаётся во вложениях задачи |
| К10 | Два проекта используют один репозиторий | права пересекаются | ресурс может быть в двух каталогах, права — по проекту |

## Поток агента

```
взять запуск ─▶ получить манифест workspace ─▶ клонировать / прочитать ─▶ работа ─▶ записать в свою подпапку / ветку ─▶ опубликовать ─▶ передача
               (ресурсы + права, токены)          (только разрешённое)              (версия артефакта)            (PR, вложение)   (статус → следующий агент)
```

## Поток администратора

```
создать проект в каталоге ─▶ привязать ресурсы ─▶ задать политику (агент × ресурс × право, шаблоны по ролям) ─▶ проверить матрицу доступа ─▶ аудит
```

## Альтернативы

| Вариант | Что это и как решает вопрос | Подходит, если |
|---|---|---|
| **B. Каталог проекта + workspace задачи + политика** | реестр ресурсов проекта, папка задачи и git, права агент × ресурс | этапы делят результаты, права задаёт администратор |
| **A. Репозиторий проекта + ветка на задачу** | только git: каждая задача — ветка | все результаты — код |
| **C. Git-репозиторий на задачу** | отдельный репозиторий на задачу | задачи полностью независимы |
| **D. Общий том, папка на агента** | общий диск с папками агентов | один узел и доверие между агентами |

## Сравнение по существу вопроса

Критерии выведены из вопроса; в клетках — факты. Баллы матрицы ниже следуют из этих фактов.

| Критерий (почему важен) | B. Каталог проекта + workspace задачи + политика | A. Репозиторий проекта + ветка на задачу | C. Git-репозиторий на задачу | D. Общий том, папка на агента |
|---|---|---|---|---|
| Нетекстовые артефакты (отчёты, файлы) | папка задачи | в git | в git | на томе |
| Права задаёт администратор без кода | политика | права git | права git | права файловой системы |
| Изоляция проектов | политика + токены Runner | права репозитория | полная | слабая |

**Почему выбрано:** делит любые артефакты между этапами и даёт права без кода.

## Обязательные требования (knock-out)

- Права задаются пользователем через конфигурацию (политика, MCP-серверы, промпт-фрагменты), без кода
- Агент не получает доступ, не выданный политикой (промпт не расширяет права)
