## Контекст

Агентов несколько; часть может идти параллельно, часть нет; агенты делят модели (TPM/RPM); нужен переключатель «всё последовательно / параллельно»; по задаче — не больше одного запуска. Исполнитель должен изолировать запуск и уважать лимиты.

## Альтернативы

| Вариант | Что это и как решает вопрос | Подходит, если |
|---|---|---|
| **A. Очередь на агента** | каждый агент берёт свои запуски по одному | агентов мало, параллельности нет |
| **B. Планировщик со слотами** | слоты: глобальные, на агента, на модель, на задачу | общая ёмкость и лимиты моделей |
| **C. Очередь с арендой (Temporal)** | внешний движок рабочих процессов | долгие процессы с ожиданиями |

## Сравнение по существу вопроса

Критерии выведены из вопроса; в клетках — факты. Баллы матрицы ниже следуют из этих фактов.

| Критерий (почему важен) | A. Очередь на агента | B. Планировщик со слотами | C. Очередь с арендой (Temporal) |
|---|---|---|---|
| Лимит на модель — rate limit провайдера | нет | слоты модели | своими средствами |
| Ожидание подтверждения не держит ёмкость | держит | освобождает слоты | есть |
| Новая инфраструктура | нет | нет | кластер Temporal |
| Протокол ICPlan (аренда, pull) | совместим | совместим | надо связывать |

**Почему выбрано:** учитывает лимиты моделей и ожидание без новой инфраструктуры.

## Последствия

**Плюсы**

- Модель не перегружается: слот модели общий для всех агентов
- Нет конфликтов двух запусков в одной задаче
- Режим платформы переключается одной настройкой

**Минусы и риски**

- Своя логика слотов — нужны тесты на гонки
- Возможно голодание долго ждущих запусков — нужна защита
