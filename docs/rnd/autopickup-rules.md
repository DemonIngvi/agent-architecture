## Контекст

Сейчас агент запускается только при ручной смене делегата или упоминании; автоназначение на статус ставит исполнителя и запуск не создаёт. Процесс «задача пришла в этап → агент взял» нужен без кода, настраиваемым пользователем.

## Обязательные требования (knock-out)

- Процесс настраивает пользователь в ICPlan без кода

- ✗ **Внешний оркестратор (Temporal / n8n)** — процесс описывается вне ICPlan, кодом или в отдельном UI

## Альтернативы

| Вариант | Что это и как решает вопрос | Подходит, если |
|---|---|---|
| **Процесс типа задачи в ICPlan** | тип задачи задаёт шаги; шаг = колонка + агент + переходы по итогу запуска | процесс команды живёт в трекере |
| **Внешний оркестратор (Temporal / n8n)** | процесс описан во внешней системе, трекер — только хранит задачи | процессы сложнее доски: ветвления, ожидания событий |
| **Ручное делегирование (как сейчас)** | пользователь сам назначает агента на каждом этапе | агенты используются эпизодически |
| **Автоназначение + отдельный триггер** | колонка назначает исполнителя, отдельное правило запускает агента | нужно минимальное изменение ICPlan |

## Сравнение по существу вопроса

Критерии выведены из вопроса; в клетках — факты. Баллы матрицы ниже следуют из этих фактов.

| Критерий (почему важен) | Процесс типа задачи в ICPlan | Внешний оркестратор (Temporal / n8n) | Ручное делегирование (как сейчас) | Автоназначение + отдельный триггер |
|---|---|---|---|---|
| Где настраивается процесс — пользователь не должен уходить из трекера | в настройках проекта ICPlan | во внешнем редакторе | нигде | в двух местах |
| Кто переводит задачу — однозначность | ICPlan по итогу запуска | оркестратор | человек | агент через `update_issue` |
| Доработка ICPlan | таблицы процесса и шагов (3.1, 3.6) | интеграция с оркестратором | нет | поле на колонке |
| Новая инфраструктура | нет | оркестратор и его БД | нет | нет |

**Почему выбрано:** процесс в трекере, переход однозначен и делается без новой инфраструктуры.

## Последствия

**Плюсы**

- Процесс виден прямо на доске и настраивается мышкой
- Опирается на существующий механизм делегирования

**Минусы и риски**

- Один агент на статус
- Порядок этапов задаётся статусами, параллельных веток нет
