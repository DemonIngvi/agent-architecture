# Методология подтверждений

← [Правила документации](README.md) · [роли](roles.md) · [типы документов](doc-types.md) · [сводная таблица](../approvals-summary.md)

Какие роли подтверждают какие документы, как ставится решение и как его видно на странице.

## Назначение и читатель

Документ считается принятым, когда его подтвердили **все роли, которые отвечают за его тип**. Подтверждение — это ответ роли на свой вопрос из [ролей](roles.md): архитектор — «где живут данные и как связаны модули», разработчик — «реализуемо ли так, как написано», тестировщик — «как проверить». Читатель — владелец продукта и любой исполнитель: по значкам в углу страницы видно, можно ли опираться на документ.

## Основа

| Практика | Что берём |
|---|---|
| Ревью по ролям (RACI, «approver») | у каждого типа документа — список подтверждающих ролей |
| Definition of Ready | документ готов, когда все его роли подтвердили |
| Версия под подтверждением | решение относится к конкретному тексту: текст изменился — решение сбрасывается |

## Роли и буквы

Значок роли — круг с одной буквой: зелёный с ✓ — подтвердил, красный с ✕ — отказ (причина — в комментарии), серый — ждёт.

| Буква | Роль | Вопрос |
|---|---|---|
| **В** | Владелец продукта | что важно, сколько стоит, что выбрать |
| **А** | Архитектор | где живут данные, как связаны модули, как развёртывается |
| **Р** | Разработчик | реализуемо ли так, как написано |
| **Т** | Тестировщик | как проверить каждое утверждение |
| **И** | Аналитик историй | кто что делает и что может пойти не так |
| **П** | Пользователь | решает ли это мою задачу |
| **Н** | Администратор (настройки) | понятны ли настройки |
| **Д** | DevOps-инженер | как развернуть, обновить, восстановить |
| **Б** | Безопасность | где утечка, лишние права, лицензионный риск |
| **С** | Инженер сборки и поставки | как собрать и откуда взять |

## Кто подтверждает какой документ

| Тип документа | Страница | Роли |
|---|---|---|
| Главная | `index.md` | А, В |
| Архитектура компонента | `components/<компонент>/` | А, Р |
| Блок | `components/<компонент>/<блок>/` | А, Р, Т |
| Интеграции | `docs/api/<компонент>.md` | А, Р, Т |
| Данные | `data-by-component/<компонент>/` | А, Р, Д |
| Deploy | `docs/techspec/<компонент>.md` | С, Д, Б |
| User Stories | `docs/stories/<компонент>.md` | И, П, В |
| Задача | `docs/tasks/<N.M>-….md` | Р, Т, В |
| R&D | `docs/rnd/*.md` | В, А |
| Решения | `design.md` | В, А |
| Методология | `docs/rules/*-methodology.md`, `tech-spec.md` | В, А |
| Спека | `spec.md` | по требованиям: роли из [видов спек](spec-kinds.md#approvals) в `approvals.md` рядом со спекой; значок спеки — сводка по требованиям |

Источник правила для сборки — `html-view/approvals.py` (`RULES`, `ROLES`); при изменении этой таблицы — сначала он ([изменение правил](change-process.md#rules-change)).

## Как ставится решение

1. Сборка добавляет в реестр [`docs/approvals.md`](../approvals.md) строку ⏳ для каждой пары «документ × роль».
2. Роль проверяет документ по своему вопросу и методологии его типа. Агент-роль — проверяющий агент `.claude/agents/doc-reviewer.md` (промпт роли — [prompts.md](prompts.md)); человек — сам.
3. Решение — командой: `./tools/doc approve <страница> <буква> ok|no "<комментарий>"` (агент — 🤖; человек добавляет `--human`). Отказ — всегда с причиной и ссылкой на то, что исправить.
4. Текст страницы изменился — сборка сбрасывает решение в ⏳ с пометкой «текст изменён после решения».
5. Что ждёт роли — `./tools/doc review-queue <буква>`.

Подтверждение агентом (🤖) и человеком (👤) различаются в реестре и в подсказке значка; агент не ставит 👤.

## Готовность документа

Документ готов, когда все его роли — ✅. Блок готов к реализации, когда документ готов, карточка заполнена и открытых вопросов по его требованиям нет ([методология блоков](block-methodology.md#ready)).

## Чек-лист

- [ ] У каждого типа документа из таблицы есть роли.
- [ ] Отказ содержит причину и что исправить.
- [ ] 🤖 и 👤 не смешаны.

## Проверки в сборке

`approvals.sync`: строки ⏳ для обязательных пар, сброс по изменённому тексту, удаление строк по удалённым документам; значки — на странице; [сводная таблица](../approvals-summary.md) — документ × роли.
