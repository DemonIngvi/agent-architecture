## Как замерять {#measure}

1. Расход агента — **сумма по всем вызовам модели** из журнала агента: input + запись кэша + чтение кэша + output по уникальным `message.id` (`python html-view/doctool.py cost from-transcript <agentId>`; в журнал — `cost add <процесс> - <единиц> <единица> --agents id,id`). `subagent_tokens` из отчёта о завершении — это **итоговый контекст** последнего вызова, а не расход: он занижает расход примерно в «число вызовов / 2» раз (хранится в поле `context` для сравнения). Делить на число единиц работы (пара документ × роль, документ, компонент, файл).
2. Расход ≈ вызовы × средний контекст, поэтому главные рычаги — меньше вызовов (правки скриптом, потолок вызовов в брифе) и меньший контекст. Главный контекст оркестратора считается так же (`cost from-transcript <uuid сессии>`), отдельной строкой.
3. Прерванные запуски в замер не входят; если расход известен только по завершённым частям, это отмечается в примечании.
4. Допуск ±2×: замер на единицу в диапазоне от половины минимума до удвоенного максимума ожидания — ✅; иначе ⚠️ «расхождение >2×» — правят ожидание в методологии или процесс (что из этого — по причине расхождения).
5. Цифры ожидания живут только в журнале: в методологиях — ссылка сюда, без повторения.
