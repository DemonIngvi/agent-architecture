# Методология интеграций и API

← [Правила документации](README.md) · [типы документов и вкладки](doc-types.md) · [каталог API](../api/README.md)

Как вести вкладку «Интеграции» компонента: схему C1 и карточки интеграций (генерируются из `datamodel.py`), эндпоинты в `docs/api/<компонент>.md`, примеры моделей в `docs/api/README.md`.

## Назначение и читатель

Отвечает на вопрос **«какие вызовы есть, что в них передаётся и что из этого уже существует»**. Читатель — разработчик компонента и тот, кто оценивает объём доработок форка ICPlan.

## Основа

| Практика | Что берём |
|---|---|
| OpenAPI 3 | структура существующих эндпоинтов ICPlan — из OpenAPI работающего форка (`icplan_openapi.json`) |
| Руководства по API ([Zalando RESTful API Guidelines](https://opensource.zalando.com/restful-api-guidelines/), [Google AIP](https://google.aip.dev)) | ресурсный путь, метод по смыслу, явные коды ответа |
| Трассировка | у эндпоинта — истории, требования, I-код |

## Из чего состоит

| Колонка или раздел | Что указать |
|---|---|
| Метод, путь | как в коде; параметры пути — `:id`; **одна строка — один путь**: доработка существующего пути — статус 🛠 на этой же строке и запись в `ENDPOINT_IO`, а не отдельная строка с пометкой в пути (`→ поле`, `· поле`) |
| Статус | ✅ есть — путь есть в OpenAPI форка; путь, смонтированный вне OpenAPI (MCP `/mcp`), — по коду форка, файл указан в `ENDPOINT_IO`; 🛠 доработка — путь есть, меняем тело или поведение; 🆕 новое |
| Что делает | одной фразой; модели — именами |
| Кто вызывает | компонент и способ доступа |
| Истории, требования, I | ссылки на US, R и I-код |
| Структура запросов и ответов | генерируется: из OpenAPI форка и / или `ENDPOINT_IO` в `datamodel.py` |
| Пример модели | `docs/api/README.md`, раздел `### <Модель>` — единственное место примеров |

## Как вести

1. Новый или изменённый эндпоинт — строка в таблице компонента; статус — по OpenAPI форка, не по памяти. Меняется существующий путь — правится его строка (статус 🛠, что меняется — в «Что делает»).
1б. У нового и доработанного эндпоинта, который меняет данные, — ответы-ошибки из сценариев отказа требований (403 — нет права, 404, 409 — состояние не позволяет) в `ENDPOINT_IO` (Z-ICP-4).
1а. Карточка интеграции описывает поведение сейчас; то, что появится после доработки, — с пометкой «после доработки (R-…)».
2. Нет в OpenAPI или доработка — запись в `ENDPOINT_IO`: запрос, ответ, заметка.
3. Новая модель — по [методологии данных](data-methodology.md); пример в README каталога.
4. Обновился форк — `python html-view/openapi_import.py`, затем сборка: статусы и структура сверятся.

## Чек-лист качества

- [ ] «✅ есть» — только для путей из OpenAPI форка или из кода форка (вне OpenAPI) со ссылкой на файл.
- [ ] В колонке «путь» — только путь; у пути одна строка.
- [ ] У всех изменяющих эндпоинтов (POST / PUT / PATCH / DELETE) из `ENDPOINT_IO` — коды ошибок; «ошибки: —» не годится (`./tools/doc lint`).
- [ ] У каждого эндпоинта есть структура запроса и ответа.
- [ ] Пример модели содержит только поля модели (точные имена).
- [ ] У эндпоинта есть требование и I-код.

## Проверки в сборке

`api_structure_check` (структура у каждого эндпоинта, доработка — с записью; в колонке пути нет пометок полей), `api_examples_check` (ключи примеров = поля моделей).

## Типичные ошибки

| Ошибка | Отклонение |
|---|---|
| Ответ heartbeat «`false`», в форке — 204 без тела | [О-45](deviations.md) |
