# Методология каталога API

← [Правила документации](README.md) · [типы документов и вкладки](doc-types.md) · [каталог API](../api/README.md)

Как вести каталог API: страницы `docs/api/<компонент>.md` и примеры моделей в `docs/api/README.md`.

## Назначение и читатель

Отвечает на вопрос **«какие вызовы есть, что в них передаётся и что из этого уже существует»**. Читатель — разработчик компонента и тот, кто оценивает объём доработок форка ICPlan.

## Основа

| Практика | Что берём |
|---|---|
| OpenAPI 3 | структура существующих эндпоинтов ICPlan — из OpenAPI работающего форка (`icplan_openapi.json`) |
| Руководства по API ([Zalando RESTful API Guidelines](https://opensource.zalando.com/restful-api-guidelines/), [Google AIP](https://google.aip.dev)) | ресурсный путь, метод по смыслу, явные коды ответа |
| Трассировка | у эндпоинта — истории, требования, I-код |

## Из чего состоит

| Колонка или раздел | Что указать |
|---|---|
| Метод, путь | как в коде; параметры пути — `:id` |
| Статус | ✅ есть — путь есть в OpenAPI форка; 🛠 доработка — путь есть, меняем тело или поведение; 🆕 новое |
| Что делает | одной фразой; модели — именами |
| Кто вызывает | компонент и способ доступа |
| Истории, требования, I | ссылки на US, R и I-код |
| Структура запросов и ответов | генерируется: из OpenAPI форка и / или `ENDPOINT_IO` в `datamodel.py` |
| Пример модели | `docs/api/README.md`, раздел `### <Модель>` — единственное место примеров |

## Как вести

1. Новый или изменённый эндпоинт — строка в таблице компонента; статус — по OpenAPI форка, не по памяти.
2. Нет в OpenAPI или доработка — запись в `ENDPOINT_IO`: запрос, ответ, заметка.
3. Новая модель — по [методологии данных](data-methodology.md); пример в README каталога.
4. Обновился форк — `python html-view/openapi_import.py`, затем сборка: статусы и структура сверятся.

## Чек-лист качества

- [ ] «✅ есть» — только для путей из OpenAPI форка.
- [ ] У каждого эндпоинта есть структура запроса и ответа.
- [ ] Пример модели содержит только поля модели (точные имена).
- [ ] У эндпоинта есть требование и I-код.

## Проверки в сборке

`api_structure_check` (структура у каждого эндпоинта, доработка — с записью), `api_examples_check` (ключи примеров = поля моделей).

## Типичные ошибки

| Ошибка | Отклонение |
|---|---|
| Ответ heartbeat «`false`», в форке — 204 без тела | [О-45](deviations.md) |
