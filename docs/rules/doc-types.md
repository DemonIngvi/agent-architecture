# Типы документов и правила

← [Правила документации](README.md)

Общие правила для всех: русский язык; заголовки OpenSpec и SHALL/MUST — на английском; в начале файла строка «←» на родителя; все упоминания документов — ссылками; схемы — ASCII по [FORMAT.md](../../FORMAT.md); секретов нет.

| Тип | Где | Обязательные разделы | Правила | Синхронизировать |
|---|---|---|---|---|
| **Главная** | `html-view/home.md` → `index.md` сайта | карта платформы: компоненты и связи, вход в разделы | только навигация и карта; описания — в страницах компонентов | `components.py`, навигация |
| **Корень** | `README.md` (на сайте — «Компоненты (таблица)», `overview.md`) | что за платформа, ссылки на разделы, таблица компонентов | компонент = строка таблицы с готовностью | architecture.md, html-view/components.py |
| **Архитектура** | `architecture.md` | C1, C2, развёртывание, сквозные решения (что и почему + ссылки), блоки, расширения, плюсы и минусы по модулям | без значений параметров, конфигов, переменных и списков доработок ([работа с архитектурой](doc-work.md#architecture)) | design, спеки, страницы компонентов |
| **Формат схем** | `FORMAT.md` | правила ASCII-схем | — | — |
| **Типы данных и интерфейсы** | `docs/data-types.md` | типы Т1–Т8; матрица интерфейсов — метка `<!-- iface-matrix -->` (генерируется из `datamodel.py`) | стороны интерфейсов и модели — только в `datamodel.py` | `datamodel.py` (INTEG, INTEG_TYPES) |
| **R&D** | `docs/rnd/<тема>.md` | по [методологии](../rules/rnd-methodology.md): итог сверху, контекст, knock-out, критерии, матрица, профиль, последствия, источники | данные репозиториев — из GitHub API с датой; не подгонять баллы | design (D-номер), REFS в rationale.py, «Обоснование» в architecture.md и спеке |
| **Задача** | `docs/tasks/<N.M>-<slug>.md` | таблица оценок, Зачем, Что сделать, Приёмка, Как прокликать, INVEST, Декомпозиция (2–8 ч), Что проработать | ссылается на требование спеки; выполненное — `[x]` | ROADMAP, TASKS, tasks.md change, components.py (tids) |
| **Roadmap** | `docs/ROADMAP.md` | этапы, таблицы задач, итоги | итоги пересчитываются при добавлении задачи | задачи |
| **Сводная таблица** | `docs/TASKS.md` | по компонентам: сделано → нужно | ссылки на документы задач | задачи |
| **Бэклог** | `docs/BACKLOG.md` | что отложено и почему | — | architecture.md |
| **Proposal** | `openspec/changes/<change>/proposal.md` | Why, What Changes, Capabilities, Impact | capability названа по поведению, не по работе | specs |
| **Spec** | `openspec/changes/<change>/specs/<cap>/spec.md` | Purpose, Requirements, Scenarios | [критерии полноты](spec-criteria.md) | architecture.md, техспека «Как работает», задачи |
| **Схема capability** | `.../specs/<cap>/architecture.md` | схема, блоки, расширения, плюсы / минусы по модулям | только схема, без требований | spec.md |
| **Интерфейсы capability** | `.../specs/<cap>/interfaces.md` | уровни L0–L3, параметры, хранилища S, интерфейсы I, FMEA | коды S и I — единые для всех спек | spec.md, техспека «Как работает», rationale.py |
| **Трассировка (RTM)** | `.../specs/<cap>/traceability.md` | требование → обоснование → задача → сценарии | разрывы явно; без задачи — решение «не в MVP» | spec.md, docs/tasks, R&D |
| **User Stories** | `docs/stories/<компонент>.md` (генерируется из `html-view/stories.py` и `html-view/stories_extra/<компонент>.md`) | роли, процесс BPMN (дорожки, события, задачи, развилки, ошибки), истории «Как… хочу… чтобы…», критерии приёмки, связанные требования; процесс и правила пользователя вне BPMN (`stories_extra`) | правим `stories.py` и `stories_extra`; каждая история ссылается на требования спек; ветки ошибок обязательны | spec.md, traceability.md (колонка US), задачи |
| **Технологии** | `docs/TECHNOLOGIES.md` | таблица: технология, назначение / компонент, версия, лицензия, репозиторий, откуда качать, статус Tech Radar, R&D; лицензионные риски; архивированные проекты | данные GitHub API с датой; новая технология — только с R&D | R&D, design, interfaces.md |
| **Методология SDD** | `docs/rules/sdd-methodology.md` | практики (OpenSpec, Spec Kit, EARS), шаблоны текста, цикл | — | spec-criteria.md |
| **Методика User Stories** | `docs/rules/us-methodology.md` | шаги 1–7, проверки покрытия, процесс | — | истории, персоны, spec-criteria.md |
| **Покрытие историй** | `docs/stories/coverage.md` (генерируется) | персона × компонент, истории без альтернатив, без требований | — | истории |
| **Граф связности** | `docs/rules/doc-graph.md` + `html-view/docgraph.py` | слои и связи документов | при новом типе документа — новый узел и связи | change-process.md |
| **Техническая спецификация** | `docs/techspec/<компонент>.md` | образы, запуск, переменные и секреты, сборка и поставка, проверка; «Как работает» — порядок работы компонента (бывшая вкладка «Потоки»), пример конфигурации | по [триггерам](tech-spec.md) | TECHNOLOGIES.md, interfaces.md, задачи |
| **Подтверждения спеки** | `.../specs/<cap>/approvals.md` (строки ⏳ добавляет сборка) | требование, роль, кто, 👤 / 🤖, дата, решение ✅ / ❌ / ⏳, комментарий | роль меняет только свою строку | готовность спеки (потолок 90) |
| **Открытые вопросы спеки** | `.../specs/<cap>/open-questions.md` | ID, вопрос, тип ❓ / 📌, блокирует ли, источник, кто решает | закрытый вопрос — удалить и записать решение в design / спеку | готовность спеки, ревью, задачи |
| **Персоны** | `docs/stories/personas.md` (из `stories.py`, PERSONAS) | кто, что может, что хочет, конфликты, промпт отыгрыша | новая сущность процесса — новая персона | истории, R&D |
| **Ревью** | `docs/reviews/<дата>-<тема>.md` | роли, сквозные замечания, по спекам, итог | статусы ✅ / ❓ / 📌 | спеки, задачи («Что проработать») |
| **Design** | `openspec/changes/<change>/design.md` | Context, Goals, Decisions (D-номера), Risks, Open Questions | у решения — альтернативы и ссылка на R&D | R&D, architecture.md |
| **Tasks change** | `openspec/changes/<change>/tasks.md` | `## N.` группы, `- [ ] N.M` | одна строка + ссылка на docs/tasks | docs/tasks |
| **Данные сайта** | `html-view/components.py`, `rationale.py`, `subcomponents.py`, `datamodel.py`, `home.md` | COMPONENTS, BLOCKS, ABOUT, RATIONALE, REFS, SUB; INTEG, MODELS, MODEL_META, TABLE_POLICY, ENDPOINT_IO | меняются вместе с архитектурой; новый блок схемы с описанием — в SUB; интеграции, модели, таблицы и структура API — только в `datamodel.py` | architecture.md, R&D, задачи, interfaces.md, каталог API |
| **Каталог API** | `docs/api/<компонент>.md`, `README.md` | таблица эндпоинтов (метод, путь, статус ✅ / 🛠 / 🆕, что делает, кто вызывает, истории, требования, I-код); в README — примеры JSON моделей | статус «✅ есть» — только если путь есть в OpenAPI форка; структура запроса и ответа генерируется (OpenAPI форка или `ENDPOINT_IO`) | `datamodel.py`, `icplan_openapi.json` |
| **Модель данных** | `data-model.md` (генерируется) | хранилища S1–S11, ER-диаграммы, контракты с источником и сноской «почему так», правило имён, все поля | правится только `datamodel.py`, схема форка — импортом | `datamodel.py`, `icplan_schema.json` |
| **Страница компонента** | `components/<компонент>/index.md` (генерируется) | схема, «Почему так», конфигурация, интеграции, контракты данных, хранилища | см. [вкладки](#tabs) | `components.py`, `rationale.py`, `datamodel.py` |
| **Страница блока** | `components/<компонент>/<блок>/index.md` (генерируется) | технология и ключевые параметры, что делает, почему так | параметры — значения из `interfaces.md` спеки | `subcomponents.py` |
| **Индексы по компоненту** | `specs-by-component/`, `tasks-by-component/`, `rnd-by-component/` (генерируются) | список документов компонента со статусом | вручную не правятся | `components.py`, REFS |
| **Последствия R&D** | `rnd-consequences.md` (генерируется) | строки Э10 всех R&D со статусом | правятся только таблицы Э10 R&D | `docs/rnd/*.md` |

## Вкладки и их наполнение {#tabs}

Правило из отклонения [О-46](deviations.md). Каждая вкладка отвечает на **свой** вопрос. Факт живёт в одной вкладке, остальные ссылаются на неё ([один источник](change-process.md#single-source)). Если тянет написать в вкладке то, что относится к другой, — ставим ссылку.

**Вкладки компонента** (в навигации — под именем компонента):

| Вкладка | Отвечает на вопрос | Обязательно | Чего здесь нет → где это | Источник | Проверка |
|---|---|---|---|---|---|
| **Компонент** (страница архитектуры) | из чего состоит, почему так, с кем связан и какими данными | схема блоков, «Почему так», конфигурация, интеграции (I-коды, канал, доступ, режим, эндпоинты), контракты данных (поля, источник, сноска, пример), хранилища (ER, индексы, срок, миграции) | порядок работы → Техспека («Как работает»); процесс пользователя → User Stories; требования → Спека | `components.py`, `rationale.py`, `datamodel.py` | карточка = `interfaces.md` спеки; модели и таблицы сверены |
| **Компоненты** (блоки) | что делает блок и на чём сделан | технология, ключевые параметры, что делает, почему так | значения параметров → `interfaces.md` спеки | `subcomponents.py` | у блока схемы есть страница |
| **User Stories** | кто и зачем пользуется, как проходит процесс пользователя | истории, BPMN, критерии приёмки; процесс и правила пользователя (например, процесс задачи ICPlan, что пользователь видит в чате запуска) | требования → Спека; работа системы → Техспека | `stories.py`, `stories_extra/` | у истории есть требование |
| **Спеки** | что компонент обязан делать | требования SHALL / MUST со сценариями; `interfaces.md` — параметры, хранилища, интерфейсы, нагрузка, FMEA; RTM; открытые вопросы; подтверждения; схема | порядок работы → Техспека; данные → Модель данных | `openspec/changes/…` | [критерии полноты](spec-criteria.md), `openspec validate` |
| **Задачи** | что сделать, сколько стоит, как принять | оценки, требования, приёмка, декомпозиция | зачем так устроено → R&D, design | `docs/tasks/*.md` | трассировка требование ↔ задача |
| **API** | какие вызовы есть и что в них передаётся | эндпоинты со статусом, требованиями, I-кодом; структура запроса и ответа (генерируется) | поля моделей → Модель данных (ссылкой) | `docs/api/*.md` + `datamodel.py` + OpenAPI форка | статус ✅ = путь в OpenAPI; у каждого эндпоинта есть структура |
| **Техспека** | как компонент работает, собирается, разворачивается и настраивается | «Как работает» (порядок работы, состояния, циклы), образы, запуск, переменные и секреты, сборка, проверка, пример конфигурации | значения параметров → `interfaces.md`; поля → Модель данных; стороны интеграций → «Интеграции» компонента | `docs/techspec/*.md` | [правило техспеки](tech-spec.md); в «Как работает» нет конфигов, модели существуют (`flows_check`) |
| **R&D** | почему выбрано именно так | исследование по [методологии](rnd-methodology.md), последствия Э10 | решение → design | `docs/rnd/*.md` | структура v3, Э10 в сводке |

**Разделы сайта** (общие):

| Раздел | Что внутри | Отвечает на вопрос |
|---|---|---|
| **Архитектура** | компоненты (таблица), схемы C1 / C2, взаимодействие компонентов (сквозной сценарий), типы данных и интерфейсы, модель данных, каталог API, техспеки, решения OpenSpec (proposal, design, tasks) | как устроена платформа целиком |
| **Требования** | все User Stories, покрытие, персоны, спеки по компонентам | что платформа обязана делать и для кого |
| **R&D** | все R&D, по компонентам, последствия, сквозные исследования | почему так |
| **План и задачи** | Roadmap, сводная таблица, задачи по компонентам, бэклог, план документации, сквозные задачи | что и когда делаем |
| **Справка** | как читать, формат схем, правила документации, журнал отклонений, ревью | как пользоваться документацией и как её менять |

Новая вкладка или раздел: строка в этих таблицах, строка в [справке](../HOW-TO-READ.md), место в навигации (`html-view/build.py`, `nav_yaml`).
