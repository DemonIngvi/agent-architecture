# 2.5. Память M3 и M2 в контекст

← [ROADMAP](../ROADMAP.md) · [сводная таблица](../TASKS.md) · спека: [agent-memory](../../openspec/changes/define-agent-platform/specs/agent-memory/spec.md)

| Этап | Компонент | Зависит от | Человек | Агент | Токены |
|---|---|---|---|---|---|
| 2 | Memory | [2.1](2.1-runner-external.md) | 3–4 дн | 3–4 ч | 2–4 M |

## Зачем

Агент следующего этапа должен продолжать работу, а не начинать с нуля. M3 — самый дешёвый способ дать это.

## Что сделать

- Хранилище M3 (состояние задачи)
- Тул записи M3 для агента
- Подача M3 и итогов последних N запусков (M2) в контекст

## Приёмка

- [ ] Агент записал M3 → следующий агент видит его в контексте
- [ ] Итоги прошлых запусков в контексте

**Как прокликать:** Два агента по одной задаче: второй ссылается на то, что сделал первый

## INVEST

| | |
|---|---|
| **I** Independent | Нужен 2.1 |
| **N** Negotiable | Формат M3 |
| **V** Valuable | Преемственность этапов |
| **E** Estimable | 3–4 дня |
| **S** Small | M3 и M2 отдельно |
| **T** Testable | Интеграционный тест |

## Что проработать

Список открытых вопросов — пройдём отдельно и заполним упущения.

- [ ] M3 в БД ICPlan (таблица в форке) или в отдельном Memory Service в MVP
- [ ] Формат M3: свободный текст или структура (сделано / дальше / блокеры)
- [ ] N последних запусков и объём итогов в контексте
- [ ] Права: кто читает M3 (все агенты задачи?)
