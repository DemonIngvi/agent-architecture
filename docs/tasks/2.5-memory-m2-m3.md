## Зачем

Агент следующего этапа должен продолжать работу, а не начинать с нуля. M3 — самый дешёвый способ дать это.

## Что сделать

- Хранилище M3 (состояние задачи)
- Тул записи M3 для агента
- Таблица `m4_fact` (M4, векторный поиск) создаётся после MVP вместе с RAG и в эту задачу не входит
- Подача M1 (последние сообщения треда `agent_chat_message`) в контекст
- Подача M3 и итогов последних N запусков (M2) в контекст
- Проверки записи по уровням: профиль, область, схема и размер M3, секреты, идемпотентность M2
- Управление памятью: администратор просматривает, правит, удаляет M1–M3 (M4 — бэклог, вместе с RAG)
- M5 (инструкция, навыки) подаётся задачей [2.3](2.3-config-from-icplan.md), M6 (`get_document`) — задачей [2.4](2.4-mcp-itsaplan-core.md)
- Срок памяти M1 и M2 — фильтр чтения по `retention` профиля: Memory не отдаёт записи старше срока и не удаляет строки форка; `POST /retention/run` удаляет только M3 ([D25](../../openspec/changes/define-agent-platform/design.md), [R&D](../rnd/fork-run-retention.md))

## Приёмка

- [ ] Агент записал M3 → следующий агент видит его в контексте
- [ ] Итоги прошлых запусков в контексте
- [ ] В треде задачи есть сообщения → последние попадают в контекст (M1); тред пуст → раздел пуст (R-MEM-01)
- [ ] Итог запуска старше срока M2 профиля не попадает в контекст, строка `agent_run` остаётся (R-MEM-08, D25)
- [ ] Завершение запуска → M0 уничтожается вместе с sandbox, M1–M6 сохраняются; неизвестный уровень в профиле → профиль не сохраняется, ошибка валидации (R-MEM-01)
- [ ] Агент B берёт задачу после агента A → контекст B содержит M3 агента A; M3 ещё нет → контекст без M3; два запуска пишут M3 одновременно → сохраняется последняя версия, прежняя в истории (R-MEM-04)
- [ ] У задачи 10 запусков, N = 3 → в контекст попадают итоги трёх последних; задача запускается впервые → раздел истории пуст (R-MEM-05)
- [ ] Администратор удаляет запись M3 → следующие запуски её не получают; исправляет запись M3 → следующий запуск получает исправленную; участник без права удаляет → отказ в доступе (R-MEM-07)
- [ ] Агент пишет в M3 запись с токеном → отклонено, причина «секрет в записи»; запись M3 больше `m3_max_kb` → отклонено с границей в причине; профиль записи «нет» → «уровень не разрешён профилем»; повтор итога с тем же `run_id` → в M2 одна запись (R-MEM-15)
- [ ] БД недоступна → чтение отдаёт пустой контекст с предупреждением, запись повторяется; очистка M3 не прошла → записи остаются, M3 закрытых задач не отдаётся в контекст, уведомление эксплуатации; профиль памяти не задан → значения по умолчанию (R-MEM-12)
- [ ] Конфликт записи → сохраняется последняя версия, предыдущая остаётся в истории (R-MEM-04)
- [ ] Следующий этап → контекст B содержит M3, записанное A (R-MEM-04)
- [ ] Запусков больше N → в контекст попадают итоги трёх последних (R-MEM-05)
- [ ] Повторный запуск → видит итоги прошлых запусков (R-MEM-05)
- [ ] Удаление ошибочного факта → последующие запуски её не получают (R-MEM-07)
- [ ] Истёк срок → запись недоступна для чтения (R-MEM-08)
- [ ] Сбой очистки → записи остаются, задание CronJob помечено неуспешным и повторяется; неуспешное задание поднимает уведомление эксплуатации (R-MEM-08)
- [ ] Срок не истёк → запись доступна (R-MEM-08)
- [ ] Удаление в журнале → ответ `{deleted: {m3}}` и запись в журнале Memory API: сколько записей и по какому сроку удалено (R-MEM-08)
- [ ] Выше максимума → значение отклонено, ошибка называет `m3_max_kb` и границы 2–64 (R-MEM-09)
- [ ] Ниже минимума → значение отклонено, ошибка называет `m2_last_runs` и границы 0–10 (R-MEM-09)
- [ ] S4 недоступно → чтение — пустой контекст с предупреждением; запись — повтор (R-MEM-10)
- [ ] Аутентификация I2 → вызов не повторяется, событие с причиной (R-MEM-11)
- [ ] Повтор I2 без дублей → дубля нет: да, по (run_id, seq) (R-MEM-11)
- [ ] Таймаут I11 → вызов прерывается; повтор: 2 раза (R-MEM-11)
- [ ] Значение по умолчанию → применяется значение по умолчанию: 16 (R-MEM-09)

**Как прокликать:** Два агента по одной задаче: второй ссылается на то, что сделал первый
