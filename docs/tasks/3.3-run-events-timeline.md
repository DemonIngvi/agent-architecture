## Зачем

Пользователь хочет видеть в задаче, что делает агент и почему: реплики, рассуждения, действия, вопросы и итог — чат запуска ([D21](../../openspec/changes/define-agent-platform/design.md), [R&D](../rnd/run-view.md), [поток](../stories/icplan.md#agent-feed)).

## Что сделать

- Таблица событий запуска `run_event` (событие AG-UI целиком) в БД ICPlan
- Приём событий от Runner: `POST /agent-runs/:runId/events` с телом `{events: RunEvent[]}`, как у чата агента форка; маскирование; дельты `*_CONTENT` собираются в сообщение на `*_END`
- Живой поток `GET /agent-runs/:runId/stream` (SSE) и история `GET /issues/:issueId/agent-feed`
- Панель «Агент» в карточке задачи на `AgentChatPanel`: реплики, свёрнутые рассуждения и тулы, план, вопросы и подтверждения с кнопками, указания, карточка итога; разделители по шагам процесса
- Срок хранения событий
- Результат quality gate по критериям (D20) — в карточке итога

## Приёмка

- [ ] Реплики агента, вызовы тулов и рассуждения (если модель их отдаёт) появляются в задаче по мере работы, без перезагрузки
- [ ] Вопрос и подтверждение — карточки с кнопками; ответ доходит до агента
- [ ] Карточка итога показывает критерии ✓ / ✗, артефакты, токены и кнопки вердикта
- [ ] Модель без рассуждений: лента на репликах, без ошибок
- [ ] Старые события удаляются по сроку
- [ ] Запуск открыт по `run_id` → последовательность шагов с входами, выходами (в пределах `events.level`) и временем; запись не удалась → Runner буферизует и дописывает позже; `TEXT_MESSAGE_CONTENT` по одному сообщению → в БД одно собранное сообщение на `*_END` (R-OBS-01)
- [ ] Агент работает → шаги появляются по мере выполнения; завершённый запуск → полный чат и итог; три запуска → разделены по запускам и агентам; перед тулом реплика о намерении, рассуждение по раскрытию; «агент взял задачу» не позже 10 с после взятия (R-OBS-02)
- [ ] Обрыв стрима → пропущенные шаги досылаются по порядковым номерам, дублей нет; итог с вложением → комментарий и вложение, без вложений → один комментарий (R-ICP-04)
- [ ] Администратор открыл задачу → все запуски, версии агентов и итоги; запуск по расписанию без задачи → трассировка по агенту и расписанию; агент удалён → история показывает агента и версию на момент запуска (R-OBS-03)
- [ ] Разбор трассировки → события содержат `run_id`, `agent_id` и `environment`; для workflow-запуска также указан `workflow_id`; OTel GenAI mapping использует `invoke_agent`, `execute_tool`, `gen_ai.usage.*` и `gen_ai.conversation.id`, оставаясь за адаптером (R-OBS-03)
- [ ] Ключ API в аргументах тула → в событии `***`; значение подключённого секрета в ответе тула и секрет в промпте → маскируются до записи; событие без секретов → без изменений (R-OBS-04)
- [ ] Срок истёк → события удалены, агрегаты затрат сохранены; событию 10 дней при сроке 90 → доступно; срок уменьшен → старые удаляются при следующей очистке (R-OBS-06)
- [ ] Нет записи событий → буфер в Runner, досылка по `seq`; нет цены модели → токены учтены, стоимость «неизвестна»; переполнение таблицы событий → очистка по сроку и предупреждение эксплуатации (R-OBS-10)
- [ ] G2 отклонил тул → в чате запуска событие с точкой, правилом и причиной; срок хранения истёк → агрегаты срабатываний сохраняются (R-GRD-16)
- [ ] БД событий недоступна → Runner буферизует и дописывает события позже (R-OBS-01)
- [ ] Разбор запуска → видит последовательность шагов с входами, выходами (в пределах `events.level`) и временем (R-OBS-01)
- [ ] Чувствительные данные → в событии значение маскируется (R-OBS-01)
- [ ] Несколько запусков → чат запуска разделён по запускам и агентам (R-OBS-02)
- [ ] Почему агент это делает → перед вызовом в ленте есть реплика агента о намерении, а рассуждение модели (если есть) доступно по раскрытию (R-OBS-02)
- [ ] Разбор задачи → видит все запуски по ней, версии агентов и итоги (R-OBS-03)
- [ ] Нет чувствительных данных → событие записывается без изменений (R-OBS-04)
- [ ] Изменён срок → старые события удаляются при следующей очистке (R-OBS-06)
- [ ] Выше максимума → значение отклонено, ошибка называет `retention_days` и границы 7–365 (R-OBS-07)
- [ ] Значение по умолчанию → применяется значение по умолчанию: всё (R-OBS-07)
- [ ] Недопустимое значение → значение отклонено, ошибка называет `events.level` и допустимые значения (R-OBS-07)
- [ ] S3 недоступно → события буферизуются у Runner, запуск продолжается; чат запуска временно неполный (R-OBS-08)
- [ ] Аутентификация I14 → вызов не повторяется, событие с причиной (R-OBS-09)
- [ ] Повтор I2 без дублей → дубля нет: да, по (run_id, seq) (R-OBS-09)
- [ ] Таймаут I2 → вызов прерывается; повтор: повтор с дедупликацией по (run_id, seq) (R-OBS-09)
- [ ] Запись в своё хранилище → запись попадает в S3 (Postgres ICPlan, схема `platform`) (R-OBS-08)

**Как прокликать:** открыть задачу во время работы агента на mock-LLM → в панели «Агент» идут реплики и тулы; ответить на вопрос → агент продолжил; после итога — карточка с критериями
