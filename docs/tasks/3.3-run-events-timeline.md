## Зачем

Пользователь хочет видеть все этапы выполнения задачи агентом, а не только итог.

## Что сделать

- Таблица событий запуска (БД ICPlan)
- Запись событий от Runner (из стрима Harness)
- Таймлайн в карточке задачи
- Срок хранения событий

## Приёмка

- [ ] Шаги появляются в задаче по мере работы
- [ ] Старые события удаляются по сроку

**Как прокликать:** Открыть задачу во время работы агента → шаги обновляются

## INVEST

| | |
|---|---|
| **I** Independent | Нужен поток событий из 1.3/2.1 |
| **N** Negotiable | Детализация шагов |
| **V** Valuable | Видимость работы агента |
| **E** Estimable | 4–6 дней |
| **S** Small | БД+API, затем UI |
| **T** Testable | Тесты + ручная проверка |

## Декомпозиция

Подзадачи по 2–8 часов; каждая проверяема сама по себе.

| # | Подзадача | Человек, ч | Готово, когда |
|---|---|---|---|
| 3.3.1 | Таблица `run_event`, миграция | 4 | таблица создаётся |
| 3.3.2 | Приём событий от Runner (API) | 6 | события пишутся по ходу запуска |
| 3.3.3 | Срок хранения событий | 3 | старые удаляются, агрегаты остаются |
| 3.3.4 | UI таймлайна в карточке задачи | 10 | шаги видны в задаче |
| 3.3.5 | Обновление в реальном времени | 6 | шаги появляются без перезагрузки |
| 3.3.6 | Тесты | 5 | тесты зелёные |
| | **Итого** | **34 ч ≈ 4.2 дн** | |
