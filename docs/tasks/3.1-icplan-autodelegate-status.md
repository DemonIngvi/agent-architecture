## Зачем

Процесс «перевёл в статус → агент взял» — ключевая автоматизация, которой сейчас нет.

## Что сделать

- Поле агента-делегата у статуса, запуск при входе задачи
- Защита от дублей
- UI в настройках статусов

## Приёмка

- [ ] Перевод задачи в статус создаёт один запуск агента

**Как прокликать:** Перетащить задачу в статус → агент взял её и ответил

## INVEST

| | |
|---|---|
| **I** Independent | Код только в ICPlan |
| **N** Negotiable | UI обсуждаем |
| **V** Valuable | Автоматический процесс |
| **E** Estimable | 3–4 дня |
| **S** Small | Да |
| **T** Testable | Интеграционные тесты ICPlan |

## Декомпозиция

Подзадачи по 2–8 часов; каждая проверяема сама по себе.

| # | Подзадача | Человек, ч | Готово, когда |
|---|---|---|---|
| 3.1.1 | Миграция: `auto_delegate_user_id` у колонки | 3 | миграция на чистой БД |
| 3.1.2 | API колонок + проверка, что агент — участник проекта | 4 | не-участник → 400 |
| 3.1.3 | Делегирование при входе задачи в колонку | 5 | перевод создаёт запуск |
| 3.1.4 | Защита от дублей | 4 | повторный вход — один запуск |

| | **Итого** | **25 ч ≈ 3.1 дн** | |
