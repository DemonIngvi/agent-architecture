## Зачем

Правила безопасности в одном месте, проверяемые и отключаемые конфигом.

## Что сделать

- Конфиг `guardrails.gN.enabled`, режим отказа
- OPA: G1 в Runner, G2 в hooks Harness
- Rego в git + `opa test`
- Аудит решений

## Приёмка

- [ ] Выключенная точка не проверяется
- [ ] Тул вне политики отклонён с причиной
- [ ] OPA недоступен → deny
- [ ] Администратор добавляет правило с точкой G2 → действует в следующих запусках агента; правило без точки → сохранение отклонено; удалено → следующие запуски без него (R-GRD-01)
- [ ] Бюджет исчерпан → `limit_exceeded`, sandbox не создан; допуск пройден → sandbox создан; kill switch агента → отклонён до создания sandbox (R-GRD-02)
- [ ] Тул с пометкой подтверждения → пауза до решения человека; результат тула с признаками injection → помечен или отфильтрован; тул из allowlist → без паузы; `scope: run` → повторные вызовы без паузы, `once` → пауза каждый раз (R-GRD-03)
- [ ] `g2.enabled: false` → проверка не вызывается, в логе «G2 disabled»; все точки включены → проверки везде; неизвестная точка `g5` → сервис не стартует с ошибкой (R-GRD-06)
- [ ] OPA не отвечает → вызов отклонён `policy_unavailable`; `on_engine_error: allow` → разрешено с пометкой «без проверки»; ответ медленнее таймаута → считается недоступным (R-GRD-07)
- [ ] Агент R2 и опасный тул → ждёт подтверждения; R5 и релиз в prod → всё равно подтверждение; R4 и обратимое опасное действие → без паузы, с аудитом (R-GRD-08)
- [ ] Третий одинаковый вызов `get_issue` подряд → `limit_exceeded`, `loop_detected`; разные аргументы или меняющийся результат → не зацикливание; 8 шагов без изменения состояния → стоп (R-GRD-09)
- [ ] Дневной бюджет агента достиг лимита → новые запуски отклонены, активный остановлен после шага; 80% месячного лимита проекта → уведомление, запуски идут; лимит запуска → стоп после шага (R-GRD-11)
- [ ] Шаг в 6 раз дороже медианы → `waiting_approval` «аномальный расход»; обычный шаг → без паузы; меньше 3 шагов → только абсолютный предел (R-GRD-12)
- [ ] Глобальный kill switch → очередь не выдаёт запуски, активные `canceled`; kill switch агента → только его запуски; снят → очередь выдаёт снова (R-GRD-15)
- [ ] Администратор ищет причину отказа → находит правило и точку G1–G4; G2 отклонил тул → событие с точкой, правилом и причиной в чате запуска; срок событий истёк → агрегаты срабатываний сохранены (R-GRD-16)

**Как прокликать:** Включить G2, вызвать запрещённый тул → отказ в чате запуска
