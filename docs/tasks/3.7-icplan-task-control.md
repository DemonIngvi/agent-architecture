## Зачем

Пользователь управляет ходом задачи: проверяет результат перед переходом, возвращает с заметкой, останавливает и возобновляет процесс, повторяет шаг. Администратор меняет процесс, не ломая задачи в работе.

## Что сделать

- Настройка шага «нужна проверка» и флаг задачи «проверять со мной»; состояние «ждёт проверки», напоминания
- Вердикт «принято / не выполнено» с заметкой; возврат на шаг с учётом лимита
- Остановка и возобновление процесса по задаче
- Повтор шага и «начать с шага N»; сброс счётчика владельцем процесса
- Версии процесса; перенос задач при удалении шага
- Независимый шаг-проверка перед завершением по умолчанию; проверяющий ≠ исполнитель; процесс из одного шага — базовая линия (R-AP-26, D27)

## Приёмка

- [ ] Шаг с проверкой: после успеха задача ждёт вердикта, без вердикта не двигается
- [ ] «Не выполнено» с заметкой → новый запуск шага, заметка в задании
- [ ] Остановка отменяет активный запуск, входы в шаги не запускают агентов; возобновление запускает агента текущего шага
- [ ] Удаление шага с задачами требует указать шаг для переноса
- [ ] Шаг упал с ошибкой → «повторить шаг» создаёт новый запуск с итогом ошибки в задании; «начать с шага SDD» → задача в колонке шага SDD, счётчики следующих шагов сброшены (R-AP-21 «Повтор после ошибки», «С выбранного шага»)
- [ ] Лимит запусков шага исчерпан → исполнителю повтор недоступен с предложением обратиться к владельцу процесса, владелец повторяет и счётчик сбрасывается (R-AP-21 «Лимит исчерпан»)
- [ ] Процесс без настройки проверки → перед завершением шаг-проверка другим агентом; проверяющий совпадает с исполнителем → сохранение отклонено; проверка явно отключена → «один шаг» в метриках

**Как прокликать:** задача «Фича» с флагом «проверять со мной» на mock-LLM → после шага SDD кнопки «принято / не выполнено» → «не выполнено» с заметкой → агент повторил шаг с заметкой

Подзадачи по 2–8 часов; каждая проверяема сама по себе.
