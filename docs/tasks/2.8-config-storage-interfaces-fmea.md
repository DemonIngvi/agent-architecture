## Зачем

Каждая спека требует: конфигурация по уровням L0–L3 с потолком, данные только в своих хранилищах, интерфейсы с таймаутами и повторами, предсказуемое поведение при отказах зависимостей (FMEA). Это общий каркас для всех модулей — дешевле сделать один раз, чем в каждом модуле по-своему.

## Что сделать

- Загрузчик конфигурации L0–L3: приоритет, потолок L0, ошибка при отсутствии обязательного параметра
- Роли БД: каждый модуль — только своя схема; секреты — только из Secret
- Клиенты интерфейсов I1–I20: таймауты, повторы, идемпотентность по таблицам `interfaces.md`
- Поведение по FMEA: fail-closed для проверок безопасности, буферизация событий, повтор записи
- Тесты отказов: остановка зависимости → ожидаемое поведение

## Приёмка

- [ ] Нет обязательного параметра → модуль не стартует, ошибка называет параметр и уровень
- [ ] Значение агента выше потолка L0 → применяется потолок, событие в журнале
- [ ] Модуль не может читать чужую схему БД
- [ ] Для каждой строки FMEA — тест «зависимость остановлена → поведение из таблицы»
- [ ] Неидемпотентные вызовы не повторяются автоматически

**Как прокликать:** остановить OPA → вызов опасного тула отклонён (deny); остановить LiteLLM → запуск `failed` после circuit breaker; вернуть сервисы → новые запуски проходят.
