## Зачем

Без лимитов агент может зациклиться и тратить токены; без управления контекстом длинные задачи падают на переполнении окна.

## Что сделать

- Лимиты шагов, времени, токенов из определения агента
- Завершение done / limit / error с частичным результатом
- Сжатие истории при приближении к окну модели

## Приёмка

- [ ] Лимит 3 шага → статус limit и частичный итог
- [ ] Переполнение окна → история сжата, запуск продолжается
- [ ] История меньше порога → сжатие не выполняется; контекст не помещается и после сжатия → `limit` с причиной `context_overflow` (R-HRN-07)
- [ ] Итог содержит все обязательные разделы → `succeeded` с отметкой «gate пройден»; раздела нет и повторы исчерпаны → `gate_failed` с перечнем критериев; критериев нет → «gate не задан»; агент пытается изменить критерий своего шага → отклонено, событие (R-HRN-08)
- [ ] Агент вернул итог → `done`; превышен максимум шагов → `limit` с частичным результатом; модель вернула ошибку после повторов → `error` с причиной и частичным итогом (R-HRN-09)
- [ ] Memory API недоступен → запуск идёт без M3 и M2, событие-предупреждение (R-HRN-13)
- [ ] `max_steps` исчерпан → `limit_exceeded` с частичным итогом; запуск дольше `timeout_s` → `limit_exceeded`, причина `timeout`; нет событий дольше `idle_s` → запуск остановлен, слот свободен (R-GRD-10)

**Как прокликать:** автотест сценария на mock-LLM (CLI-запуск, вывод шагов): агент с маленьким лимитом останавливается со статусом limit
