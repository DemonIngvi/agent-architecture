## Зачем

Harness нужно разрабатывать и тестировать без платного провайдера и без случайности ответов. Mock за LiteLLM даёт тот же маршрут, что в проде: смена mock → реальная модель — одна строка конфига.

## Что сделать

- OpenAI-совместимый mock-сервер: `/v1/chat/completions`, стрим, ответы по сценарию (текст, вызов тула, ошибка, задержка)
- Сценарии в YAML: на какой запрос что отвечать (по ключевой фразе или по номеру шага)
- LiteLLM: алиас `team-default` → mock, virtual key на тестового агента
- docker-compose для mock + LiteLLM

## Приёмка

- [ ] Запрос по алиасу через LiteLLM возвращает ответ сценария
- [ ] Сценарий с вызовом тула отдаёт корректный `tool_calls`
- [ ] В LiteLLM виден расход токенов по ключу агента
- [ ] Профили dev/CI используют mock без ключей провайдеров; попытка выбрать реальную модель отклоняется; staging-профиль позволяет проверить подключение реального провайдера
- [ ] Администратор переназначает алиас → новые вызовы идут в новую модель; несуществующий алиас → отказ с ошибкой алиаса; алиас переназначен во время запуска → следующие вызовы в новую модель, событие в чате запуска (R-LLM-01)
- [ ] Запуск завершён → известны токены и $ запуска; ответ стримом → токены учтены по завершении стрима; провайдер вернул ошибку → неуспешный вызов учтён отдельно, без стоимости ответа (R-LLM-02)
- [ ] Алиас на локальную или облачную модель → агент работает без изменений; у провайдера нет ключа → алиас помечен недоступным, вызов отклонён (R-LLM-07)
- [ ] Провайдер недоступен → ошибка вызова (fallback — в 4.5); БД `litellm` недоступна → вызовы отклонены; нет ключа провайдера → алиас недоступен; LiteLLM упал → вызовы Harness получают ошибку (R-LLM-11)
- [ ] Неизвестный алиас → вызов отклоняется с ошибкой алиаса (R-LLM-01)
- [ ] Нет подходящего сценария → mock возвращает ответ по умолчанию и отмечает это в логе (R-LLM-04)
- [ ] Граница от другого параметра → значение отклонено: `key.max_budget` не может быть больше `budget.daily_usd` (R-LLM-08)
- [ ] Значение по умолчанию → применяется значение по умолчанию: true (R-LLM-08)
- [ ] Недопустимое значение → значение отклонено, ошибка называет `fallbacks` и допустимые значения (R-LLM-08)
- [ ] S6 недоступно → проверка бюджетов невозможна — вызовы отклоняются (R-LLM-09)
- [ ] Аутентификация I13 → вызов не повторяется, событие с причиной (R-LLM-10)
- [ ] Повтор I8 без дублей → дубля нет: да по результату: побочных действий нет; повтор стоит токенов и учитывается в бюджете (R-LLM-10)
- [ ] Таймаут I8 → вызов прерывается; повтор: 2 раза с backoff (R-LLM-10)
- [ ] Разработка без ключа провайдера → агент получает ответы сценария, затраты считаются по сценарию (R-LLM-04)
- [ ] Сценарий с вызовом тула → агент получает корректный `tool_calls` (R-LLM-04)

**Как прокликать:** `localhost:4000/ui` → ключ агента → расход; curl на алиас возвращает ответ сценария

## Что проработать

Список открытых вопросов — пройдём отдельно и заполним упущения.

- [ ] Свой mock или готовый (LiteLLM `mock_response`, проекты типа ollama-mock) — проверить, поддерживают ли они tool calls и стрим
- [ ] Формат сценария: ключевая фраза, номер шага, или запись/воспроизведение реальных диалогов
- [ ] Нужна ли «полуреальная» модель для ручных проверок (бесплатный тир провайдера, локальная Ollama)
- [ ] Подсчёт токенов в mock — правдоподобный (по символам) или фиксированный
- [ ] Где живёт compose: в этом репозитории или в `itsaplan-agents`
