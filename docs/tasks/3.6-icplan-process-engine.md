## Зачем

Задача сама проходит процесс: переход делает ICPlan по итогу запуска, а не агент по своему усмотрению. Агент берёт задачи из своей очереди в предсказуемом порядке.

## Что сделать

- Переход по итогу запуска: успех → переход при успехе; ошибка, лимит, непройденный quality gate → переход при ошибке + уведомление владельца процесса; ожидание ответа → остаться; отмена → без перехода
- Переход в другой процесс: смена типа задачи → первый шаг нового процесса
- Лимит запусков на шаге
- Запрет смены колонки агентом через `update_issue` для задач в процессе
- Порядок очереди агента при выдаче запуска: приоритет задачи, затем время постановки

## Приёмка

- [ ] Задача типа «Фича» проходит 3 шага с агентами без участия человека
- [ ] Ошибка на шаге → переход при ошибке и уведомление владельца
- [ ] Лимит шага превышен → запуск не создаётся, переход при ошибке
- [ ] Агент не может сменить колонку задачи в процессе
- [ ] Срочная задача выдаётся раньше обычной, поставленной раньше

**Как прокликать:** Создать задачу «Фича» на mock-LLM → в истории видно 3 перехода и итог каждого шага

## Декомпозиция

Подзадачи по 2–8 часов; каждая проверяема сама по себе.

| # | Подзадача | Человек, ч | Готово, когда |
|---|---|---|---|
| 3.6.1 | Переход по итогу запуска (успех, ошибка, ожидание, отмена) | 6 | тест четырёх итогов |
| 3.6.2 | Переход в другой процесс: смена типа → первый шаг, отмена активного запуска | 4 | тест смены процесса |
| 3.6.3 | Лимит запусков на шаге | 3 | четвёртый вход при лимите 3 → ошибка шага |
| 3.6.4 | Запрет смены колонки агентом в `update_issue` | 3 | смена отклонена, остальные поля обновлены |
| 3.6.5 | Порядок очереди агента при выдаче (приоритет, время) | 4 | тест порядка |
| 3.6.6 | Уведомление владельца процесса при ошибке шага | 3 | уведомление доставлено |
| 3.6.7 | Тест цепочки из 3 шагов на mock-LLM | 6 | цепочка проходит сама |
| | **Итого** | **29 ч ≈ 3.6 дн** | |
