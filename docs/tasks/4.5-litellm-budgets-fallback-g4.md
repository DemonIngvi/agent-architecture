## Зачем

Контроль трат и устойчивость к сбоям провайдера; базовая защита содержимого.

## Что сделать

- Бюджеты и rate limit на virtual key
- Fallback-модель
- Хуки G4: PII, injection, модерация (включаемые)
- Pre-call хук атрибуции: вызов без `metadata.run_id` отклоняется, `run_id` не того агента, что ключ, — затраты на агента ключа и событие в аудит (R-LLM-03, D26)

## Приёмка

- [ ] Превышение бюджета → отказ
- [ ] Ошибка основной модели → ответ резервной
- [ ] Ключ в промпте маскируется
- [ ] Вызов модели без `run_id` → отклонён; вызов с `run_id` и задачей → затраты привязаны к запуску и задаче (R-LLM-03 «Вызов без метаданных», «Вызов с метаданными»)
- [ ] Вызов с ключом другого агента → затраты на агента ключа, событие несоответствия в аудите (R-LLM-03 «Чужой ключ»)
- [ ] Секрет в промпте → строка маскируется до отправки провайдеру; чистый промпт → запрос без изменений; ответ нарушает политику модерации → блокируется, агент получает отказ (R-GRD-05)
- [ ] Расход агента за сутки достиг лимита → новые запуски отклонены со статусом `limit_exceeded`; проект набрал 80% месячного лимита → администратор получает уведомление, запуски идут; запуск потратил лимит токенов → остановка после текущего шага (R-GRD-11)
- [ ] Суммарный поток токенов превысил TPM модели → вызовы ждут или отклонены с ошибкой лимита; поток ниже TPM → без задержки; агент превысил свой RPM → ждёт только он (R-GRD-14)
- [ ] Агент превысил лимит частоты → ошибка лимита; ниже лимитов → вызов проходит; бюджет virtual key исчерпан → отказ до обращения к провайдеру (R-LLM-05)
- [ ] Основная модель недоступна → запрос выполняет резервная, факт в трейсе; резерв не задан → ошибка вызова, Harness повторяет; обе недоступны → ошибка `all_providers_failed` (R-LLM-06)
- [ ] Провайдер недоступен → fallback-модель, если нет — ошибка вызова; БД `litellm` недоступна → проверка бюджетов невозможна, вызовы отклонены (R-LLM-11)

**Как прокликать:** LiteLLM UI: бюджет агента; mock-сценарий ошибки → ответ fallback
