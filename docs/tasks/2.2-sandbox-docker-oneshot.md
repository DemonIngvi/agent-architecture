## Зачем

Изоляция запусков с первого дня интеграции; тёплый пул — оптимизация позже (4.1).

## Что сделать

- Образ Harness
- `SandboxProvider` (Docker): create / exec / destroy
- Эфемерный `/workspace`
- Лимиты CPU/RAM из профиля
- Подключение источников манифеста: git-клон и папка из объектного хранилища, выгрузка своей подпапки

## Приёмка

- [ ] После запуска контейнера нет
- [ ] Два параллельных запуска не видят файлы друг друга
- [ ] Лимит RAM применяется
- [ ] Запуск `failed` или `succeeded` → sandbox уничтожен, логи сохранены; контейнер не удалился → Runner повторяет удаление и пишет событие, слот не занят (R-RUN-10)
- [ ] Агент с профилем увеличенной RAM → sandbox с этой RAM; превышение RAM → контейнер остановлен, `failed` с причиной; профиль не найден или `runtime: runsc` без runsc на узле → запуск отклонён до создания контейнера (R-SBX-05)
- [ ] Репозиторий (write) и папка (read) в манифесте → клон в `/workspace/repo`, папка в `/workspace/task`, запись только в репозиторий; подпапка шага выгружена новой версией; запись в папку с правом read отклонена (R-SBX-14)
- [ ] Нет `setup.script`-кэша → шаг подготовки в контейнере с `setup.registries`, результат в `/workspace/.deps`; lock-файлы не менялись и кэш свежий → шаг пропущен (R-SBX-14)
- [ ] Нет ресурсов хоста → запуск ждёт в `queued`; образ недоступен → профиль помечен недоступным; диск workspace переполнен → запись отклонена; реестр пакетов или RustFS недоступны → ошибка подготовки или «нет рабочего пространства» (R-SBX-11)
- [ ] `docker compose` поднимает ICPlan, Postgres, RustFS, LiteLLM с mock → Harness разрабатывается локально; версия образа в compose отличается от чарта → проверка сообщает о расхождении (R-INF-12)
- [ ] Проверка gVisor 2.2.8 выполнена, результат записан в R&D изоляции и TECHNOLOGIES

**Как прокликать:** Делегировать 2 задачи подряд → `docker ps` пуст после завершения, ответы в задачах
