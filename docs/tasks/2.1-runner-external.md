## Зачем

Первая связь с ICPlan: задачи из очереди ICPlan выполняет наш Harness, а не CLI на машине оператора.

## Что сделать

- Каркас Runner (Go)
- Опрос очереди ICPlan по ключу агента (протокол `@itsaplan/runner`)
- Запуск Harness, приём событий, стрим ответа в ICPlan, итог
- Таймаут и отмена
- Параллельность на агента

## Приёмка

- [ ] Делегированная внешнему агенту задача → ответ в комментарии
- [ ] Отмена в ICPlan останавливает запуск
- [ ] Таймаут → статус failed с причиной

**Как прокликать:** ICPlan: агент «внешний» в сети → делегировать задачу → комментарий агента

## Декомпозиция

Подзадачи по 2–8 часов; каждая проверяема сама по себе.

| # | Подзадача | Человек, ч | Готово, когда |
|---|---|---|---|
| 2.1.1 | Изучить протокол раннера ICPlan по коду: поля, стрим, статусы | 6 | контракт `Run` уточнён в flows |
| 2.1.2 | Каркас Runner (Go): конфиг, ключи агентов, логирование | 6 | сервис стартует |
| 2.1.3 | Poller: опрос очереди, захват запуска | 6 | запуск переходит в работу |
| 2.1.4 | Запуск Harness и трансляция событий в ICPlan | 8 | ответ стримится в задачу |
| 2.1.5 | Таймаут, отмена, параллельность на агента | 6 | отмена в ICPlan останавливает запуск |
| 2.1.6 | Интеграционный тест на локальном ICPlan | 6 | делегирование → комментарий агента |
| | **Итого** | **38 ч ≈ 4.8 дн** | |

## Что проработать

Список открытых вопросов — пройдём отдельно и заполним упущения.

- [ ] Изучить протокол раннера ICPlan по коду (`apps/api/src/modules/agents/runner`): поля запуска, стрим, статусы
- [ ] Один Runner на много агентов (много ключей) или Runner на агента
- [ ] Go или Python для Runner в MVP (Go — по design D3; Python — быстрее старт)
- [ ] Как Runner передаёт Harness задание: процесс, контейнер (2.2), API
- [ ] Чат с агентом (не только задачи) — поддерживаем в MVP?
