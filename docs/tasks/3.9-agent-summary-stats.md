## Зачем

Пользователь видит, что выполняется, сколько это идёт и стоит; администратор и владелец продукта — какой агент полезен. Данные уже есть: `agent_run` (статус, начало и конец, токены), события запуска, затраты LiteLLM, вердикты (3.7).

## Что сделать

- Агрегаты по задачам: в работе, в очереди, ждут человека, открыто, закрыто; время в работе и в ожидании
- Затраты по задаче и агенту из LiteLLM
- Сводка пользователя в ICPlan («Мои задачи с агентами», дашборд проекта)
- Статистика агентов: запуски, успешные, возвращённые, среднее время, затраты
- Метрики цепочки (D27, R-OBS-13): стоимость на принятую задачу по задаче, процессу и роли; доли причин возвратов, круги, блокировки по бюджету и лимитам; pass^k на эталонном наборе

## Приёмка

- [ ] Сводка с фильтрами проект, пользователь, период
- [ ] Статистика агента с долей возвратов
- [ ] LiteLLM недоступен → сводка без затрат с пометкой
- [ ] Стоимость на принятую задачу считается по всем ролям и возвратам цепочки; процессы из одного шага помечены базовой линией
- [ ] Видны доли причин возвратов, круги на задачу и бюджетные блокировки
- [ ] Эталонный набор прогнан ≥3 раза → pass^k для «один агент» и «цепочка»

**Как прокликать:** прогнать 5 задач на mock-LLM, одну вернуть → сводка и статистика показывают 5 запусков, 1 возврат
