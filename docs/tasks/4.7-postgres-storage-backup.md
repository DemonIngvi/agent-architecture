## Зачем

Одна СУБД обслуживает ICPlan, платформу и LiteLLM — нужны пул соединений, бэкапы вне узла и проверка восстановления (риск X5 ревью).

## Что сделать

- CloudNativePG: кластер PostgreSQL 17 с pgvector, БД `itsaplan` и `litellm`
- Пулер PgBouncer (transaction), список session-клиентов
- Роли БД по схемам
- RustFS: бакеты, ключи сервисов
- Бэкап: базовые копии + WAL в S3 вне узла; копия RustFS вне узла
- Ежемесячная проверка восстановления
- Задача worker форка: очистка завершённых `agent_run` и тредов чата агента по `runs.retention_days` и `chat.retention_days` по образцу `cleanupOldDeliveries`; `issue_activity` не чистится ([D25](../../openspec/changes/define-agent-platform/design.md), [R&D](../rnd/fork-run-retention.md))

## Приёмка

- [ ] 60 клиентов → ≤ 30 серверных соединений
- [ ] Восстановление из копии в отдельный namespace проходит
- [ ] Чужая схема недоступна роли
- [ ] 60 клиентских соединений → не более 30 серверных, запросы обслуживаются; клиенту нужен LISTEN / NOTIFY → отдельный session-пул или прямое подключение по списку; выходит версия ICPlan с миграциями → миграции до старта новых реплик, схема `platform` не затронута (R-INF-06)
- [ ] Агент публикует артефакт → файл в бакете `planner-attachments`; RustFS заменяется S3-совместимым → меняются только адрес и ключи; RustFS не отвечает → итог без вложений, загрузка повторяется (R-INF-07)
- [ ] Модуль сохраняет вложения, артефакты, копии → запись в S7; S7 недоступно → вложения не сохраняются, итоги без вложений, копии БД вне площадки не затронуты; код модуля подключается к БД платформы напрямую → невозможно, нет учётных данных и сетевого доступа (R-INF-14)
- [ ] Узел недоступен → платформа недоступна, восстановление из бэкапа вне узла; Postgres недоступен → сервисы не готовы, запуски не стартуют; PgBouncer исчерпал пул → запросы ждут до таймаута, ошибка с причиной; истёк TLS-сертификат → Traefik обновляет по ACME, при сбое предупреждение; переполнен диск → запись в БД и хранилище останавливается (R-INF-16)
- [ ] Завершённый запуск старше `runs.retention_days` без `run_event` удалён, с `run_event` — пропущен; тред чата старше `chat.retention_days` удалён; `issue_activity` на месте (R-ICP-19)

**Как прокликать:** остановить Postgres → сервисы не готовы; восстановить из копии → данные на месте
