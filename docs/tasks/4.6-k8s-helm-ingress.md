## Зачем

Платформа должна разворачиваться воспроизводимо на сервере: кластер, чарты, вход по HTTPS, изоляция namespaces, секреты вне git.

## Что сделать

- k3s на узле, namespaces `itsaplan-core`, `itsaplan-data`, `itsaplan-agents`
- Чарты: `itsaplan` (форк), `litellm`, `agent-platform` (Runner, OPA, Memory, egress)
- Traefik Ingress: HTTPS, ACME, маршруты web / api / mcp; админки без ingress
- NetworkPolicy по списку интерфейсов I1–I23
- Secret через `existingSecret`, скрипт создания из `.env`
- Проверки liveness / readiness, порядок запуска
- Провайдер сред запуска в K8s (I23) и CIS-проверка узла

## Приёмка

- [ ] Установка с нуля проходит скриптом
- [ ] Админки недоступны снаружи (404)
- [ ] Контейнер запуска не достучится до Postgres
- [ ] Обновление чарта LiteLLM без простоя
- [ ] Установка на чистом сервере → k3s, namespaces, все сервисы готовы; повторная установка → изменения без пересоздания данных; сервис агента создаёт объект в `itsaplan-core` → отказ правами ServiceAccount (R-INF-02)
- [ ] Обновление чарта LiteLLM → реплики заменяются по одной, вызовы не прерываются; версия не прошла проверки готовности → откат на предыдущую ревизию; секрет в `values.yaml` → установка отклонена проверкой чарта (R-INF-03)
- [ ] Пользователь открывает адрес ICPlan → HTTPS через Traefik к `web`; запрос на адрес LiteLLM снаружи → 404; HTTP → перенаправление на HTTPS (R-INF-04)
- [ ] Одна из двух реплик LiteLLM не прошла readiness → трафик на здоровую; обе реплики OPA готовы → запросы распределяются; нет готовых реплик → клиенты получают ошибку соединения (R-INF-05)
- [ ] Добавлен ключ провайдера → попадает в Secret, сервис перечитывает без пересборки; значение секрета в коммите → останавливает проверка перед коммитом; обязательного Secret нет → сервис не стартует, ошибка называет Secret (R-INF-09)
- [ ] Runner обращается к API ICPlan → разрешено; контейнер запуска подключается к Postgres напрямую → заблокировано; новый интерфейс в `interfaces.md` → политика дополнена до выпуска (R-INF-10)
- [ ] Холодный старт → сначала Postgres и PgBouncer, затем api, LiteLLM, OPA, затем Runner; Postgres пропал у работающего api → api не готов, ingress не шлёт трафик; процесс не отвечает на liveness → под перезапущен (R-INF-11)
- [ ] compose поднимает ICPlan, Postgres, RustFS, LiteLLM с mock; чарты в k3d дают тот же результат, что на сервере, кроме адресов и ресурсов; версия образа в compose отличается от чарта → проверка согласованности сообщает о расхождении (R-INF-12)
- [ ] Установка платформы → компоненты подняты в порядке проверок готовности; обновление чарта компонента → замена по одной реплике, проверки зелёные; узлу не хватает ресурсов → под ждёт размещения, предупреждение эксплуатации (R-INF-18)
- [ ] Новый образ Harness (`HARNESS_IMAGE`) → новые запуски на нём, активные доделываются; образ не скачивается → запуск `failed` с причиной «образ недоступен»; не хватает ресурсов → запуск ждёт в `queued` (R-HRN-15)
- [ ] Новый образ среды → пул пересоздаёт тёплые контейнеры; новая версия `egress-proxy` → замена без разрыва соединений дольше переподключения; не хватает ресурсов → запуск ждёт в `queued`, пул не доливается (R-SBX-13)
- [ ] Обновление api ICPlan с `itsaplan-core` → MCP обновляется по одной реплике; новый внешний MCP-сервер → образ закреплён по digest, доступ через egress-прокси; сервер не прошёл готовность → его тулы недоступны, остальные работают (R-MCP-12)

**Как прокликать:** открыть https-адрес ICPlan; попробовать адрес LiteLLM снаружи → 404
