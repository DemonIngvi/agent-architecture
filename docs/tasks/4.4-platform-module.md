## Зачем

Перенести настройки из YAML в ICPlan: бюджеты, профили, данные guardrails, версии — с UI.

## Что сделать

- Схема БД модуля
- API
- Экраны в UI ICPlan по [D24](../../openspec/changes/define-agent-platform/design.md) ([R&D](../rnd/platform-module-screens.md)): агент — раздел «Платформа» в карточке агента; проект — Проект → ИИ-команда → «Платформа»; экземпляр — God mode → «Платформа» через `@/cloud`; права — ресурс `ai_agents` форка, God mode — владелец экземпляра
- Карточка внешнего агента: поля Registry (модель-алиас, навыки, тулы, MCP; R-REG-02, D23)
- PR в upstream: точка расширения разделов карточки и проекта через `@/cloud`; до принятия — правка `TeamAiAgentFields.tsx`, `settingsSections.ts` и сообщений
- Версии определения агента, экспорт/импорт YAML
- Руководство проекта для агентов

## Приёмка

- [ ] Настройки агента меняются в UI и применяются к следующему запуску
- [ ] Бюджет 5 $ в сутки и профиль `light` сохранены и видны в карточке; отрицательный бюджет или несуществующий профиль → отказ с полем и причиной; `concurrency` выше потолка L0 → отказ с названием потолка; сброс → значение по умолчанию; потолок L0 снижен после сохранения → запуски идут в потолок, в карточке это видно (R-CP-01 «Недопустимое значение», «Выше потолка платформы», «Потолок снижен после сохранения», «Сброс к умолчаниям»)
- [ ] Runner читает настройки через API модуля, прямой доступ к таблицам закрыт, обновление ICPlan из upstream схему модуля не затрагивает (R-CP-02)
- [ ] Смена профиля sandbox во время запуска → активный запуск по прежнему профилю, следующий по новому; бюджет уменьшен ниже потраченного → запуск остановлен с причиной «бюджет» сразу; запуск в `queued` стартует с новыми настройками (R-CP-03)
- [ ] История настроек показывает кто, когда, что изменено; откат на версию 3 → новая версия с содержимым версии 3 со следующего запуска; без права `ai_agents` откат → 403 (R-CP-04)
- [ ] Импорт YAML из dev создаёт в prod новую версию; ссылка на несуществующий MCP-сервер → отказ с указанием ссылки; в экспорте только ссылки на секреты (R-CP-05)
- [ ] Новый тул в списке с подтверждением → следующий вызов ждёт approve; LiteLLM не отвечает при сохранении бюджета → «не применено» и повтор; бюджет в модуле и LiteLLM различается → предупреждение администратору (R-CP-06, R-CP-11 «LiteLLM admin API недоступен», «OPA не забрал bundle», «Рассинхронизация настроек»)
- [ ] Руководство проекта новым запуском получает слой после системного промпта; длиннее `prompt.guidance_max_chars` → отказ с границей; не задано → слой пропущен (R-CP-14)
- [ ] Экспорт → импорт даёт тот же агент
- [ ] Настройки агента — в карточке, проекта — в разделе «ИИ-команда», экземпляра — в God mode; без права `ai_agents` — только чтение, God mode — только владелец экземпляра (D24)

**Как прокликать:** ICPlan: экран настроек агента (бюджет, профиль) → запуск учитывает
