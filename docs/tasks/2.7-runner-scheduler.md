## Зачем

Агентов несколько, они делят модели и могут работать параллельно или только по одному. Без планировщика агенты упираются в лимиты провайдера, а два запуска по одной задаче конфликтуют. Решение — вариант B ([design D14](../../openspec/changes/define-agent-platform/design.md)).

## Что сделать

- Конфиг `scheduling`: `mode`, `global_max`, `per_issue`, `order`, `agents.<id>.parallel/max`, `models.<alias>.max`
- Слоты: глобальный, агента, модели, задачи; запуск стартует, когда свободны все
- Статус `queued` и порядок `fifo` / `priority`
- Общие слоты для нескольких экземпляров Runner (Postgres)
- Метрики очереди: сколько ждёт, почему (какой слот занят)

## Приёмка

- [ ] `sequential`: три запуска разных агентов идут по одному
- [ ] Агент с `parallel: false` никогда не идёт в два потока
- [ ] Занят слот модели → запуск ждёт в `queued` и стартует после освобождения
- [ ] Второй запуск по той же задаче ждёт первого
- [ ] Два экземпляра Runner соблюдают `global_max` суммарно

**Как прокликать:** включить `sequential`, делегировать три задачи разным агентам → в ICPlan видно, что они выполняются по очереди; переключить на `parallel` → одновременно.

## Что проработать

- [ ] Где задаётся `scheduling`: конфиг деплоя или Platform module (UI)
- [ ] Priority: брать приоритет задачи ICPlan или отдельное поле
- [ ] Защита от голодания: долго ждущий запуск поднимать в очереди
