## Зачем

Агент должен читать задачу, писать комментарии и менять статус — иначе процесс между этапами не работает.

## Что сделать

- Подключение MCP ICPlan в определении агента
- Ключ агента для MCP без попадания в контекст
- Allowlist тулов (issue.*, docs.*)

## Приёмка

- [ ] Агент читает задачу и пишет комментарий → данные и комментарий в задаче от имени агента (R-MCP-13, «Работа с задачей»)
- [ ] Агент меняет статус задачи вне процесса → статус изменён
- [ ] MCP проекта выключен → тулы ICPlan недоступны, запуск завершается с причиной (R-MCP-13, «MCP выключен в проекте»)
- [ ] `update_issue` со сменой колонки задачи в процессе → смена отклонена, остальные поля обновлены (R-MCP-13, «Смена колонки в процессе»)
- [ ] Запуск получен из очереди ICPlan → используется прямой API, не MCP (R-MCP-04, «Внутренний вызов»)
- [ ] Доступ к git-провайдеру нужен нескольким агентам → подключён как MCP-сервер, секрет на стороне сервера (R-MCP-04, «Тул для нескольких агентов»)
- [ ] Обработка 500 записей → прямой вызов, не тул модели (R-MCP-04, «Пакетная операция»)

**Как прокликать:** Делегировать задачу → агент оставил комментарий и сменил статус
