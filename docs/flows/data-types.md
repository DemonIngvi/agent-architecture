# Типы данных и потоки

← [Все потоки](README.md) · [сборка запроса к модели](harness.md#llm-request) · [потоки памяти](memory.md) · [правила](../rules/spec-criteria.md)

Все данные платформы разбиты на типы. Для каждого типа — откуда берётся, где хранится, кто пишет и читает, как защищается. Каждый интерфейс (I-код) отнесён к типам данных, которые по нему идут; сборка проверяет, что в матрице есть все I-коды из `interfaces.md` спек.

## Типы

| Код | Тип | Примеры | Откуда | Где хранится | Пишет | Читает | Защита | Срок |
|---|---|---|---|---|---|---|---|---|
| **Т1** | Промпт | системный промпт платформы, руководство проекта, инструкция и навыки агента, задание, указания пользователя | git платформы, Platform module, Registry, задача ICPlan, чат | S8, S2, S1 | разработчик платформы, администратор, пользователь | Harness → модель | слой 1 не отменяется нижними; маскирование секретов в задании | версии; задача — по ICPlan |
| **Т2** | Контекст памяти | M0 рабочий, M1 переписка, M2 итоги, M3 состояние, M4 факты | Harness, ICPlan, Runner, агент | контекст запуска, S1, S4 | см. [потоки памяти](memory.md) | Harness | профиль памяти, область видимости, маскирование | M0 — запуск; M1 30 д; M2 180 д; M3 — до закрытия задачи |
| **Т3** | Документы и файлы | документы проекта (M6), вложения, файлы рабочего пространства, артефакты, код | пользователи, агент, git | S1, S7, S10, git | пользователи; агент — своя подпапка, ветка | агент (по политике), пользователи | политика доступа, токены на запуск, egress-прокси, проверка секретов при публикации | по ICPlan и git; `/workspace` — запуск |
| **Т4** | Конфигурация | параметры L0–L3, определения агентов, процессы, политики доступа, правила Rego, values Helm | администратор, эксплуатация | S9, S2, S1, S8 | администратор, эксплуатация | все модули | права на настройки, журнал изменений, версии | версии |
| **Т5** | Секреты | ключи провайдеров, virtual keys, токены git, ключи агентов ICPlan, пароли БД, ключи S3 | эксплуатация, Platform module, git-провайдер | Secret кластера, S6 (virtual keys) | эксплуатация, Platform module | сервисы по ссылке; в sandbox — через прокси | не в git и не в БД платформы; маскирование; ротация без простоя | до ротации; токен запуска — время запуска |
| **Т6** | Управляющие сообщения | `Run`, `RunBundle`, `ApprovalDecision`, `UserMessage`, отмена, `PolicyInput` / `PolicyDecision`, heartbeat | ICPlan, Runner, OPA | S1 (`agent_run`), память сервисов | ICPlan, Runner, OPA | Runner, Harness | аутентификация интерфейса, идемпотентность | по `agent_run` |
| **Т7** | Телеметрия и учёт | `RunEvent`, трассы, затраты, аудит guardrails, журнал изменений, статистика | Harness, Runner, LiteLLM, OPA | S3, S6, журналы | Harness, Runner, LiteLLM | Observability, пользователи, администратор | маскирование, `events.level` | 90 дней (`retention_days`) |
| **Т8** | Ответы модели и тулов | текст ответа, вызовы тулов, размышления, вывод тулов | провайдер модели, MCP-серверы | M0; итог — M2 и комментарий | LiteLLM, MCP | Harness, пользователь (итог) | обрезка `max_result_kb`; размышления не сохраняются, кроме `events.level: всё`; G4 | M0 — запуск; итог — по M2 |
