# Изменение данных и интеграций

Единственный источник — `html-view/datamodel.py`; страницы «Модель данных», карточки интеграций, ER-диаграммы, структура API и раздел «Данные» потоков генерируются.

| Что меняется | Где править |
|---|---|
| Интерфейс (I-код) | `INTEG` (стрелка = кто вызывает), `DATA_IN_RESPONSE` (если данные в ответе), `INTEG_TYPES`, `ALSO`; строка с I-кодом в `interfaces.md` **всех** спек-участников |
| Модель (контракт JSON) | `MODELS` (поля: имя, тип, обязательность, описание), `MODEL_META` (источник ✅ / 📘 / 🧩 и «почему так»), `PLANNED` / `FIELD_SRC`; пример — `docs/api/README.md` |
| Таблица БД | `PLATFORM_TABLES` + `TABLE_POLICY` (индексы, срок, очистка, миграции); таблицы форка — `python html-view/schema_import.py` |
| Эндпоинт | строка в `docs/api/<компонент>.md`; структура — OpenAPI форка (`python html-view/openapi_import.py`) или `ENDPOINT_IO` |

Правило имён — в `NAMING` (JSON camelCase как в ICPlan; внешние протоколы и конфигурация — в своём стиле). Решения в сносках — только со ссылкой на существующие D-номер или R-требование: проверь `grep` по design и спекам, не выдумывай параметры.

Проверка: `python html-view/doctool.py check`; модели и имена — навык `doc-dual-read`.
