# Новое R&D

**Для R&D читай только этот сценарий, шаблон (заготовку) и нужные якоря** `docs/rules/rnd-methodology.md` по карте ниже. `AGENTS.md`, `README.md`, остальные правила не нужны. Разделы методологии читаются выборкой: `sed -n '/{#e3}/,/^### Э4/p' docs/rules/rnd-methodology.md`.

1. **Заготовка.**
   - С инструментом: `python html-view/doctool.py rnd <slug> <тема>` → `docs/rnd/<slug>.md` (Э1–Э10 со строкой «Вывод этапа» и воротами, первая страница, приложение, источники); в другом проекте вместо slug — путь к `.md`.
   - Без инструмента: скопировать шаблон `RND` и этапы из функции `rnd` в `html-view/doctool.py` (или эталон [выбор трекера](../../../docs/rnd/tracker-choice.md), дописав «Вывод этапа», где его нет) — блоки `rnd-hero`, `deck`, `rnd-grid`, разделы `## Эn. … {#en}`, в каждом «**Вывод этапа.**» и `<span class="gate">Gn</span> ✅ …`, `<details>` приложения, `## Источники`.
2. **Реестр.** Строка в `docs/rnd/README.md` (последняя колонка — `v3.2`). Новый проект без документов — реестр R&D в `README.md` корня проекта.
3. **Этапы** — по карте; первый поиск (Э4) — одной пачкой по списку кандидатов и видов источников ([#search](../../../docs/rules/rnd-methodology.md#search)).

   | Этап | Якорь | Нужные подразделы |
   |---|---|---|
   | Э1 Вопрос | `#e1` | `#greenfield` — если продукта и документов нет |
   | Э2 Потребности | `#e2` | — |
   | Э3 Опорное решение | `#e3` | `#evidence`; `#greenfield` (как решают без нас) |
   | Э4 Альтернативы | `#e4` | `#search`, `#candidate-card` |
   | Э5 Ценность | `#e5` | `#evidence`, `#kano`; агентные технологии — AG1–AG6 |
   | Э6 Перенос и критерии | `#e6` | `#kano`; потоки — `#us-rnd`, `#personas` |
   | Э7 Отсев и встраивание | `#e7` | `#integration` |
   | Э8 Спор ролей | `#e8` | `#debate` |
   | Э9 Выбор | `#e9` | `#argument` |
   | Э10 Последствия | `#e10` | `#consequences`, `#greenfield` |
   | Первая страница | `#layout` | `#deck`, `#colors` |
   | Ворота ⚠️ | `#gate-status` | — |

4. **Э10 «Последствия»:** каждая строка — документ и статус ✅ / 📌 (со следующим шагом); внести решение в `openspec/changes/<change>/design.md` и все последствия (спеки, `html-view/datamodel.py`, API, потоки, задачи).
5. **Проверка.**
   - С инструментом: `python html-view/doctool.py rnd-check <файл>` (Э1–Э10, «Вывод этапа», ворота G1–G10 ✅ или ⚠️ с 📌, источники — ссылка, дата, уровень), затем `python html-view/doctool.py check` (реестр, блоки первой страницы, Э/G — та же проверка, что в сборке).
   - Без инструмента: `grep -c '^## Э' <файл>` = 10; `grep -c 'Вывод этапа' <файл>` = 10; `grep -o 'G[0-9]*</span> [✅⚠]' <файл>` — 10 ворот, у каждого ⚠️ в строке есть 📌; у каждой строки «Источников» — ссылка, дата (или одна на раздел), уровень А–Г.
