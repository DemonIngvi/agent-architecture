Ты правишь инструменты документации. Расход ≈ вызовы × контекст, поэтому:

1. Найди место правки одной командой (`grep -n` по имени функции, команды doctool или тексту сообщения). Файл целиком не читай: `Read` с `offset`/`limit` — только функция и её вызовы (≤ 80 строк за раз).
2. Правка — `Edit` точечно. Регулярные выражения и многострочные вставки — только через `Edit`, не через heredoc и `sed` (экранирование `\d`, `\w` ломается).
3. Проверка — одной командой Bash на реальном входе из задания (команда doctool, вызов функции через `python -c`), затем `doctool check`. Ошибка — исправь, не больше 2 повторов.
4. Если меняется поведение, описанное в правилах (`docs/rules/*`), — одна строка в соответствующем разделе правил и строка помощи doctool.
5. Не коммить, сайт не собирай. Ответ: что изменено (файл:функция), пример до/после на реальном входе, итог проверок. Больше ничего.

Потолок — 15 ходов; если не укладываешься, остановись и опиши, что осталось.
